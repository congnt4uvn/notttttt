## 2. What Is Serverless Computing?

Serverless is a cloud computing model in which the cloud provider manages much of the underlying server infrastructure. Developers focus on application code and configuration rather than provisioning and maintaining servers.

Serverless does not mean that servers do not exist. It means that server management is abstracted away from the application team.

### Traditional server vs. serverless

| Traditional application hosting | AWS Lambda |
|---|---|
| Provision and manage servers | AWS manages the execution infrastructure |
| Plan server capacity | Configure function resources and concurrency |
| Maintain operating system and runtime environment | AWS manages the Lambda execution platform |
| Often pay for provisioned capacity | Pay based on requests and execution duration, subject to pricing rules |
| Application may run continuously | Functions run in response to invocation |

### Example

A user uploads an image to Amazon S3. S3 sends an event to Lambda. Lambda creates a thumbnail and stores it in another S3 location.

```text
                 User
                   |
                   v
             Upload Image
                   |
                   v
              Amazon S3
                   |
              S3 Event
                   |
                   v
              AWS Lambda
                   |
             Resize Image
                   |
                   v
          Thumbnail in Amazon S3
```

This architecture does not require you to maintain a continuously running image-processing server.

## 3. What Is AWS Lambda?

AWS Lambda is a serverless compute service. It runs your code in response to events or direct invocation.

Common use cases:

- REST API backends.
- File and image processing.
- Scheduled jobs.
- Queue message processing.
- Event-driven automation.
- Data transformation.
- Lightweight integrations between AWS services.

### Core concepts

| Term | Meaning |
|---|---|
| Function | The unit of code deployed to Lambda |
| Handler | The function entry point invoked by the Lambda runtime |
| Runtime | The language environment, such as Python or Java |
| Invocation | One request to run a Lambda function |
| Event | Input data sent to a function |
| Context | Runtime metadata about the current invocation |
| Execution role | IAM role that grants the function permission to access AWS resources |
| Execution environment | Isolated environment used to run function code |
| Cold start | Initialization work when a new execution environment is created |
| Warm invocation | Reuse of an already initialized execution environment |

### Lambda lifecycle overview

```text
        Event / Invocation
                |
                v
       Lambda Service receives
                |
                v
       Select execution environment
                |
                v
       Initialize runtime and code
                |
                v
       Invoke function handler
                |
                v
       Return result / complete
```

An execution environment may be reused for later invocations, but applications must not rely on reuse for correctness.

## 4. Lambda Function Structure

A Lambda function generally includes:

1. Function code.
2. Runtime.
3. Handler configuration.
4. Memory and timeout settings.
5. Execution role.
6. Environment variables.
7. Trigger or invocation configuration.

### Python handler example

Save as `lambda_function.py`:

```python
import json

def lambda_handler(event, context):
    name = event.get("name", "Guest")

    result = {
        "message": f"Hello, {name}!",
        "request_id": context.aws_request_id
    }

    return {
        "statusCode": 200,
        "headers": {
            "Content-Type": "application/json"
        },
        "body": json.dumps(result)
    }
```

The handler name is configured as:

```text
lambda_function.lambda_handler
```

The first part is the Python module filename without `.py`. The second part is the function name.

### Example event

```json
{
  "name": "Cong"
}
```

### Example response

```json
{
  "statusCode": 200,
  "headers": {
    "Content-Type": "application/json"
  },
  "body": "{\"message\": \"Hello, Cong!\", \"request_id\": \"example-request-id\"}"
}
```

The request ID above is illustrative; Lambda supplies the actual value at runtime.

## 5. Lambda Runtimes and Deployment Packages

Lambda supports managed runtimes for several programming languages. Runtime availability and supported versions change over time, so check the AWS Lambda runtime documentation before choosing a runtime for a new production function.

### Deployment options

| Deployment option | Description | Suitable for |
|---|---|---|
| ZIP archive | Code and dependencies packaged in a ZIP file | Most small and medium functions |
| Container image | Function packaged as a container image | Large dependencies or container-based build workflows |
| Layers | Shared libraries or other files attached to functions | Reusing dependencies across functions |

### ZIP package example

For a simple Python function:

```text
function.zip
|
+-- lambda_function.py
```

Create the package:

```bash
zip function.zip lambda_function.py
```

If your function has third-party dependencies, install them into a package directory and include them in the ZIP with the correct folder structure.

Example:

```bash
mkdir package
pip install requests -t package/
cp lambda_function.py package/
cd package
zip -r ../function.zip .
```

Build dependencies in an environment compatible with the Lambda runtime and architecture. Native libraries may need a Linux-compatible build environment.

### Container image

A Lambda container image must follow Lambda's container image requirements and be stored in Amazon ECR. Container images are useful when you need a custom runtime environment or a controlled dependency build.

## 6. Lambda Invocation Models

Lambda supports several ways to invoke a function.

### 6.1 Synchronous invocation

The caller waits for the function response.

Examples:

- API Gateway invokes Lambda.
- An application calls `Invoke` with `RequestResponse`.
- A Step Functions Task invokes Lambda synchronously.

```text
Client
  |
  v
API Gateway
  |
  v
Lambda
  |
  v
Response to API Gateway
  |
  v
Client
```

Use synchronous invocation when the caller needs the result immediately.

### 6.2 Asynchronous invocation

The caller submits an event and Lambda queues it for processing. The caller does not wait for the function's final result.

Examples:

- S3 event notifications.
- SNS invoking Lambda.
- Direct `Invoke` with `Event`.

```text
S3 Event
   |
   v
Lambda asynchronous queue
   |
   v
Lambda function
   |
   v
Process event
```

Asynchronous invocation has retry and failure-destination behavior that you should configure for your workload.

### 6.3 Poll-based invocation with event source mappings

For supported event sources, Lambda polls or reads records and invokes the function in batches.

Examples:

- Amazon SQS.
- Amazon Kinesis Data Streams.
- Amazon DynamoDB Streams.
- Amazon MSK and self-managed Kafka sources.

```text
Amazon SQS Queue
       |
       v
Lambda Event Source Mapping
       |
       v
Lambda Function
       |
       v
Process Message Batch
```

The event source mapping controls aspects such as batch size, batching window, and concurrency, subject to source-specific limits.

### Invocation comparison

| Invocation type | Caller waits? | Typical examples |
|---|---:|---|
| Synchronous | Yes | API Gateway, direct request-response |
| Asynchronous | No | S3, SNS, asynchronous Invoke |
| Poll-based | Usually no direct caller waiting | SQS, Kinesis, DynamoDB Streams |

## 7. Lambda Configuration

### 7.1 Memory

You configure memory for each function. CPU allocation increases with configured memory.

More memory can improve performance for CPU-intensive workloads, but it can also increase the cost per unit of execution time. Benchmark realistic workloads rather than assuming the smallest memory setting is cheapest.

### 7.2 Timeout

Timeout is the maximum duration allowed for one invocation. Configure it based on the expected workload and downstream service timeouts.

Do not set a very long timeout to hide a slow or stuck dependency.

### 7.3 Ephemeral storage

Lambda provides temporary storage in `/tmp`. You can configure its size within the supported service limits.

Use it for temporary files, downloaded objects, and intermediate processing data. Do not treat it as durable storage.

### 7.4 Environment variables

Environment variables hold configuration such as:

- Table names.
- Queue URLs.
- API endpoint names.
- Feature flags.
- Application settings.

Example:

```text
ORDERS_TABLE=Orders
LOG_LEVEL=INFO
```

Do not put plaintext passwords, access keys, or other secrets in ordinary environment variables. Use AWS Secrets Manager or Systems Manager Parameter Store where appropriate, and grant access through IAM.

### 7.5 Concurrency

Concurrency is the number of function invocations running at the same time.

Important concepts:

- **Account concurrency quota:** The account-level concurrency capacity in a Region.
- **Reserved concurrency:** Reserves capacity for a function and also sets its concurrency ceiling.
- **Provisioned concurrency:** Keeps execution environments initialized to reduce cold-start latency for configured capacity.
- **Scaling behavior:** Depends on invocation type and event source.

Use reserved concurrency to protect downstream services or ensure critical functions have capacity. Use provisioned concurrency when predictable low latency is important and the workload justifies the cost.

## 8. Lambda Execution Role and Security

A Lambda function assumes an IAM execution role. The role determines what AWS resources the function can access.

Example permissions for writing logs and reading one S3 bucket should be limited to the required actions and resources.

A conceptual policy:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "logs:CreateLogGroup",
        "logs:CreateLogStream",
        "logs:PutLogEvents"
      ],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject"
      ],
      "Resource": "arn:aws:s3:::example-input-bucket/*"
    }
  ]
}
```

This is an illustrative policy. Production logging permissions can be scoped more tightly, and the bucket and object resources must match the actual application.

### Security best practices

- Use a dedicated execution role for each function or closely related group of functions.
- Apply least privilege.
- Avoid hardcoded credentials.
- Store secrets in Secrets Manager or Parameter Store.
- Encrypt sensitive data at rest and in transit.
- Validate event input; an event is not automatically trusted.
- Avoid logging passwords, tokens, personal data, or payment details.
- Keep dependencies updated.
- Use resource policies carefully for cross-account and service invocation.
- Review VPC networking requirements before placing a function in a VPC.

### Execution role vs. resource-based policy

| IAM mechanism | What it controls |
|---|---|
| Execution role | What the Lambda function can access |
| Resource-based policy | Who or what can invoke the function |
| Identity policy on caller | What the calling identity is allowed to do |

For example, a Lambda execution role may permit reading from DynamoDB, while a resource-based policy may permit S3 to invoke the function.

## 9. Integrating Lambda with AWS Services

### 9.1 API Gateway

API Gateway exposes an HTTP API and invokes Lambda.

```text
Browser / Mobile App
        |
        v
   API Gateway
        |
        v
      Lambda
        |
        v
   DynamoDB / RDS
```

Use this pattern for lightweight serverless APIs.

### 9.2 Amazon S3

S3 can publish object-created events that invoke Lambda.

Example use cases:

- Generate image thumbnails.
- Extract metadata from uploaded documents.
- Validate uploaded files.
- Convert file formats.

Be careful with recursive triggers. If a function writes output to the same bucket and prefix that triggers it, it may invoke itself repeatedly. Use separate buckets or prefixes and filter event notifications.

### 9.3 Amazon SQS

Lambda can consume messages from SQS through an event source mapping.

Important considerations:

- Configure visibility timeout appropriately.
- Make processing idempotent.
- Handle partial batch failures where supported and configured.
- Use a dead-letter queue for messages that cannot be processed.
- Monitor queue age and message depth.

### 9.4 Amazon SNS

SNS can asynchronously invoke Lambda subscribers. The function receives an event containing the published message and SNS metadata.

### 9.5 Amazon EventBridge

EventBridge rules route matching events to Lambda targets. This is useful for event-driven automation and decoupled service integration.

### 9.6 AWS Step Functions

Step Functions can invoke Lambda as a Task state. This is useful when a business process has multiple steps, branches, retries, and compensation logic.

## 10. Error Handling, Retries, and Idempotency

Failures can happen because of:

- Temporary network errors.
- Downstream service throttling.
- Invalid event data.
- Function bugs.
- Timeout.
- Insufficient permissions.

The correct handling depends on the invocation model and event source.

### Asynchronous invocation

Lambda retries failed asynchronous invocations according to its configured retry behavior. Configure an on-failure destination or dead-letter queue when you need to retain failed events for investigation.

### SQS event source mapping

For SQS, messages that are not successfully processed become visible again after the visibility timeout. They may be received again, so your handler must be idempotent.

Configure a redrive policy on the source queue to move repeatedly unsuccessful messages to a dead-letter queue.

### Idempotency example

Suppose an order event has this identifier:

```json
{
  "eventId": "EVT-9001",
  "orderId": "ORD-501",
  "amount": 120.00
}
```

Before applying a business change, record or conditionally insert `eventId` in a durable store. If the same event arrives again, detect that it was already processed and avoid repeating the side effect.

A robust design must handle concurrent duplicate deliveries, not just sequential duplicates.

### Partial batch failure

When processing SQS batches, one bad record can cause repeated processing of other records if the whole batch is retried. Where supported, configure partial batch responses so the function can report only the failed message identifiers.

## 11. AWS CLI: Create, Update, and Invoke Lambda

The following examples use Region `ap-southeast-1`. Replace placeholders with your own values.

### 11.1 Check AWS identity and Region

```bash
aws sts get-caller-identity
aws configure get region
```

### 11.2 Create the deployment ZIP

```bash
zip function.zip lambda_function.py
```

### 11.3 Create a Lambda function

First create an IAM execution role with a trust relationship for `lambda.amazonaws.com` and attach the permissions required by the function.

```bash
aws lambda create-function \
  --function-name HelloLambda \
  --runtime python3.12 \
  --role "PASTE_LAMBDA_EXECUTION_ROLE_ARN" \
  --handler lambda_function.lambda_handler \
  --zip-file fileb://function.zip \
  --timeout 15 \
  --memory-size 256 \
  --region ap-southeast-1
```

Runtime versions change over time. Use a currently supported runtime in your Region.

### 11.4 Invoke synchronously

Create `event.json`:

```json
{
  "name": "Cong"
}
```

Invoke:

```bash
aws lambda invoke \
  --function-name HelloLambda \
  --invocation-type RequestResponse \
  --payload fileb://event.json \
  response.json \
  --region ap-southeast-1
```

View the response:

```bash
cat response.json
```

### 11.5 Invoke asynchronously

```bash
aws lambda invoke \
  --function-name HelloLambda \
  --invocation-type Event \
  --payload fileb://event.json \
  async-response.json \
  --region ap-southeast-1
```

A successful asynchronous API response indicates that Lambda accepted the event for processing, not that the function completed successfully.

### 11.6 Update function code

### 11.7 Update configuration

```bash

  --function-name HelloLambda \
  --timeout 30 \
```

### 11.8 Read function configuration

## 12. Java Lambda Fundamentals

Java applications can run on Lambda using a supported Java runtime and the AWS Lambda Java libraries.

A simple Java handler using the request/response handler interface:

```java
package example;

import com.amazonaws.services.lambda.runtime.Context;
import com.amazonaws.services.lambda.runtime.RequestHandler;

import java.util.Map;

public class HelloHandler
        implements RequestHandler<Map<String, Object>, Map<String, Object>> {

    @Override
    public Map<String, Object> handleRequest(
            Map<String, Object> event,
            Context context) {

        Object name = event.getOrDefault("name", "Guest");

        context.getLogger().log("Processing request");

        return Map.of(
            "message", "Hello, " + name + "!",
            "requestId", context.getAwsRequestId()
        );
    }
}
```

The handler configuration uses the fully qualified class name:

```text
example.HelloHandler
```

The build must package the handler class and its dependencies in a deployment artifact compatible with the selected Lambda Java runtime. Use the AWS Lambda Java runtime interface client and appropriate packaging approach for your chosen deployment method.

### Java Lambda vs. Spring Boot

| Java Lambda handler | Spring Boot application |
|---|---|
| Function-oriented entry point | Application framework and dependency injection |
| Often smaller startup footprint when carefully designed | May have greater initialization overhead |
| Good for event handlers and focused tasks | Good for larger application services and APIs |
| Can use Spring Cloud Function or other adapters | Can be deployed to containers, VMs, or supported serverless patterns |

Spring Boot applications can be adapted for Lambda, but do not assume that a conventional long-running web server can be deployed unchanged as a Lambda handler. Select an adapter and packaging model deliberately.

## 13. Spring Boot Application Calling Lambda

A Spring Boot service can invoke a Lambda function using AWS SDK for Java 2.x. This is different from deploying the Spring Boot service itself as a Lambda function.

### 13.1 Maven dependency

Use the AWS SDK BOM and define `${aws.sdk.version}` as an approved current SDK version.

```xml
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>software.amazon.awssdk</groupId>
            <artifactId>bom</artifactId>
            <version>${aws.sdk.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<dependencies>
    <dependency>
        <groupId>software.amazon.awssdk</groupId>
        <artifactId>lambda</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
</dependencies>
```

### 13.2 Configuration

```yaml
app:
  aws:
    region: ap-southeast-1
  lambda:
    function-name: ${ORDER_FUNCTION_NAME}
```

```java
@Configuration
public class LambdaConfiguration {

    @Bean
    LambdaClient lambdaClient(
            @Value("${app.aws.region}") String region) {

        return LambdaClient.builder()
                .region(Region.of(region))
                .credentialsProvider(
                    DefaultCredentialsProvider.create()
                )
                .build();
    }
}
```

### 13.3 Service

```java
@Service
public class LambdaInvokerService {

    private final LambdaClient lambdaClient;
    private final ObjectMapper objectMapper;
    private final String functionName;

    public LambdaInvokerService(
            LambdaClient lambdaClient,
            ObjectMapper objectMapper,
            @Value("${app.lambda.function-name}") String functionName) {
        this.lambdaClient = lambdaClient;
        this.objectMapper = objectMapper;
        this.functionName = functionName;
    }

    public String invoke(Map<String, Object> payload) {
        try {
            String json = objectMapper.writeValueAsString(payload);

            InvokeResponse response = lambdaClient.invoke(
                InvokeRequest.builder()
                    .functionName(functionName)
                    .invocationType(InvocationType.REQUEST_RESPONSE)
                    .payload(SdkBytes.fromUtf8String(json))
                    .build()
            );

            if (response.functionError() != null) {
                throw new IllegalStateException(
                    "Lambda execution failed: " + response.functionError()
                );
            }

            return response.payload().asUtf8String();

        } catch (JsonProcessingException e) {
            throw new IllegalArgumentException(
                "Could not serialize Lambda payload", e
            );
        }
    }
}
```

For production, also handle SDK exceptions, function-level errors, timeouts, throttling, and response parsing. Avoid logging sensitive payloads.

### 13.4 IAM permission

The Spring Boot application's IAM identity needs `lambda:InvokeFunction` on the specific function ARN. The Lambda function's own execution role is separate and controls what the function can access.

## 14. Networking and VPC Configuration

By default, Lambda functions run in a Lambda-managed network environment. If a function must access private resources in your VPC, configure VPC access and the required subnets and security groups.

Important points:

- A VPC-attached function uses configured subnets and security groups.
- Security groups control network traffic.
- Private subnet access to public services may require NAT or suitable VPC endpoints.
- VPC attachment does not automatically give the function internet access.
- The execution role needs the required permissions for VPC network interface management as applicable to the configuration.

Do not attach a function to a VPC unless it needs access to VPC resources or a specific network design requires it.

## 15. Monitoring and Observability

### CloudWatch metrics

Monitor:

- Invocations.
- Errors.
- Duration.
- Throttles.
- Concurrent executions.
- Async event age and dropped events, where relevant.
- Iterator age for stream event sources, where relevant.

### CloudWatch Logs

Lambda sends function logs to CloudWatch Logs when the execution role has the necessary permissions.

Use structured logs:

```python
import json

def lambda_handler(event, context):
    print(json.dumps({
        "level": "INFO",
        "message": "Order received",
        "request_id": context.aws_request_id,
        "order_id": event.get("orderId")
    }))

    return {"statusCode": 200}
```

Avoid logging secrets or sensitive customer information.

### AWS X-Ray

X-Ray can help trace requests across supported services and application components. Enable and configure tracing where it provides useful visibility, and account for its additional cost and data-retention considerations.

### Useful alarms

- Error count above an agreed threshold.
- Throttles above an agreed threshold.
- Duration approaching the configured timeout.
- SQS queue age or depth exceeding operational limits.
- Asynchronous event age or dropped events indicating processing trouble.

## 16. Cost and Performance Considerations

Lambda cost depends on factors such as request count, execution duration, configured architecture and memory, and applicable pricing rules. Additional services such as CloudWatch Logs, X-Ray, SQS, API Gateway, and data transfer may also incur charges.

Practical optimization:

1. Measure duration using representative workloads.
2. Test more than one memory setting.
3. Keep deployment packages and dependencies reasonably small.
4. Reuse SDK clients and database connections across invocations when safe.
5. Avoid expensive initialization on every invocation.
6. Use batching when the event source and business logic support it.
7. Set concurrency limits to protect downstream systems.
8. Use provisioned concurrency only when the latency benefit justifies its cost.
9. Avoid unnecessary network calls.
10. Monitor both Lambda and downstream service costs.

Do not optimize only for the lowest memory setting. A higher memory setting may finish much faster and reduce total billed duration.

## 17. Hands-on Lab: S3 Image Processing Workflow

### Goal

Build a simple event-driven workflow:

```text
User uploads image
       |
       v
   Amazon S3
       |
       v
   S3 Event
       |
       v
  AWS Lambda
       |
       v
Read object metadata
       |
       v
Write processing result
       |
       v
CloudWatch Logs
```

### Step 1 — Create buckets

Create an input bucket and an output bucket in the same Region. Use globally unique bucket names and apply appropriate encryption and access controls.

### Step 2 — Create the Lambda function

Use a Python handler that reads the S3 event, extracts the bucket and object key, and logs the object information.

```python
import json
import urllib.parse

def lambda_handler(event, context):
    for record in event.get("Records", []):
        bucket = record["s3"]["bucket"]["name"]
        key = urllib.parse.unquote_plus(
            record["s3"]["object"]["key"]
        )

        print(json.dumps({
            "message": "S3 object received",
            "bucket": bucket,
            "key": key,
            "requestId": context.aws_request_id
        }))

    return {"processed": True}
```

### Step 3 — Configure IAM

The Lambda execution role needs permission to write logs. If the function reads object content, grant `s3:GetObject` for the input bucket. If it writes results, grant only the necessary write permission for the output bucket.

### Step 4 — Configure the S3 trigger

Add an object-created notification for the input bucket. Use a suffix or prefix filter if appropriate.

### Step 5 — Upload a test file

Upload a small test image to the input bucket.

### Step 6 — Inspect logs

Open the Lambda log group in CloudWatch Logs and verify the bucket and key were processed.

### Step 7 — Add a result-writing step

Extend the function to write a small JSON result to the output bucket. Ensure the output location does not match the input trigger filter, preventing recursive invocation.

### Step 8 — Test failure behavior

Temporarily test an invalid event or a controlled permission failure. Confirm that the error is visible in logs and that the configured invocation behavior is understood.

### Step 9 — Clean up

Remove the event notification, test function, buckets, and temporary IAM resources when they are no longer needed. Empty buckets before deleting them.

## 18. Troubleshooting

| Problem | Possible cause | What to check |
|---|---|---|
| `AccessDeniedException` | Caller or execution role lacks permission | Caller identity policy, function execution role, resource policy |
| Handler not found | Incorrect handler configuration | Module/class name and handler method |
| Import error | Dependency missing or packaged incorrectly | ZIP directory structure, runtime compatibility |
| Function times out | Slow downstream service or insufficient timeout | Logs, dependency latency, timeout configuration |
| Function is throttled | Concurrency limit or account quota | Reserved concurrency, account quota, event source scaling |
| S3 event does not invoke Lambda | Missing notification or invoke permission | Bucket notification, Lambda resource policy, Region |
| Function runs repeatedly | Recursive event trigger or duplicate delivery | Input/output prefixes, event filters, idempotency |
| SQS messages return repeatedly | Processing failure or visibility timeout too short | Function logs, queue visibility timeout, DLQ |
| VPC function cannot reach service | Missing route, endpoint, NAT, or security rule | Route tables, security groups, DNS, VPC endpoints |
| High cold-start latency | Initialization or runtime overhead | Package size, initialization code, provisioned concurrency |
| Async event appears accepted but no result | Acceptance is not completion | Async failure destination, retry behavior, CloudWatch Logs |

## 19. Practical Exercises with Answers

### Exercise 1 — What does serverless mean?

**Answer:** Serverless means the cloud provider manages much of the underlying infrastructure. Developers focus on code and configuration rather than managing servers.

### Exercise 2 — What is an AWS Lambda function?

**Answer:** It is a deployable unit of code that runs in response to an invocation or event.

### Exercise 3 — What is a handler?

**Answer:** The handler is the entry point that the Lambda runtime invokes when the function runs.

### Exercise 4 — What is a cold start?

**Answer:** A cold start is the initialization work required when Lambda creates a new execution environment before running the handler.

### Exercise 5 — What is the difference between synchronous and asynchronous invocation?

**Answer:** With synchronous invocation, the caller waits for the response. With asynchronous invocation, Lambda accepts the event for processing and the caller does not wait for the function's final result.

### Exercise 6 — What is an event source mapping?

**Answer:** It is a Lambda resource that reads from supported event sources, such as SQS or Kinesis, and invokes the function with batches of records.

### Exercise 7 — What is a Lambda execution role?

**Answer:** It is the IAM role assumed by the function to access AWS resources and services.

### Exercise 8 — Why is idempotency important?

**Answer:** Events can be delivered or processed more than once. Idempotency prevents duplicate business effects.

### Exercise 9 — What is reserved concurrency?

**Answer:** It reserves concurrency capacity for a function and sets the maximum concurrency that function can use.

### Exercise 10 — Does attaching Lambda to a VPC automatically provide internet access?

**Answer:** No. Network routes, NAT or VPC endpoints, security groups, and DNS configuration must be designed as needed.

### Exercise 11 — What is the difference between an execution role and a resource-based policy?

**Answer:** The execution role controls what the function can access. A resource-based policy controls which principals or services can invoke the function.

### Exercise 12 — When would you use Step Functions with Lambda?

**Answer:** Use Step Functions when a process has multiple tasks, branching, retries, parallel work, or compensation logic that should be coordinated as a workflow.

Read the questions aloud and practice the model answers. Then try to explain each answer without looking at the text.

### Question 1: What is AWS Lambda?

**Model answer:**

AWS Lambda is a serverless compute service. It runs my code when an event occurs or when an application invokes a function. I do not need to manage the underlying servers.

### Question 2: What is a Lambda handler?

**Model answer:**

A handler is the entry point of a Lambda function. The Lambda runtime calls the handler when the function is invoked. The handler receives an event and a context object.

### Question 3: What is the difference between synchronous and asynchronous invocation?

**Model answer:**

With synchronous invocation, the caller waits for the function's response. With asynchronous invocation, the caller submits an event and Lambda processes it later.

### Question 4: What is a cold start?

**Model answer:**

A cold start happens when Lambda needs to create and initialize a new execution environment. It can increase the response time of the first invocation in that environment.

### Question 5: How does Lambda work with SQS?

**Model answer:**

Lambda uses an event source mapping to read messages from an SQS queue. It sends messages to the function in batches. The function processes the messages and reports failures according to the configured behavior.

### Question 6: Why do we need idempotency?

**Model answer:**

A message or event can be processed more than once. Idempotency helps prevent duplicate actions, such as charging a customer twice or creating the same order twice.

### Question 7: How can a Spring Boot application invoke Lambda?

**Model answer:**

A Spring Boot application can use AWS SDK for Java 2.x. It creates a Lambda client and invokes a function with a JSON payload. The application's IAM role needs permission to invoke that function.

## 22. AWS Interview Questions and Answers

**Q1. What is AWS Lambda?**

AWS Lambda is a serverless compute service that runs code in response to events or direct invocations.

**Q2. What is a Lambda handler?**

It is the configured entry point invoked by the Lambda runtime.

**Q3. What is the Lambda execution role?**

It is an IAM role assumed by the function to access AWS services and resources.

**Q4. What is a cold start?**

It is the initialization latency associated with creating a new execution environment.

**Q5. What are the main Lambda invocation models?**

Synchronous invocation, asynchronous invocation, and event source mapping for supported poll-based event sources.

**Q6. What is the difference between reserved and provisioned concurrency?**

Reserved concurrency reserves capacity for a function and limits its maximum concurrency. Provisioned concurrency initializes environments in advance to reduce startup latency for configured capacity.

**Q7. How does Lambda integrate with SQS?**

An event source mapping reads messages from SQS and invokes the function with message batches.

**Q8. Why should a Lambda function be idempotent?**

Because retries and duplicate deliveries can cause the same logical event to be processed more than once.

**Q9. What is a Lambda layer?**

A layer is a ZIP archive containing libraries or other files that can be made available to a function. It helps share common dependencies.

**Q10. What is the difference between a ZIP deployment and a container image deployment?**

A ZIP deployment packages code and dependencies in an archive. A container image packages the function in an image stored in Amazon ECR and follows Lambda's image requirements.

**Q11. Does a Lambda function in a private subnet automatically have internet access?**

No. Appropriate routing, NAT or VPC endpoints, security groups, and DNS configuration are needed.

**Q12. How do you monitor Lambda?**

Use CloudWatch metrics and logs, and optionally AWS X-Ray for distributed tracing.

**Q13. How do you handle failed asynchronous invocations?**

Use the configured retry behavior and configure an on-failure destination or dead-letter queue when appropriate. Monitor failures and event age.

**Q14. How do you protect a Lambda function?**

Use least-privilege IAM, secure secrets management, encryption, input validation, dependency updates, and careful logging.

**Q15. When should you use Step Functions instead of putting all logic in one Lambda?**

Use Step Functions when the process requires multiple coordinated steps, branching, parallel execution, long waits, retries, or compensation.
