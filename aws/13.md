## 2. IAM Module Review: The Big Picture

AWS Identity and Access Management (IAM) controls authentication and authorization for AWS resources.

- **Authentication:** Who are you?
- **Authorization:** What are you allowed to do?

### 2.1 Core IAM components

| Component | Purpose | Example |
|---|---|---|
| IAM User | Identity that can have long-term credentials | Legacy integration identity |
| IAM Group | Organizes IAM users and shared permissions | Developers group |
| IAM Role | Identity assumed by a trusted principal | EC2 application role |
| IAM Policy | JSON document defining permissions | Allow S3 object upload |
| Trust Policy | Defines who can assume a role | EC2 service can assume role |
| Permissions Boundary | Sets a maximum for identity-based permissions | Limit developer-created roles |
| STS | Provides temporary security credentials | AssumeRole |

### 2.2 Recommended credential approach

| Workload | Preferred identity approach |
|---|---|
| EC2 application | EC2 instance role |
| Lambda function | Lambda execution role |
| ECS application container | ECS task role |
| Human workforce | IAM Identity Center or federation |
| External CI/CD system | OIDC federation or another supported short-lived credential method |
| Local developer | Approved developer identity/profile |

Avoid long-lived access keys for workloads when role-based or federated credentials are available.

## 3. IAM Policy Review

A common IAM policy structure:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ReadInvoiceObjects",
      "Effect": "Allow",
      "Action": [
        "s3:GetObject"
      ],
      "Resource": "arn:aws:s3:::company-invoices/invoices/*"
    }
  ]
}
```

| Element | Meaning |
|---|---|
| `Version` | IAM policy language version |
| `Statement` | One or more permission statements |
| `Sid` | Optional statement identifier |
| `Effect` | `Allow` or `Deny` |
| `Action` | AWS API action |
| `Resource` | Resource ARN |
| `Condition` | Optional context-based restriction |
| `Principal` | Identifies a principal in policies that support it, such as resource policies and trust policies |

### 3.1 ARN review

Common ARN pattern:

```text
arn:partition:service:region:account-id:resource
```

S3 bucket ARN:

```text
arn:aws:s3:::company-invoices
```

S3 object ARN:

```text
arn:aws:s3:::company-invoices/invoices/*
```

Important distinction:

| S3 action | Typical resource |
|---|---|
| `s3:ListBucket` | Bucket ARN |
| `s3:GetObject` | Object ARN |
| `s3:PutObject` | Object ARN |
| `s3:DeleteObject` | Object ARN |

Do not use the object ARN for `s3:ListBucket`.

## 4. Trust Policy vs Permissions Policy

A role usually has two essential policy concepts.

### Trust policy: Who can assume the role?

Example for EC2:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "TrustEC2",
      "Effect": "Allow",
      "Principal": {
        "Service": "ec2.amazonaws.com"
      },
      "Action": "sts:AssumeRole"
    }
  ]
}
```

### Permissions policy: What can the role do?

Example:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "UploadInvoiceFiles",
      "Effect": "Allow",
      "Action": "s3:PutObject",
      "Resource": "arn:aws:s3:::company-invoices/invoices/*"
    }
  ]
}
```

| Question | Trust policy | Permissions policy |
|---|---|---|
| Controls | Who can assume the role | What the role can do |
| Common principal | `ec2.amazonaws.com` | Usually no `Principal` |
| Common action | `sts:AssumeRole` | `s3:PutObject`, `s3:GetObject`, etc. |
| Example | EC2 may assume role | Role may upload invoice objects |

Remember: a trust policy does not grant S3 access.

## 5. IAM Authorization: Multiple Policy Layers

A request may be affected by several controls.

| Policy/control | Purpose |
|---|---|
| Identity-based policy | Grants or denies actions for an identity |
| Resource-based policy | Defines access on a supported resource |
| Trust policy | Controls role assumption |
| Permissions boundary | Limits identity-based permissions |
| SCP | Sets maximum available permissions in affected organization accounts |
| Session policy | Further restricts a role session |
| VPC endpoint policy | Controls requests through a specific VPC endpoint |
| KMS key policy | Controls use of a KMS key |

Key principles:

1. An explicit Deny overrides an applicable Allow.
2. An Allow in one policy does not guarantee that a request succeeds.
3. An SCP does not grant permissions.
4. A permissions boundary does not grant permissions.
5. A session policy cannot grant permissions beyond the role's permissions.
6. Service-specific authorization rules also matter.

## 6. Mini Project: Secure Spring Boot Invoice Upload Service

### 6.1 Business requirement

Build a Spring Boot service that uploads invoice PDFs to Amazon S3.

Requirements:

- Application runs on an EC2 instance.
- Bucket name: `training-invoices`.
- Application uploads only to `uploads/`.
- Application does not need permission to delete objects.
- Application uses temporary credentials from an EC2 role.
- No long-term AWS access keys are stored in source code.

### 6.2 Architecture

```text
                    Customer
                       |
                       v
                Application API
                       |
                       v
               Spring Boot Service
                       |
                       v
                  EC2 Instance
                       |
                       v
                Instance Profile
                       |
                       v
             IAM Role: InvoiceAppRole
                       |
                       | s3:PutObject
                       | uploads/*
                       v
                Amazon S3 Bucket
                 training-invoices
                       |
                       v
                uploads/invoice.pdf
```

### 6.3 Security design

| Component | Configuration |
|---|---|
| EC2 | Runs the Spring Boot application |
| Instance profile | Contains `InvoiceAppRole` |
| Trust policy | Allows EC2 service to assume the role |
| Permissions policy | Allows `s3:PutObject` on `uploads/*` |
| S3 bucket | Private bucket with Block Public Access |
| Credentials | Temporary role credentials |
| Application | Uses AWS SDK default credentials provider chain |

## 7. Hands-on Lab — Step 1: Create the S3 Bucket

Choose a globally unique bucket name. The example uses `training-invoices-example-2026`; replace it with a name that is available in your account.

Set your Region:

```bash
export AWS_REGION=ap-southeast-1
export BUCKET_NAME=training-invoices-example-2026
```

For Windows PowerShell:

```powershell
$env:AWS_REGION = "ap-southeast-1"
$env:BUCKET_NAME = "training-invoices-example-2026"
```

Create the bucket in the Asia Pacific (Singapore) Region:

```bash
aws s3api create-bucket \
  --bucket "$BUCKET_NAME" \
  --region "$AWS_REGION" \
  --create-bucket-configuration LocationConstraint="$AWS_REGION"
```

Enable S3 Block Public Access:

```bash
aws s3api put-public-access-block \
  --bucket "$BUCKET_NAME" \
  --public-access-block-configuration \
  BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
```

Enable default server-side encryption with SSE-S3:

```bash
aws s3api put-bucket-encryption \
  --bucket "$BUCKET_NAME" \
  --server-side-encryption-configuration \
  '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"}}]}'
```

Verify the configuration:

```bash
aws s3api get-public-access-block --bucket "$BUCKET_NAME"
aws s3api get-bucket-encryption --bucket "$BUCKET_NAME"
```

Note: AWS S3 automatically encrypts new object uploads at rest by default with SSE-S3 in current standard behavior. Explicitly configuring encryption makes the intended bucket configuration visible and easier to audit.

## 8. Hands-on Lab — Step 2: Create the EC2 Trust Policy

Create a file named `ec2-trust-policy.json`:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowEC2AssumeRole",
      "Effect": "Allow",
      "Principal": {
        "Service": "ec2.amazonaws.com"
      },
      "Action": "sts:AssumeRole"
    }
  ]
}
```

This trust policy allows the EC2 service to assume the role. It does not grant S3 permissions.

Create the role:

```bash
aws iam create-role \
  --role-name InvoiceAppRole \
  --assume-role-policy-document file://ec2-trust-policy.json
```

Inspect it:

```bash
aws iam get-role --role-name InvoiceAppRole
```

## 9. Hands-on Lab — Step 3: Create a Least-Privilege S3 Policy

Create `invoice-upload-policy.json`.

Use the exact bucket name you created:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "UploadOnlyToUploadsPrefix",
      "Effect": "Allow",
      "Action": [
        "s3:PutObject"
      ],
      "Resource": "arn:aws:s3:::training-invoices-example-2026/uploads/*"
    }
  ]
}
```

Replace `training-invoices-example-2026` with your actual bucket name.

Create a customer managed policy:

```bash
aws iam create-policy \
  --policy-name InvoiceUploadOnlyPolicy \
  --policy-document file://invoice-upload-policy.json
```

Get your account ID:

```bash
aws sts get-caller-identity
```

Attach the policy to the role. Replace the account ID:

```bash
aws iam attach-role-policy \
  --role-name InvoiceAppRole \
  --policy-arn arn:aws:iam::111122223333:policy/InvoiceUploadOnlyPolicy
```

Verify:

```bash
aws iam list-attached-role-policies \
  --role-name InvoiceAppRole
```

This policy does not grant `s3:ListBucket`, `s3:GetObject`, or `s3:DeleteObject`. Add permissions only if a real application feature requires them.

## 10. Hands-on Lab — Step 4: Create the EC2 Instance Profile

Create the instance profile:

```bash
  --instance-profile-name InvoiceAppInstanceProfile
```

Inspect it:

```bash
aws iam get-instance-profile \
  --instance-profile-name InvoiceAppInstanceProfile
```

Associate it with an EC2 instance:

```bash
aws ec2 associate-iam-instance-profile \
  --instance-id i-0123456789abcdef0 \
  --iam-instance-profile Name=InvoiceAppInstanceProfile
```

Replace the sample instance ID. The instance and profile must be in the same AWS account. If the instance already has a profile association, inspect it and use the appropriate replacement workflow.

In the EC2 console, you can also associate an IAM role with an instance through the instance's security settings.

## 12. Hands-on Lab — Step 6: Test S3 Upload

Create a test file:

```bash
echo "Invoice upload test" > invoice.txt
```

Upload it:

```bash
aws s3 cp invoice.txt \
  s3://training-invoices-example-2026/uploads/invoice.txt
```

Replace the example bucket with your bucket.

Expected result: the upload succeeds if the role, bucket, and other applicable controls are configured correctly.

Try uploading outside the permitted prefix:

```bash
aws s3 cp invoice.txt \
  s3://training-invoices-example-2026/private/invoice.txt
```

Expected result: access should be denied by the role's identity policy, assuming no other applicable policy grants access.

Try deleting the uploaded object:

```bash
aws s3 rm \
  s3://training-invoices-example-2026/uploads/invoice.txt
```

Expected result: access should be denied because the role policy does not grant `s3:DeleteObject`, unless another applicable policy grants it.

## 13. Hands-on Lab — Step 7: Spring Boot Implementation

### Maven dependency

Use AWS SDK for Java 2.x and manage compatible module versions with the AWS SDK BOM.

```xml
<dependency>
    <groupId>software.amazon.awssdk</groupId>
    <artifactId>s3</artifactId>
</dependency>
```

### S3 client configuration

```java
@Configuration
public class AwsConfig {

    @Bean
    public S3Client s3Client() {
        return S3Client.builder()
                .region(Region.AP_SOUTHEAST_1)
                .build();
    }
}
```

The SDK's default credentials provider chain can retrieve temporary credentials from the EC2 instance role when the application runs on a correctly configured instance.

### Storage service

```java
@Service
public class InvoiceStorageService {

    private final S3Client s3Client;

    @Value("${app.aws.s3.bucket}")
    private String bucketName;

    public InvoiceStorageService(S3Client s3Client) {
        this.s3Client = s3Client;
    }

    public void uploadInvoice(String fileName, Path filePath) {
        String key = "uploads/" + fileName;

        PutObjectRequest request = PutObjectRequest.builder()
                .bucket(bucketName)
                .key(key)
                .contentType("application/pdf")
                .build();

        s3Client.putObject(
                request,
                RequestBody.fromFile(filePath)
        );
    }
}
```

### Application configuration

```yaml
app:
  aws:
    s3:
      bucket: training-invoices-example-2026
```

Do not add AWS access keys or secret keys to this file.

### Important application security notes

- Validate the uploaded file type and size.
- Generate safe object keys; do not trust arbitrary path fragments supplied by a user.
- Authenticate API users.
- Authorize each user to upload to the correct business account.
- Do not expose S3 object keys or internal error details unnecessarily.
- Use TLS for API traffic.
- Consider malware scanning and content validation for user-uploaded files.
- Keep application logs free of credentials and sensitive document contents.

IAM permission does not replace application-level authorization.

## 14. Troubleshooting the Mini Project

| Problem | Possible reason | What to check |
|---|---|---|
| `Unable to locate credentials` | No usable credentials found | Instance profile, SDK provider chain, environment overrides |
| `AccessDenied` on upload | Missing `s3:PutObject` or another restriction | Role policy, bucket policy, boundary, SCP, endpoint policy |
| Upload to wrong prefix fails | Resource ARN only allows `uploads/*` | Object key and policy ARN |
| Role cannot be assumed | Trust policy is incorrect | `Principal` and `sts:AssumeRole` |
| EC2 does not use expected role | Instance profile not associated or stale configuration | EC2 profile association and caller identity |
| KMS error | Customer-managed key permissions missing | KMS IAM permission and key policy |
| CLI works but app fails | Different credential source or runtime configuration | Compare caller identity and SDK configuration |

### Systematic troubleshooting workflow

1. Run `aws sts get-caller-identity`.
2. Identify the exact API action.
3. Identify the exact resource ARN.
4. Inspect role policies.
5. Inspect the role trust policy if assumption fails.
6. Inspect permissions boundaries.
7. Check SCPs if the account belongs to an organization.
8. Check bucket policy and VPC endpoint policy.
9. Check KMS key permissions if SSE-KMS is involved.
10. Inspect CloudTrail and application error details.
11. Make the smallest safe change.
12. Retest both allowed and disallowed operations.

Never solve every `AccessDenied` problem by attaching `AdministratorAccess`.

## 15. IAM Security Checklist for Production

### Account security
- [ ] Root user MFA is enabled.
- [ ] Root user is not used for daily administration.
- [ ] Human privileged access is protected by strong MFA.
- [ ] Workforce access uses an approved identity process.

### Identity and roles
- [ ] Applications use roles or federation where possible.
- [ ] Role trust policies trust only required principals.
- [ ] Unused IAM users and access keys are removed.
- [ ] Temporary credentials are used for workloads.
- [ ] Roles are separated by workload and environment where appropriate.

### Policies
- [ ] Least privilege is applied.
- [ ] Actions and resource ARNs are narrowly scoped.
- [ ] Wildcards are justified.
- [ ] Permissions boundaries are used where appropriate.
- [ ] SCPs are tested and reviewed.
- [ ] Resource policies are reviewed for unintended public or cross-account access.

### Monitoring
- [ ] CloudTrail logging is configured appropriately.
- [ ] Sensitive IAM changes are reviewed.
- [ ] Access Analyzer findings are investigated.
- [ ] Credential reports are reviewed where relevant.
- [ ] AccessDenied errors are investigated systematically.

### Application
- [ ] No AWS keys are committed to Git.
- [ ] SDK default credentials provider is used appropriately.
- [ ] IMDSv2 is required where supported.
- [ ] Application-level authorization is implemented.
- [ ] Data encryption and secure transport are configured.
- [ ] Logs do not expose credentials or sensitive content.

## 16. Practical Exercises with Answers

### Exercise 1 — Choose the correct identity

A Spring Boot application runs on EC2 and needs S3 upload permission. Which identity should it use?

**Answer:** A dedicated IAM role associated with the EC2 instance through an instance profile.

### Exercise 2 — Identify the trust policy

Which statement allows EC2 to assume a role?

**Answer:**

```json
{
  "Effect": "Allow",
  "Principal": {
    "Service": "ec2.amazonaws.com"
  },
  "Action": "sts:AssumeRole"
}
```

### Exercise 3 — Identify the least-privilege action

The application only uploads files. Which action is the starting point?

A. `s3:*`

B. `s3:PutObject`

C. `iam:*`

**Answer:** B. `s3:PutObject`, scoped to the required object ARN prefix.

### Exercise 4 — S3 ARN

Which resource should be used for `s3:PutObject`?

A. `arn:aws:s3:::training-invoices`

B. `arn:aws:s3:::training-invoices/uploads/*`

**Answer:** B. Object-level actions such as `s3:PutObject` use object ARNs.

### Exercise 5 — Role assumption succeeds, upload fails

What should you check?

**Answer:** The role's permissions policy, bucket policy, resource ARN, conditions, SCP, permissions boundary, endpoint policy, and KMS authorization if applicable.

### Exercise 6 — Upload succeeds, delete fails

Is this necessarily a problem?

**Answer:** No. If the application only needs to upload files, denying delete is an intentional least-privilege design.

### Exercise 7 — What does an SCP do?

**Answer:** It sets maximum permissions available to principals in affected AWS Organization accounts. It does not grant permissions.

### Exercise 8 — Why use temporary credentials?

**Answer:** They expire and reduce reliance on long-term credentials stored in applications or configuration.

### Exercise 9 — What should you do after exposing an access key?

**Answer:** Deactivate or revoke it immediately, investigate usage, assess impact, replace the credential method, and remove the exposed secret from repository history where practical.

### Exercise 10 — Why does application authorization still matter?

**Answer:** IAM authorizes the application workload to call AWS services. The application must still decide whether a particular customer can access a particular invoice.

## 18. English Speaking Practice

### Question 1: What is AWS IAM?

**Model answer:**

AWS IAM stands for Identity and Access Management. It helps us manage identities and permissions in AWS. We use IAM users, groups, roles, and policies to control access to AWS resources.

### Question 2: What is the difference between a trust policy and a permissions policy?

**Model answer:**

A trust policy defines who can assume a role. A permissions policy defines what the role can do after it is assumed. For example, EC2 can assume an application role, and that role can upload files to S3.

### Question 3: Why should an application use an IAM role?

**Model answer:**

An IAM role provides temporary credentials to an application. We do not need to store permanent access keys in source code. We can also manage the application's permissions centrally.

### Question 4: How do you troubleshoot an AccessDenied error?

**Model answer:**

First, I check the current identity with `aws sts get-caller-identity`. Then I identify the action and resource. I review the identity policy, resource policy, permissions boundary, SCP, and other relevant controls.

### Question 5: What is least privilege?

**Model answer:**

Least privilege means giving an identity only the permissions it needs. For example, an invoice application that uploads files should not have permission to delete every object in an AWS account.

### Five-minute speaking script

Today, I completed my review of AWS IAM.

IAM stands for Identity and Access Management. It controls who can access AWS resources and what actions they can perform.

An IAM role is commonly used by applications running on AWS. For example, a Spring Boot application can run on EC2 and use an instance role to upload files to S3.

The role has a trust policy and a permissions policy. The trust policy defines who can assume the role. The permissions policy defines what the role can do.

We should follow the principle of least privilege. The application should receive only the permissions it needs.

We should also use temporary credentials instead of storing long-term access keys in source code.

When an AccessDenied error occurs, we should identify the caller, action, and resource. Then we can review all relevant policy layers.

These practices help us build secure and maintainable applications on AWS.

## 19. AWS Interview Questions and Answers

### Q1. What is AWS IAM?

AWS Identity and Access Management is a service for controlling access to AWS resources through identities, policies, and role-based access.

### Q2. What is the difference between an IAM user and an IAM role?

An IAM user can have long-term credentials. An IAM role is assumed by a trusted principal and normally provides temporary credentials.

### Q3. What is a trust policy?

A trust policy defines which principals can assume an IAM role and under what conditions.

### Q4. What is a permissions policy?

A permissions policy defines the actions and resources that an identity can access, subject to other applicable controls.

### Q5. What is STS?

AWS Security Token Service provides temporary security credentials and supports role-assumption operations.

### Q6. What is an EC2 instance profile?

An instance profile is a container for an IAM role that can be associated with an EC2 instance.

### Q7. What is least privilege?

Least privilege means granting only the permissions required for a task.

### Q8. What is a permissions boundary?

A permissions boundary sets the maximum permissions that identity-based policies can grant to an IAM user or role. It does not grant permissions itself.

### Q9. What is an SCP?

A Service Control Policy sets the maximum permissions available to principals in affected AWS Organization accounts. It does not grant permissions.

### Q10. Why might an S3 request be denied even when the role policy allows it?

An applicable explicit Deny, bucket policy, permissions boundary, SCP, session policy, VPC endpoint policy, KMS key policy, or service-specific condition may restrict the request.

### Q11. How does a Spring Boot application on EC2 obtain AWS credentials?

The AWS SDK default credentials provider chain can retrieve temporary credentials through the EC2 instance metadata service when the instance has an appropriate IAM role.

### Q12. How do you investigate an IAM access issue?

Identify the caller, action, and resource; inspect identity and resource policies, boundaries, SCPs, session and endpoint policies, KMS authorization, and CloudTrail events where relevant.
