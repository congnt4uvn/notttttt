## 2. What Is Amazon EC2?

**Amazon Elastic Compute Cloud (Amazon EC2)** provides resizable virtual servers in the AWS Cloud. An EC2 virtual server is called an **instance**.

You can choose its:

- Operating system, usually through an Amazon Machine Image (AMI).
- CPU and memory capacity, through an instance type.
- Storage, such as Amazon EBS volumes or instance store.
- Network placement, such as a VPC subnet.
- Network access rules, through security groups.
- Permissions to access other AWS services, through an IAM role.

### Common use cases

| Use case | Example |
|---|---|
| Web application | Run a Java Spring Boot API |
| Website | Host an Nginx or Apache web server |
| Application server | Run business services |
| Development environment | Create a temporary test server |
| Batch processing | Process files or scheduled jobs |
| Machine learning | Run workloads on GPU instances |
| Database server | Run a database when self-management is required |

For many managed workloads, AWS offers alternatives such as Lambda, ECS, EKS, and managed database services. EC2 is useful when you need operating-system-level control or software that requires a virtual machine.

### Basic architecture

```text
Users
  |
  v
Internet
  |
  v
Internet Gateway
  |
  v
VPC
  |
  v
Public Subnet
  |
  +---- Security Group
  |
  v
EC2 Instance
  |
  +---- Spring Boot Application
  |
  +---- EBS Volume
```

An Internet Gateway alone does not make an instance reachable. The subnet route table, public IPv4 address or other routing arrangement, security group, and operating-system firewall must also permit the required traffic.

## 3. EC2 Instance Lifecycle

An EC2 instance has states that describe its lifecycle.

| State | Meaning |
|---|---|
| `pending` | AWS is preparing the instance |
| `running` | The instance is running |
| `stopping` | AWS is stopping the instance |
| `stopped` | The instance is shut down |
| `shutting-down` | AWS is preparing to terminate it |
| `terminated` | The instance has been permanently deleted |

`rebooting` is an operation, not a separate EC2 instance state.

### Reboot vs Stop/Start vs Terminate

| Operation | What happens | Important consideration |
|---|---|---|
| Reboot | Restarts the operating system | Usually keeps the same instance and attached storage |
| Stop | Shuts down an EBS-backed instance | EBS data is retained; instance-store data is lost |
| Start | Starts a stopped instance | Public IPv4 address can change |
| Terminate | Permanently deletes the instance | Root EBS volume is deleted by default when its `DeleteOnTermination` setting is enabled |

**Remember:**

- Use **reboot** when the operating system needs a restart.
- Use **stop/start** when you want to shut down an EBS-backed instance and later use it again.
- Use **terminate** when you no longer need the instance.
- Before terminating, check which EBS volumes will be deleted and back up important data.
- Stopping an instance does not necessarily stop every related cost. EBS storage and other provisioned resources can continue to incur charges.

### Lifecycle diagram

```text
             Launch
               |
               v
            pending
               |
               v
            running
            /     \
       Stop       Terminate
         |            |
         v            v
      stopping    shutting-down
         |            |
         v            v
       stopped     terminated
         |
        Start
         |
         v
      pending
         |
         v
      running
```

## 4. EC2 Instance Families and Types

An instance type determines the hardware capacity available to your virtual server, including vCPUs, memory, networking, and sometimes local storage or accelerators.

Choose a family based on the workload rather than selecting the largest instance.

| Family category | Common prefixes | Best suited for |
|---|---|---|
| General purpose | T, M | Web servers, development, application servers |
| Compute optimized | C | CPU-intensive services, batch processing |
| Memory optimized | R, X | In-memory databases, large caches, analytics |
| Storage optimized | I, D, H | High-throughput or high-IOPS local storage workloads |
| Accelerated computing | P, G, Inf | GPU computing, graphics, machine learning inference |

The exact families and availability differ by Region.

### General purpose

- Balanced CPU, memory, and networking.
- Useful for many everyday application workloads.
- T family instances are burstable: they use CPU credits to support bursts above their baseline CPU performance.
- M family instances are commonly used for balanced workloads.

### Compute optimized

- Designed for workloads that benefit from higher CPU performance.
- Examples: video encoding, scientific modeling, high-performance application servers.

### Memory optimized

- Designed for workloads that need large memory capacity.
- Examples: in-memory caches, memory-heavy databases, real-time analytics.

### Storage optimized

- Designed for workloads with high local storage performance or throughput.
- Some instance-store-backed data is temporary and should not be treated as durable backup storage.

### Accelerated computing

- Uses hardware accelerators such as GPUs or specialized chips.
- Examples: machine learning, graphics rendering, and parallel processing.

### Instance type naming

A type name often contains a family, generation, optional feature, and size.

Example format:

```text
family + generation + optional feature + size
```

For example, `m7i.large` can be read as:

- `m`: general-purpose family.
- `7`: generation.
- `i`: an instance-family variant.
- `large`: size.

A size such as `large`, `xlarge`, or `2xlarge` represents a capacity tier within that family. Do not assume that two different families with the same size label have identical CPU or memory resources.

### How to choose

| Workload | Starting point for evaluation |
|---|---|
| Small development API | A small general-purpose or burstable instance |
| Production web API | General purpose; load-test before choosing size |
| CPU-heavy processing | Compute optimized |
| Large in-memory cache | Memory optimized |
| GPU model inference | Suitable accelerated-computing family |

Always validate the selection with metrics such as CPU utilization, memory usage, network throughput, and application latency.

## 5. Amazon Machine Images (AMIs)

An **Amazon Machine Image (AMI)** is a template used to launch EC2 instances.

An AMI can include:

- An operating system.
- Preinstalled software.
- Configuration and application components.
- Launch permissions and block-device mappings.

### AMI types

| AMI type | Description |
|---|---|
| AWS-provided AMI | Published by AWS |
| Marketplace AMI | Published by a third-party seller |
| Community AMI | Shared publicly by another publisher |
| Custom AMI | Created and maintained by your organization |

### Important AMI facts

- AMIs are Region-specific.
- To use an AMI in another Region, copy it to that Region.
- An AMI can be used to launch multiple instances.
- A custom AMI can standardize server configuration.
- Review the publisher and security posture before using public or Marketplace images.

### Example

Your team configures a server with:

- A supported Linux operating system.
- A Java runtime.
- Monitoring and security agents.
- Standard operating-system settings.

You can create a custom AMI from that configured instance and use it as a consistent base for additional servers. For repeatable production deployments, combine AMIs with launch templates and automated image-building practices.

## 6. Key Pairs and Connecting to EC2

A key pair is commonly used to authenticate to a Linux EC2 instance over SSH.

A key pair consists of:

- **Public key:** AWS places or makes it available to the instance during launch.
- **Private key:** You keep this securely and use it to authenticate.

For Windows instances, connection methods commonly include Remote Desktop Protocol (RDP) and Windows password retrieval workflows, depending on the image and configuration.

### Linux SSH example

```bash
ssh -i my-ec2-key.pem ec2-user@YOUR_PUBLIC_IP
```

The default username depends on the AMI. Common examples include:

| Image family | Common username |
|---|---|
| Amazon Linux | `ec2-user` |
| Ubuntu | `ubuntu` |
| Some Debian images | `admin` or `debian` |

Check the image publisher's instructions rather than guessing.

On Linux or macOS, restrict the private key file permissions:

```bash
chmod 400 my-ec2-key.pem
```

### Key-pair security

- Never share your private key.
- Never commit a private key to Git.
- Do not paste private key contents into chat, tickets, or logs.
- Store keys in a secure location with restricted access.
- If a private key is lost or exposed, follow a recovery or replacement process; do not assume AWS can show you the original private key again.

### SSH network access

SSH normally uses TCP port 22. Allow it only from a trusted source IP or approved network.

Avoid this broad rule:

```text
TCP 22 from 0.0.0.0/0
```

## 7. Security Groups

A **security group** acts as a virtual firewall for network interfaces associated with an EC2 instance.

Security groups are **stateful**:

- If an inbound connection is allowed, response traffic for that connection is automatically allowed.
- You do not need a separate outbound rule just for the response traffic.

### Inbound and outbound rules

| Rule direction | Example |
|---|---|
| Inbound | Allow HTTPS on TCP 443 from approved clients |
| Inbound | Allow SSH on TCP 22 from an administrator's IP |
| Outbound | Allow the application to reach required external services |

New security groups typically start with no inbound rules and an outbound rule that allows all outbound traffic. Review and adjust rules for your requirements.

### Example web application rules

| Type | Protocol | Port | Source | Purpose |
|---|---|---:|---|---|
| SSH | TCP | 22 | Your trusted public IP `/32` | Administration |
| HTTP | TCP | 80 | `0.0.0.0/0` | Public website, if required |
| HTTPS | TCP | 443 | `0.0.0.0/0` | Public encrypted website |

For an application behind a load balancer, a better design is often to allow application traffic only from the load balancer's security group. Do not expose an application port such as 8080 directly to the whole Internet unless there is a specific, justified requirement.

### Security group vs Network ACL

| Feature | Security Group | Network ACL |
|---|---|---|
| Scope | Network interface / instance association | Subnet |
| Stateful? | Yes | No, stateless |
| Rules | Allow rules | Allow and deny rules |
| Evaluation | All applicable rules are considered | Rules are evaluated by rule number |

Network ACLs will be studied in more detail in the VPC module.

## 8. Amazon EBS Fundamentals

**Amazon Elastic Block Store (EBS)** provides block-level storage volumes for EC2 instances.

Think of an EBS volume as a virtual disk that you attach to an EC2 instance.

### Common uses

- Operating-system root disk.
- Application data.
- Database storage.
- Logs and persistent files.

### EBS volume concepts

| Concept | Meaning |
|---|---|
| Volume | A block-storage disk |
| Snapshot | A point-in-time backup of a volume |
| Root volume | The volume containing the operating system |
| Data volume | An additional volume for application or data files |
| Encryption | Protects supported data at rest and related volume snapshots |

### Common EBS volume types

| Type | General purpose |
|---|---|
| `gp3` | General-purpose SSD for many workloads |
| `io2` | Provisioned IOPS SSD for demanding I/O workloads |
| `st1` | Throughput-oriented HDD |
| `sc1` | Lower-cost, infrequently accessed HDD |

Choose a type based on workload performance, durability, and cost requirements. Check current service limits and pricing before deployment.

### Availability Zone limitation

An EBS volume is created in a specific Availability Zone. It can normally be attached only to an instance in the same Availability Zone.

To use the data in another Availability Zone:

1. Create a snapshot of the EBS volume.
2. Use the snapshot to create a new EBS volume in the target Availability Zone.
3. Attach the new volume to an appropriate instance.

You can also copy snapshots to another Region for geographic recovery planning.

### EBS snapshots

Snapshots are incremental backups stored and managed by AWS.

Example:

```text
EC2 Instance
    |
    +---- Root EBS Volume
    |
    +---- Data EBS Volume
                 |
                 v
             Snapshot
                 |
        +--------+---------+
        |                  |
        v                  v
  Restore in AZ A    Restore in AZ B
```

Snapshots are not a substitute for a complete backup and recovery strategy. Define retention, access controls, encryption, and recovery testing.

### EBS encryption

EBS encryption helps protect data at rest. Encrypted volumes and snapshots use AWS Key Management Service (AWS KMS) keys.

For production systems:

- Enable encryption for sensitive data.
- Restrict access to KMS keys.
- Understand who can create, copy, restore, and share snapshots.
- Test restoration procedures.

## 9. EBS vs Instance Store

EC2 can provide block storage through EBS or instance store, depending on the instance type and configuration.

| Feature | EBS | Instance Store |
|---|---|---|
| Storage location | Network-attached block storage | Physically attached host storage |
| Persistence | Designed to persist independently of the instance lifecycle | Temporary; data can be lost when the instance stops, terminates, or underlying hardware fails |
| Detach and reattach | Supported for eligible volumes | Not like an EBS volume |
| Typical use | OS, application data, databases | Cache, scratch data, temporary processing |
| Backup | EBS snapshots | Use application-level backup or copy data elsewhere |

**Rule:** Do not store the only copy of important data on instance store.

## 10. EC2 Networking: Public and Private IP Addresses

An EC2 instance can have private and public network addresses, depending on its network configuration.

### Private IPv4 address

- Used for communication within a VPC and connected private networks.
- Not directly routable from the public Internet.
- Commonly used for communication between application tiers.

### Public IPv4 address

- Can be used for communication with the public Internet when routing and security rules permit it.
- A normal auto-assigned public IPv4 address can change after a stop/start.
- AWS public IPv4 addresses can incur charges; check current pricing.

### Elastic IP address

An **Elastic IP address** is a static public IPv4 address allocated to your AWS account. It can be associated with supported resources such as an EC2 instance or network interface.

Use it only when a stable public IPv4 address is genuinely required. It is not a replacement for a resilient architecture, DNS, or a load balancer.

### Public subnet vs private subnet

A subnet is considered public when its route table has a route to an Internet Gateway. A private subnet does not have a direct route to an Internet Gateway for general Internet access.

```text
                         Internet
                            |
                     Internet Gateway
                            |
              +-------------+-------------+
              |                           |
              v                           v
         Public Subnet               Private Subnet
              |                           |
        Load Balancer                 EC2 App Server
              |                           |
              +-------------+-------------+
                            |
                       Internal VPC
```

A public IP address alone does not make an instance reachable. Routing, security groups, network ACLs, and host firewall settings must also be correct.

A common production pattern is to put a public-facing load balancer in public subnets and application instances in private subnets.

## 11. EC2 Instance Metadata and IAM Roles

EC2 instance metadata provides information about the running instance from within that instance.

The metadata service is available through a link-local address. **IMDSv2** uses a session-oriented token mechanism and is recommended over IMDSv1.

### Why metadata is useful

An application or administrator can retrieve instance information such as:

- Instance ID.
- Instance type.
- Region and Availability Zone.
- Network interface information.
- Temporary credentials when an IAM role is attached.

### IMDSv2 example

Run this from inside an EC2 instance configured to use IMDSv2:

```bash
TOKEN=$(curl -X PUT \
  "http://169.254.169.254/latest/api/token" \
  -H "X-aws-ec2-metadata-token-ttl-seconds: 21600")

curl -H "X-aws-ec2-metadata-token: $TOKEN" \
  "http://169.254.169.254/latest/meta-data/instance-id"
```

This example retrieves the instance ID. Do not print or log metadata credentials.

### IAM role for EC2

If an EC2 application needs to access S3, assign an IAM role to the instance through an instance profile.

```text
Spring Boot Application
          |
          v
   AWS SDK for Java
          |
          v
 Default Credential Provider Chain
          |
          v
 EC2 Instance Profile
          |
          v
 Temporary IAM Role Credentials
          |
          v
       Amazon S3
```

Avoid hardcoding access keys in application source code or configuration files. Grant only the permissions the application needs.

### Important security note

Require IMDSv2 where appropriate and protect applications against server-side request forgery (SSRF). An application vulnerability that can reach metadata endpoints may expose sensitive instance information or credentials if the environment is not properly protected.

## 12. AWS CLI: Inspect and Manage EC2

The examples below use the Singapore Region, `ap-southeast-1`.

First, verify your AWS identity and Region:

```bash
aws sts get-caller-identity

aws configure get region
```

Set the Region explicitly for commands:

```bash
export AWS_DEFAULT_REGION=ap-southeast-1
```

On Windows PowerShell:

```powershell
$env:AWS_DEFAULT_REGION = "ap-southeast-1"
```

### Describe instances

```bash
aws ec2 describe-instances
```

List instance IDs, states, and types:

```bash
aws ec2 describe-instances \
  --query "Reservations[].Instances[].[InstanceId,State.Name,InstanceType,PrivateIpAddress,PublicIpAddress]" \
  --output table
```

### Describe instance types

```bash
aws ec2 describe-instance-types \
  --instance-types t3.micro t3.small \
  --query "InstanceTypes[].[InstanceType,VCpuInfo.DefaultVCpus,MemoryInfo.SizeInMiB]" \
  --output table
```

The example types may not be available in every Region or account. Check availability before using them.

### Describe AMIs

Find Amazon Linux images published by the relevant owner in the selected Region. AMI owners and filters should be checked against current AWS guidance.

```bash
aws ec2 describe-images \
  --owners amazon \
  --filters "Name=state,Values=available" \
             "Name=name,Values=al2023-ami-*-x86_64" \
  --query "Images | sort_by(@, &CreationDate)[-10:].[ImageId,Name,CreationDate]" \
  --output table
```

Review the image name, architecture, creation date, and publisher before selecting an AMI. Do not copy an AMI ID from an unrelated Region.

### Describe security groups

```bash
aws ec2 describe-security-groups
```

### Describe EBS volumes

```bash
aws ec2 describe-volumes \
  --query "Volumes[].[VolumeId,State,Size,VolumeType,AvailabilityZone,Encrypted]" \
  --output table
```

### Start, stop, and reboot

Replace the placeholder with an actual instance ID:

```bash
aws ec2 start-instances --instance-ids i-REPLACE_ME

aws ec2 stop-instances --instance-ids i-REPLACE_ME

aws ec2 reboot-instances --instance-ids i-REPLACE_ME
```

### Terminate an instance

**Warning: termination is destructive.** Check backups, attached volumes, and `DeleteOnTermination` settings before running this command.

```bash
aws ec2 terminate-instances --instance-ids i-REPLACE_ME
```

### Check instance status

```bash
aws ec2 describe-instance-status \
  --instance-ids i-REPLACE_ME \
  --include-all-instances
```

## 13. Hands-on Lab: Launch a Linux EC2 Instance in Singapore

### Lab objective

Launch a small Linux EC2 instance in `ap-southeast-1`, connect to it securely, and verify that it is running.

**Cost and safety:** EC2 instances, EBS volumes, public IPv4 addresses, and related resources may incur charges. Review the current Free Tier or plan eligibility, pricing, and account budget. Stop or terminate resources when finished. Do not use production data in this exercise.

### Step 1 — Check the AWS identity and Region

```bash
aws sts get-caller-identity
aws configure set region ap-southeast-1
```

Confirm that you are using the intended AWS account and permissions.

### Step 2 — Inspect available resources

List VPCs:

```bash
aws ec2 describe-vpcs \
  --query "Vpcs[].[VpcId,CidrBlock,IsDefault]" \
  --output table
```

List subnets:

```bash
aws ec2 describe-subnets \
  --query "Subnets[].[SubnetId,VpcId,AvailabilityZone,MapPublicIpOnLaunch]" \
  --output table
```

List key pairs:

```bash
aws ec2 describe-key-pairs \
  --query "KeyPairs[].[KeyName,KeyPairId]" \
  --output table
```

List security groups:

```bash
aws ec2 describe-security-groups \
  --query "SecurityGroups[].[GroupId,GroupName,VpcId]" \
  --output table
```

Do not assume that a default VPC, public subnet, key pair, or suitable security group exists. If a required resource is missing, create it deliberately using the Console or a reviewed infrastructure-as-code template.

### Step 3 — Select a suitable AMI

Use the AMI discovery command from Section 12, or select a current supported Linux AMI in the EC2 Console in Singapore.

Record its AMI ID. Confirm:

- The AMI is available in `ap-southeast-1`.
- The architecture matches the instance type.
- The operating system is supported.
- You know the correct SSH username.

Do not use an invented or copied AMI ID.

### Step 4 — Prepare a security group

Create or select a security group in the VPC that contains your chosen subnet.

For a basic SSH lab, allow:

| Type | Protocol | Port | Source |
|---|---|---:|---|
| SSH | TCP | 22 | Your current trusted public IP `/32` |

If you later test a web server, add HTTP TCP 80 only when needed. Remove unnecessary inbound rules after the lab.

### Step 5 — Prepare launch values

Set shell variables to the actual values from your account:

```bash
AMI_ID="ami-REPLACE_WITH_VALID_AMI_ID"
SUBNET_ID="subnet-REPLACE_WITH_SUBNET_ID"
SG_ID="sg-REPLACE_WITH_SECURITY_GROUP_ID"
KEY_NAME="REPLACE_WITH_EXISTING_KEY_PAIR_NAME"
INSTANCE_TYPE="t3.micro"
```

The sample instance type is only an example. Confirm that it is supported by the selected AMI architecture, subnet Availability Zone, and your account.

### Step 6 — Launch the instance

```bash
aws ec2 run-instances \
  --image-id "$AMI_ID" \
  --instance-type "$INSTANCE_TYPE" \
  --key-name "$KEY_NAME" \
  --security-group-ids "$SG_ID" \
  --subnet-id "$SUBNET_ID" \
  --count 1 \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=aws-day14-lab}]'
```

This command assumes the selected subnet and security group are compatible and that the account has the required permissions. If you need an IAM role, configure an instance profile using a reviewed role with least-privilege permissions.

### Optional: user data

User data can run initialization commands when an instance launches. The following example is for an Amazon Linux 2023 AMI and installs a simple web server. It is not a universal script for every Linux distribution.

```bash
#!/bin/bash
dnf update -y
dnf install -y httpd
systemctl enable httpd
systemctl start httpd
echo "Hello from my EC2 lab" > /var/www/html/index.html
```

To pass a script from a local file, save it as `user-data.sh` and add this option to `run-instances`:

```bash
--user-data file://user-data.sh
```

Do not put passwords, API keys, or private credentials in user data. User data may be accessible to users or processes with sufficient instance permissions.

### Step 7 — Find the instance details

```bash
aws ec2 describe-instances \
  --filters "Name=tag:Name,Values=aws-day14-lab" \
  --query "Reservations[].Instances[].[InstanceId,State.Name,PublicIpAddress,PrivateIpAddress,Placement.AvailabilityZone]" \
  --output table
```

Wait until the instance is running and its status checks pass.

### Step 8 — Connect using SSH

```bash
chmod 400 my-ec2-key.pem

ssh -i my-ec2-key.pem ec2-user@YOUR_PUBLIC_IP
```

Replace the key file, username, and public IP with your actual values. If you selected Ubuntu, the username is commonly `ubuntu`.

### Step 9 — Verify the server

After connecting:

```bash
whoami
hostname
uname -a
df -h
free -h
```

If you installed the optional web server, test it from a browser or with:

```bash
curl http://localhost
```

For public access, ensure the instance has a valid route through an Internet Gateway, a public IPv4 address or other suitable connectivity, and an appropriate inbound security group rule.

### Step 10 — Clean up

If you no longer need the lab, terminate the instance:

```bash
aws ec2 terminate-instances --instance-ids i-REPLACE_ME
```

Then verify whether any EBS volumes, snapshots, Elastic IP addresses, or other resources remain. Clean up only resources that you have positively identified as belonging to this lab.

## 14. Troubleshooting EC2 Connections

| Symptom | Possible cause | What to check |
|---|---|---|
| SSH connection timeout | Network path is blocked | Public IP, subnet route, Internet Gateway, security group, NACL, host firewall |
| Permission denied (publickey) | Wrong key or username | Private key, key pair selected at launch, AMI username |
| Instance status checks fail | OS or infrastructure problem | System and instance status checks, system logs, console output |
| Website cannot be reached | Application or HTTP path issue | Application process, listening port, security group, route, host firewall |
| No public IP | Subnet or launch configuration | Public IPv4 assignment and subnet settings |

### Session Manager as an alternative

AWS Systems Manager Session Manager can provide shell access without opening inbound SSH, when correctly configured.

Typical requirements include:

- SSM Agent installed and running.
- An appropriate IAM instance role with required Systems Manager permissions.
- Network connectivity to Systems Manager endpoints, directly or through VPC endpoints.
- The instance registered and available in Systems Manager.

Session Manager is often a better operational choice than distributing SSH private keys, but it still requires careful IAM permissions and audit configuration.

## 15. Deploying a Spring Boot Application on EC2

A simple architecture for a Spring Boot API:

```text
                 Client
                   |
                   v
              HTTPS (443)
                   |
                   v
          Application Load Balancer
                   |
                   v
             EC2 Instance
                   |
          Spring Boot Application
               Port 8080
                   |
          +--------+--------+
          |                 |
          v                 v
      Amazon RDS        Amazon S3
      Database          File Storage
```

For a production architecture:

- Prefer private subnets for application instances.
- Use a load balancer for public HTTP/HTTPS traffic.
- Restrict the application security group to traffic from the load balancer.
- Use an EC2 IAM role for AWS SDK access.
- Store secrets in a suitable secrets-management service rather than source code.
- Send logs and metrics to CloudWatch.
- Use EBS encryption and backups where appropriate.
- Consider Auto Scaling for changing demand and resilience.

### Spring Boot configuration example

For an application that uses the AWS SDK for Java 2.x, configure the SDK to use its default credential provider chain instead of hardcoding access keys.

Example S3 client bean:

```java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import software.amazon.awssdk.services.s3.S3Client;

@Configuration
public class AwsConfig {

    @Bean
    public S3Client s3Client() {
        return S3Client.builder().build();
    }
}
```

When running on EC2 with a suitable instance profile, the SDK can obtain temporary role credentials through the supported credential provider chain.

The IAM role should grant only the required S3 actions on the required bucket and object prefix.

### Build and run

A basic deployment flow:

```bash
./mvnw clean package
java -jar target/application.jar
```

Configure the application to listen on the intended port, and ensure the EC2 operating system and network configuration allow only the required traffic. For a real deployment, use a process manager or container platform, health checks, centralized logs, and a repeatable release process rather than relying on a manually opened terminal.

## 16. Common EC2 Mistakes

1. Choosing an instance type without measuring the workload.
2. Opening SSH or RDP to the entire Internet.
3. Storing important data only on instance store.
4. Terminating an instance without checking EBS deletion settings.
5. Assuming a public IP automatically makes an instance Internet-accessible.
6. Using an AMI ID from a different Region.
7. Hardcoding IAM access keys in a Spring Boot application.
8. Forgetting that a public IPv4 address can change after stop/start.

## 17. Practical Exercises

### Exercise 1 — EC2 fundamentals

**Question:** What is an EC2 instance?

**Answer:** An EC2 instance is a resizable virtual server running in AWS. You select its AMI, instance type, storage, networking, and security configuration.

### Exercise 2 — Lifecycle

**Question:** What is the difference between stopping and terminating an EBS-backed instance?

**Answer:** Stopping shuts down the instance while normally retaining attached EBS volumes. Terminating permanently deletes the instance and can delete EBS volumes whose `DeleteOnTermination` setting is enabled.

### Exercise 3 — Instance families

**Question:** Which category would you evaluate first for a CPU-intensive batch-processing workload?

**Answer:** Compute optimized, commonly a C family instance. Benchmark the application before selecting a final type and size.

### Exercise 4 — AMIs

**Question:** Can you directly use an AMI ID from one Region to launch an instance in another Region?

**Answer:** No. AMIs are Region-specific. Copy the AMI to the target Region or select an appropriate AMI there.

### Exercise 5 — Security groups

**Question:** Are security groups stateful or stateless?

**Answer:** Stateful. Return traffic for an allowed connection is automatically permitted.

### Exercise 6 — EBS

**Question:** Can an EBS volume created in one Availability Zone normally be attached directly to an instance in another Availability Zone?

**Answer:** No. Create a snapshot and restore it as a new volume in the target Availability Zone.

### Exercise 7 — Networking

**Question:** Does assigning a public IPv4 address automatically make an EC2 instance reachable from the Internet?

**Answer:** No. The subnet needs suitable routing, typically through an Internet Gateway, and security groups, network ACLs, and host firewall rules must permit the traffic.

### Exercise 8 — IAM

**Question:** What is the recommended way for an EC2-hosted Spring Boot application to access S3?

**Answer:** Attach an IAM role through an instance profile and let the AWS SDK obtain temporary credentials. Do not hardcode long-term access keys.

### Exercise 9 — Troubleshooting

**Question:** SSH returns `Permission denied (publickey)`. Name three things to check.

**Answer:**
1. Whether the private key matches the key pair selected at launch.
2. Whether the correct operating-system username is used.
3. Whether the private key file and SSH command are configured correctly.

### Exercise 10 — Cost and cleanup

**Question:** Does stopping an EC2 instance guarantee that all related AWS charges stop?

**Answer:** No. EBS volumes, snapshots, public IPv4 addresses, and other provisioned resources may continue to incur charges. Review the resources and current pricing.

## 20. AWS Interview Questions and Answers

### Q1. What is Amazon EC2?

Amazon EC2 is an AWS service that provides resizable compute capacity through virtual servers called instances.

### Q2. What is the difference between an AMI and an instance type?

An AMI defines the software image used to launch an instance, while an instance type defines the underlying compute capacity, such as CPU and memory.

### Q3. What happens to EBS data when an instance is stopped?

EBS volumes normally persist when an EBS-backed instance is stopped. However, instance-store data is lost when the instance stops.

### Q4. What is the difference between reboot, stop, and terminate?

- Reboot restarts the operating system.
- Stop shuts down an EBS-backed instance while retaining its EBS volumes.
- Terminate permanently deletes the instance and may delete associated EBS volumes depending on their deletion settings.

### Q5. What is an EC2 security group?

A security group is a stateful virtual firewall associated with an instance's network interface. It controls allowed inbound and outbound traffic.

### Q6. What is the difference between EBS and instance store?

EBS is persistent block storage that exists independently of the EC2 instance lifecycle. Instance store is temporary host-attached storage.

### Q7. Can an EBS volume be attached to instances in different Availability Zones?

A standard EBS volume is AZ-scoped and is attached to an instance in the same Availability Zone. A snapshot can be used to create a volume in another Availability Zone.

### Q8. What is an Elastic IP?

An Elastic IP is a static public IPv4 address allocated to an AWS account. It can be associated with supported resources such as an EC2 instance or network interface.

### Q9. How should an EC2 application access S3 securely?

Attach a least-privilege IAM role to the instance through an instance profile. The application can use the AWS SDK default credential provider chain to obtain temporary credentials.

### Q10. What is IMDSv2?

IMDSv2 is the second version of the EC2 Instance Metadata Service. It uses a session token obtained through an HTTP PUT request before metadata requests are made.

### Q11. Does a public IP make an EC2 instance publicly accessible?

No. The subnet route table, Internet Gateway path, security group, network ACL, and operating-system firewall must also allow the traffic.

### Q12. How can you reduce the risk of exposing SSH?

Restrict TCP port 22 to trusted source IP ranges, avoid broad Internet access, consider Systems Manager Session Manager, and use strong identity and audit controls.
