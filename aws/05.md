## 3. AWS CLI — Command Line Interface

AWS CLI allows you to manage AWS services using commands in your terminal.

Instead of opening the AWS Console and clicking buttons, you can execute commands.

### 3.1 Install AWS CLI on Windows

Download the official AWS CLI v2 installer:

[Install AWS CLI on Windows — AWS Documentation](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html?utm_source=chatgpt.com)

After installation, open PowerShell:

```
aws --version
```

Example output:

```
aws-cli/2.x.x Python/3.x Windows/10 exe/AMD64
```

### 3.2 Configure AWS CLI securely

For a new setup, I recommend AWS IAM Identity Center (SSO) rather than creating long-lived access keys.

Configure an SSO profile:

```
aws configure sso
```

Follow the prompts to select your SSO start URL, account, role, and default Region.

Log in:

```
aws sso login --profile development
```

Verify your identity:

```
aws sts get-caller-identity --profile development
```

Example output:

```
{
    "UserId": "EXAMPLE:user@example.com",
    "Account": "123456789012",
    "Arn": "arn:aws:sts::123456789012:assumed-role/DeveloperRole/example"
}
```

This command tells you which AWS identity your CLI is currently using.

### 3.3 Useful AWS CLI commands

| Command                          | Description                |
| -------------------------------- | -------------------------- |
| `aws --version`                  | Check CLI version          |
| `aws configure list`             | Show configuration sources |
| `aws configure get region`       | Get configured Region      |
| `aws sts get-caller-identity`    | Check current identity     |
| `aws s3 ls`                      | List S3 buckets            |
| `aws ec2 describe-instances`     | List EC2 instances         |
| `aws iam list-roles`             | List IAM roles             |
| `aws cloudformation list-stacks` | List CloudFormation stacks |

Use a specific profile when you have multiple AWS accounts or environments:

```
aws s3 ls --profile development
aws s3 ls --profile production
```

Important: Do not put AWS access keys in source code, Git repositories, or Docker images. Prefer temporary credentials and IAM roles.

## 5. AWS SDK — Software Development Kit

AWS SDK allows your application to communicate with AWS services programmatically.

For example, a Java Spring Boot application can:

- Upload files to Amazon S3.
- Read messages from Amazon SQS.
- Publish messages to Amazon SNS.
- Access DynamoDB.
- Invoke AWS Lambda.
- Retrieve secrets from AWS Secrets Manager.

### AWS CLI vs AWS SDK

| Feature      | AWS CLI                            | AWS SDK                         |
| ------------ | ---------------------------------- | ------------------------------- |
| Main purpose | Manage AWS from terminal           | Integrate AWS into applications |
| Interface    | Commands                           | Programming APIs                |
| Example      | `aws s3 ls`                        | `s3Client.listBuckets()`        |
| Used by      | Developers, administrators, DevOps | Application developers          |

### 5.1 Java Spring Boot + AWS SDK v2

Let's create a simple Spring Boot integration with Amazon S3.

Step 1 — Add Maven dependency

```
<dependency>
    <groupId>software.amazon.awssdk</groupId>
    <artifactId>s3</artifactId>
</dependency>
```

If your project does not already manage AWS SDK versions, import the AWS SDK for Java v2 BOM in your Maven `dependencyManagement`.

Step 2 — Configure S3Client

```
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

import software.amazon.awssdk.auth.credentials.DefaultCredentialsProvider;
import software.amazon.awssdk.regions.Region;
import software.amazon.awssdk.services.s3.S3Client;

@Configuration
public class AwsConfig {

    @Bean
    public S3Client s3Client() {
        return S3Client.builder()
                .region(Region.AP_SOUTHEAST_1)
                .credentialsProvider(
                    DefaultCredentialsProvider.create()
                )
                .build();
    }
}
```

Here:

- `S3Client` is the AWS S3 client.
- `Region.AP_SOUTHEAST_1` represents the Singapore Region.
- `DefaultCredentialsProvider` discovers credentials from supported sources, such as an SSO profile or an IAM role.

Step 3 — Create a service

```
import org.springframework.stereotype.Service;

import software.amazon.awssdk.services.s3.S3Client;
import software.amazon.awssdk.services.s3.model.ListBucketsResponse;

@Service
public class S3Service {

    private final S3Client s3Client;

    public S3Service(S3Client s3Client) {
        this.s3Client = s3Client;
    }

    public void listBuckets() {
        ListBucketsResponse response =
                s3Client.listBuckets();

        response.buckets().forEach(bucket ->
            System.out.println(bucket.name())
        );
    }
}
```

Step 4 — Call the service

```
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class S3Controller {

    private final S3Service s3Service;

    public S3Controller(S3Service s3Service) {
        this.s3Service = s3Service;
    }

    @GetMapping("/aws/s3/buckets")
    public String listBuckets() {
        s3Service.listBuckets();
        return "S3 buckets retrieved successfully";
    }
}
```

Run your Spring Boot application and call:

```
GET http://localhost:8080/aws/s3/buckets
```

Your AWS identity must have permission to list buckets, such as `s3:ListAllMyBuckets`.

Architecture

```
Client
   |
   v
Spring Boot Controller
   |
   v
S3Service
   |
   v
AWS SDK for Java v2
   |
   v
AWS Credentials Provider
   |
   v
Amazon S3
```

This architecture is useful when building applications that integrate with AWS services.

## 6. AWS Account Security

Account security is one of the most important AWS fundamentals.

### 6.1 Root user

When you create an AWS account, AWS creates a root user.

The root user has extensive permissions over the account.

Recommended practices:

- Enable MFA (Multi-Factor Authentication).
- Do not use the root user for everyday tasks.
- Do not create root access keys.
- Keep root credentials secure.
- Use an IAM Identity Center user or an appropriate IAM role for daily operations.

### 6.2 Authentication vs Authorization

These two concepts are different.

| Concept        | Meaning          | Example                          |
| -------------- | ---------------- | -------------------------------- |
| Authentication | Who are you?     | Login using SSO                  |
| Authorization  | What can you do? | Permission to upload files to S3 |

Example:

A developer successfully logs into AWS.

However, the developer cannot delete an S3 bucket because their assigned permissions do not allow that action.

- Authentication: Successful.
- Authorization: Denied.

### 6.3 AWS IAM Roles

An IAM Role is an identity that provides temporary permissions to an AWS principal or workload.

For example:

```
Spring Boot Application
        |
        v
Running on EC2
        |
        v
EC2 IAM Role
        |
        v
Temporary Credentials
        |
        v
Amazon S3
```

Instead of storing AWS access keys in your Spring Boot application, attach an IAM role to the EC2 instance.

The AWS SDK can automatically retrieve temporary credentials through its default credential provider chain.

This is a much safer approach for production workloads.

## 7. Infrastructure as Code (IaC)

Infrastructure as Code means defining and managing infrastructure using code instead of manually configuring resources.

Two popular AWS infrastructure tools are:

| Tool               | Description                          |
| ------------------ | ------------------------------------ |
| AWS CloudFormation | AWS-native infrastructure management |
| Terraform          | Multi-cloud infrastructure as code   |

Example Terraform configuration for creating an S3 bucket:

```
provider "aws" {
  region = "ap-southeast-1"
}

resource "aws_s3_bucket" "my_bucket" {
  bucket = "my-unique-learning-bucket-2026"
}
```

Deploy:

```
terraform init
terraform plan
terraform apply
```

Terraform helps you create repeatable infrastructure across development, staging, and production environments.

Example in a real project:

```
Git Repository
      |
      v
Terraform Files
      |
      v
Terraform Plan
      |
      v
Terraform Apply
      |
      v
AWS Infrastructure
  ├── VPC
  ├── EC2
  ├── S3
  ├── RDS
  └── IAM Roles
```

## 11. Interview Questions

Q1. What is the difference between AWS CLI and AWS SDK?

Answer: AWS CLI is used to manage AWS services through terminal commands, while AWS SDK allows applications to communicate with AWS services programmatically.

Q2. What is AWS CloudShell?

Answer: AWS CloudShell is a browser-based shell that allows users to execute commands and manage AWS resources without installing command-line tools locally.

Q3. What is the difference between authentication and authorization?

Answer: Authentication verifies who a user is, while authorization determines what actions the user is allowed to perform.

Q4. Why should we use IAM roles instead of hardcoded access keys?

Answer: IAM roles provide temporary credentials, reduce credential exposure, and make applications more secure.

Q5. What is Infrastructure as Code?

Answer: Infrastructure as Code is the practice of managing infrastructure through machine-readable configuration files instead of manual operations.
