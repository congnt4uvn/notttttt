## 2. What Is an AWS Account?

An AWS account is a container for AWS resources, services, permissions, and billing.

When you create an AWS account, you get an account identity and access to AWS services. You can use the account to create resources such as:

- Amazon EC2 instances
- Amazon S3 buckets
- Amazon RDS databases
- Amazon VPC networks
- AWS Lambda functions
- Amazon CloudWatch alarms

An AWS account also provides a boundary for resource management, access control, and billing. Larger organizations often use multiple AWS accounts to separate environments, teams, applications, or business units.

### 2.1 AWS account structure

```text
AWS Organization (optional)
|
+-- Management account
|
+-- Member account: Development
|   |
|   +-- IAM identities and roles
|   +-- EC2 instances
|   +-- S3 buckets
|   +-- RDS databases
|
+-- Member account: Testing
|   |
|   +-- IAM identities and roles
|   +-- Application resources
|
+-- Member account: Production
    |
    +-- IAM identities and roles
    +-- Production application resources
```

This is an example of an organization structure. A small personal learning environment may use only one AWS account.

### 2.2 Why use separate AWS accounts?

Separate accounts can help organizations:

- Isolate development, testing, and production resources.
- Apply different security policies.
- Separate billing and cost tracking.
- Reduce the impact of mistakes or compromised credentials.
- Delegate administration to different teams.

AWS Organizations can help centrally manage multiple AWS accounts. More advanced organization governance will be covered in a later lesson.

## 3. Root User, IAM User, and IAM Role

These identities are important, but they are not interchangeable.

### 3.1 AWS account root user

The root user is the identity created when an AWS account is first established. It has unrestricted access to the account's resources and settings, subject to AWS service behavior and applicable controls.

The root user is associated with the account's original sign-up email address and password.

**Security recommendation:** Do not use the root user for everyday administration or application access.

Protect it carefully:

- Enable multi-factor authentication (MFA).
- Use a strong, unique password.
- Do not create root access keys for routine programmatic access.
- Use it only for tasks that specifically require root-user access.
- Secure the email account associated with the AWS account.

### 3.2 IAM user

An IAM user is an identity in an AWS account that can have credentials and permissions assigned to it.

An IAM user may be configured for a person or a workload, but AWS generally recommends federation and temporary credentials for human access, and IAM roles for workloads, instead of creating long-lived IAM user access keys.

An IAM user can have:

- A console password, if console access is enabled.
- Access keys, if programmatic access is configured.
- Permissions through attached or associated IAM policies.

### 3.3 IAM role

An IAM role is an identity with permissions that can be assumed by a trusted principal.

A role provides temporary security credentials when it is assumed. Roles are commonly used by:

- EC2 applications
- Lambda functions
- ECS tasks
- Users accessing AWS through an identity provider
- AWS services that need permission to call other AWS services

Example: A Spring Boot application running on EC2 needs to read files from an S3 bucket. Instead of storing an access key in the application, attach an IAM role to the EC2 instance and grant the required S3 permissions to that role.

### 3.4 Comparison

| Feature | Root user | IAM user | IAM role |
|---|---|---|---|
| Scope | One AWS account's root identity | Identity in an AWS account | Assumable identity in an AWS account |
| Credentials | Account email and password; MFA can be enabled | Password and/or access keys, depending on configuration | Temporary credentials when assumed |
| Permissions | Full account access | Determined by applicable permissions and policies | Determined by role policies and trust relationship |
| Typical use | Account-level tasks that require root | Specific legacy or limited use cases | Workloads, federation, and temporary access |
| Everyday human access | Avoid | Prefer federation where possible | Commonly used through federation/SSO |

### 3.5 Example: Spring Boot on EC2 accessing S3

**Avoid this pattern:**

```text
Spring Boot application
       |
       v
Hard-coded AWS access key
       |
       v
Amazon S3
```

Hard-coded credentials can leak through source code, logs, container images, or configuration files.

**Prefer this pattern:**

```text
Spring Boot application on EC2
       |
       v
EC2 instance profile
       |
       v
IAM role with limited S3 permissions
       |
       v
Amazon S3 bucket
```

The application obtains temporary credentials through the AWS SDK's default credential provider chain. You do not need to put long-lived access keys in the application.

## 4. AWS Management Tools

There are several ways to manage AWS services.

### 4.1 AWS Management Console

The AWS Management Console is a web-based interface for managing AWS resources.

You can use it to:

- Launch an EC2 instance.
- Create an S3 bucket.
- Configure IAM policies.
- View RDS databases.
- Monitor CloudWatch metrics.
- Review billing and cost information.

Example workflow:

1. Sign in using an authorized identity.
2. Select the required AWS service.
3. Select the Region if the service is regional.
4. Create or inspect resources.
5. Review configuration and permissions.

**Best for:** Learning AWS, visual administration, and occasional manual tasks.

### 4.2 AWS Command Line Interface (AWS CLI)

AWS CLI is a command-line tool for interacting with AWS services.

Example:

```bash
aws sts get-caller-identity
```

This command displays the AWS account and identity associated with the active credentials.

Other examples:

```bash
aws s3 ls
```

Lists S3 buckets visible to the current identity.

```bash
aws ec2 describe-instances --region ap-southeast-1
```

Lists EC2 instance information in the specified Region, subject to permissions.

**Best for:** Automation, scripts, repeatable administration, and terminal workflows.

### 4.3 AWS SDK

An AWS SDK is a software development kit that allows application code to call AWS services.

AWS provides SDKs for languages such as:

- Java
- Python
- JavaScript / TypeScript
- .NET
- Go
- C++

For a Java Spring Boot application, you can use the AWS SDK for Java 2.x to interact with S3, SQS, DynamoDB, and other services.

**Best for:** Integrating AWS services into applications.

### 4.4 AWS CloudShell

AWS CloudShell is a browser-based shell available from the AWS Management Console in supported Regions.

It provides a managed command-line environment where you can run commands and AWS CLI operations without installing the CLI on your own computer.

Typical uses:

- Run AWS CLI commands.
- Inspect resources.
- Execute small scripts.
- Work with files in the CloudShell environment.

CloudShell has its own environment and storage behavior. Do not assume files or configuration are shared with your local computer.

**Best for:** Quick command-line tasks from a browser.

## 5. Management Tool Comparison

| Tool | Interface | Main purpose | Example |
|---|---|---|---|
| AWS Management Console | Web browser | Visual resource management | Create an S3 bucket |
| AWS CLI | Terminal | Commands and automation | List EC2 instances |
| AWS SDK | Application code | Integrate AWS services into software | Spring Boot uploads a file to S3 |
| AWS CloudShell | Browser-based terminal | Run commands without local CLI installation | Inspect IAM or S3 resources |

### Which tool should you use?

- Use the **Console** when learning a service or reviewing settings visually.
- Use the **CLI** when you need repeatable commands or scripts.
- Use the **SDK** when an application needs to call AWS services.
- Use **CloudShell** when you need a quick browser-based command-line environment.

These tools complement one another. A professional workflow often uses more than one.

## 6. Installing and Configuring AWS CLI

You can install AWS CLI on Windows, macOS, or Linux. Follow the current AWS CLI installation documentation for your operating system.

After installation, verify it:

```bash
aws --version
```

Example output:

```text
aws-cli/2.x.x Python/3.x.x ...
```

The exact version and output will differ.

### 6.1 Configure a default profile

The interactive configuration command is:

```bash
aws configure
```

It asks for:

- AWS Access Key ID
- AWS Secret Access Key
- Default Region name
- Default output format

For example, the default Region might be:

```text
ap-southeast-1
```

**Security note:** `aws configure` stores credentials in your local AWS CLI credentials file for that profile. Do not use this approach with long-lived credentials if your organization provides a safer option such as IAM Identity Center, role assumption, or another temporary credential provider.

### 6.2 Configuration files

On Windows, AWS CLI configuration files are normally located under:

```text
%UserProfile%\.aws\
```

On Linux and macOS:

```text
~/.aws/
```

Common files:

- `config` — profile settings such as Region and output format.
- `credentials` — access keys for profiles that use stored access keys.

Example configuration file:

```ini
[default]
region = ap-southeast-1
output = json

[profile dev]
region = ap-southeast-1
output = json

[profile prod]
region = ap-southeast-2
output = json
```

This example shows profile configuration only. It does not contain credentials.

### 6.3 Named profiles

Named profiles allow you to use different AWS configurations.

List configured profiles:

```bash
aws configure list-profiles
```

Run a command using the `dev` profile:

```bash
aws sts get-caller-identity --profile dev
```

Run a command using the `prod` profile:

```bash
aws sts get-caller-identity --profile prod
```

Set the default profile for the current terminal session.

Linux/macOS:

```bash
export AWS_PROFILE=dev
```

Windows PowerShell:

```powershell
$env:AWS_PROFILE = "dev"
```

To return to the default profile, unset or change the environment variable for your shell session.

**Important:** A profile name is not a security boundary by itself. Verify the account and identity before running commands that create, modify, or delete resources.

### 7.7 Understand permissions errors

You may see an error such as:

```text
An error occurred (AccessDenied) when calling the ListBuckets operation:
Access Denied
```

This generally means the active identity does not have permission for the requested operation, or an applicable policy or organizational control denies it.

A useful debugging sequence:

1. Run `aws sts get-caller-identity`.
2. Confirm the expected account and identity.
3. Confirm the selected profile and Region.
4. Check whether the identity has the required IAM permissions.
5. Check whether a permissions boundary, service control policy, resource policy, or other control affects the request.

Do not solve every `AccessDenied` error by granting administrator permissions. Identify the missing action and resource, then grant only the required access.

## 8. AWS SDK for Java 2.x — Spring Boot Example

This section shows how a Java application can use the AWS SDK to interact with Amazon S3.

### 8.1 Add the Maven dependency

For a project using Maven, add the S3 module. Use a consistent, current AWS SDK for Java 2.x version and preferably manage versions with the AWS SDK BOM.

Example:

```xml
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>software.amazon.awssdk</groupId>
            <artifactId>bom</artifactId>
            <version>2.XX.X</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<dependencies>
    <dependency>
        <groupId>software.amazon.awssdk</groupId>
        <artifactId>s3</artifactId>
    </dependency>
</dependencies>
```

Replace `2.XX.X` with a valid AWS SDK for Java 2.x release version. In a real project, keep the version aligned with your dependency-management policy.

### 8.2 Configure an S3 client

```java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import software.amazon.awssdk.regions.Region;
import software.amazon.awssdk.services.s3.S3Client;

@Configuration
public class AwsConfig {

    @Bean
    public S3Client s3Client() {
        return S3Client.builder()
                .region(Region.AP_SOUTHEAST_1)
                .build();
    }
}
```

The SDK uses its default credential provider chain. For example, it can obtain credentials from an EC2 instance role when the application runs on an appropriately configured EC2 instance.

Do not place access keys directly in this Java class.

### 8.3 Create a service to list objects

```java
import org.springframework.stereotype.Service;
import software.amazon.awssdk.services.s3.S3Client;
import software.amazon.awssdk.services.s3.model.ListObjectsV2Request;
import software.amazon.awssdk.services.s3.model.ListObjectsV2Response;

@Service
public class S3Service {

    private final S3Client s3Client;

    public S3Service(S3Client s3Client) {
        this.s3Client = s3Client;
    }

    public void listObjects(String bucketName) {
        ListObjectsV2Request request = ListObjectsV2Request.builder()
                .bucket(bucketName)
                .maxKeys(20)
                .build();

        ListObjectsV2Response response =
                s3Client.listObjectsV2(request);

        response.contents().forEach(object ->
                System.out.println(object.key())
        );
    }
}
```

This example lists up to 20 objects in a bucket. Production code should handle pagination, exceptions, logging, and application-level error handling.

### 8.4 Permission required

The application's IAM role needs an appropriate permission, such as `s3:ListBucket` on the specific bucket.

A narrowly scoped policy could look like this:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::example-app-bucket"
    }
  ]
}
```

Replace `example-app-bucket` with your bucket name. This policy only grants bucket-listing permission; it does not grant permission to read or upload objects.

### 8.5 Request flow

```text
Spring Boot application
        |
        v
AWS SDK for Java 2.x
        |
        v
Default credentials provider chain
        |
        v
EC2 instance role credentials
        |
        v
Amazon S3 API
        |
        v
S3 bucket
```

The application calls the SDK. The SDK obtains credentials from the configured provider chain, signs the request, and calls the S3 API. IAM evaluates whether the role is allowed to perform the requested action.

## 9. Account Security Best Practices

Use these practices when setting up or managing an AWS account.

### 9.1 Protect the root user

- Enable MFA for the root user.
- Use a strong, unique password.
- Do not use root credentials for normal work.
- Avoid creating root access keys.
- Protect the email account associated with the AWS account.

### 9.2 Prefer temporary credentials

- Use IAM roles for AWS workloads.
- Use federation or IAM Identity Center for human access where appropriate.
- Avoid long-lived access keys when temporary credentials are available.
- Rotate and remove credentials that are no longer needed.

### 9.3 Apply least privilege

Give each identity only the permissions needed for its job.

For example:

- A reporting role may only need read access to selected resources.
- An application role may only need to read and write objects in one specific S3 bucket.
- A deployment role may need permissions for a defined deployment workflow, not unrestricted access to the entire account.

### 9.4 Monitor account activity

AWS CloudTrail records account activity and API events. Organizations commonly use CloudTrail with monitoring and alerting to investigate changes and suspicious activity.

### 9.5 Monitor costs

Use AWS billing and cost-management tools to review spending. For learning environments:

- Set a budget and configure alerts.
- Stop or delete resources when they are no longer needed.
- Review storage, snapshots, public IPs, and other resources that may continue to incur charges.
- Understand that free-tier eligibility and limits vary by account, service, and time.

### 9.6 Avoid accidental production changes

- Separate development and production accounts where appropriate.
- Use named profiles carefully.
- Check `aws sts get-caller-identity` before important operations.
- Use infrastructure as code and code review for repeatable changes.
- Apply approval processes to sensitive production changes.

## 13. AWS Interview Questions and Answers

### Q1. What is an AWS account?

**Answer:** An AWS account is a boundary for AWS resources, identities, permissions, and billing. It can contain services such as EC2, S3, RDS, and VPC.

### Q2. What is the AWS root user?

**Answer:** The root user is the original identity created when an AWS account is established. It has unrestricted access to the account and should be protected with MFA and used only when required.

### Q3. What is the difference between an IAM user and an IAM role?

**Answer:** An IAM user is an identity that can have credentials associated with it. An IAM role is an assumable identity that provides temporary credentials to a trusted principal.

### Q4. Why should an application use an IAM role instead of hard-coded access keys?

**Answer:** An IAM role can provide temporary credentials and avoids storing long-lived access keys in source code or application configuration. It also supports least-privilege permissions.

### Q5. What is AWS Management Console?

**Answer:** It is a browser-based interface for creating, configuring, and monitoring AWS resources.

### Q6. What is AWS CLI?

**Answer:** AWS CLI is a command-line tool that allows users to interact with AWS services through commands and scripts.

### Q7. What is AWS SDK?

**Answer:** AWS SDKs are libraries for programming languages that allow applications to call AWS service APIs. For example, the AWS SDK for Java can be used by a Spring Boot application to access S3.

### Q8. What is AWS CloudShell?

**Answer:** CloudShell is a browser-based shell available from the AWS Management Console. It provides a convenient environment for running AWS CLI commands.

### Q9. What is the principle of least privilege?

**Answer:** It means giving an identity only the permissions required to perform its tasks, rather than granting broad access by default.

### Q10. How do you check which AWS identity is being used by the CLI?

**Answer:**

```bash
aws sts get-caller-identity
```

This returns the account and identity information associated with the active credentials.

## 14. Lesson Summary

- An **AWS account** contains resources, identities, permissions, and billing information.
- The **root user** is highly privileged and should be protected and used only when necessary.
- An **IAM user** is an identity with configured credentials and permissions.
- An **IAM role** is an assumable identity that commonly provides temporary credentials.
- The **Management Console** provides a visual web interface.
- The **AWS CLI** provides terminal-based access and automation.
- The **AWS SDK** lets application code call AWS services.
- **CloudShell** provides a browser-based command-line environment.
- Use **least privilege**, MFA, and temporary credentials wherever appropriate.
