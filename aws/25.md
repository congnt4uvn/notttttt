## 2. What Is Amazon S3?

**Amazon Simple Storage Service (Amazon S3)** is an object storage service. It stores data as objects inside buckets.

Common use cases include:

- Images and videos.
- Application uploads and downloads.
- Documents and backups.
- Log archives.
- Data lakes and analytics files.
- Static website assets.
- Software packages and build artifacts.

### 2.1 Object storage

Object storage is different from a traditional block device or a file system.

```text
Amazon S3
   |
   +-- Bucket: my-company-files
          |
          +-- Object: images/logo.png
          |
          +-- Object: documents/invoice-001.pdf
          |
          +-- Object: backups/database-2026-11-04.sql
```

Each object consists conceptually of:

- **Key:** The object's name within the bucket.
- **Data:** The stored content.
- **Metadata:** Information describing the object, such as content type and user-defined metadata.
- **Version ID:** A version identifier when versioning is enabled.

S3 is designed for object storage. It is not a conventional mounted file system, although tools and services can provide file-system-like access patterns.

### 2.2 Bucket

A bucket is a container for objects.

Example:

```text
Bucket: company-production-assets

Objects:
  images/logo.png
  images/banner.jpg
  documents/manual.pdf
  exports/report.csv
```

Bucket names are globally unique within the S3 partition namespace and must follow S3 bucket naming rules. Choose names that do not expose sensitive internal information.

### 2.3 Object key and prefix

An object key identifies an object inside a bucket.

Example key:

```text
customers/1001/profile/avatar.png
```

The prefix is:

```text
customers/1001/profile/
```

The object name is the complete key. S3 uses a flat object namespace rather than real directories. The console presents prefixes as folders to make browsing easier.

### 2.4 Region

A bucket is created in a chosen AWS Region. Consider:

- User and application latency.
- Data residency and regulatory requirements.
- Where the application runs.
- Replication and disaster recovery needs.
- Cross-region transfer and storage costs.

S3 bucket names are globally unique within the relevant partition, but bucket data is associated with the Region in which the bucket is created.

## 3. S3 Durability and Availability

Two important terms:

- **Durability:** The likelihood that data remains intact over time.
- **Availability:** The proportion of time a service or object is accessible.

S3 Standard is designed for 99.999999999% (11 nines) of object durability and 99.99% availability over a year. These are design targets, not a promise that every individual application request will always succeed.

S3 Standard stores data redundantly across multiple Availability Zones in a Region.

### Important distinction

| Concept | Meaning |
|---|---|
| Durability | Protects against data loss |
| Availability | Measures accessibility |
| Backup | A recoverable copy or recovery strategy |
| Replication | Copies objects to another bucket or location |
| Versioning | Retains multiple versions of an object |

High durability does not replace a backup strategy. Accidental deletion, malicious changes, incorrect lifecycle policies, and compromised credentials can still affect data.

## 4. S3 Storage Classes

S3 offers storage classes for different access patterns and cost requirements.

| Storage class | Typical use case | Key consideration |
|---|---|---|
| S3 Standard | Frequently accessed data | General-purpose storage |
| S3 Intelligent-Tiering | Unknown or changing access patterns | Automatically moves eligible data between access tiers |
| S3 Standard-IA | Infrequently accessed data needing rapid access | Retrieval charges and minimum storage duration apply |
| S3 One Zone-IA | Infrequent data that can be recreated | Stored in one AZ; lower resilience to AZ loss |
| S3 Glacier Instant Retrieval | Archive data needing millisecond retrieval | Retrieval charges and minimum storage duration apply |
| S3 Glacier Flexible Retrieval | Archive data with minutes-to-hours retrieval options | Retrieval time depends on retrieval option |
| S3 Glacier Deep Archive | Long-term archive with rarely needed data | Long retrieval times and minimum storage duration |

Storage-class pricing and feature details can change. Check the current AWS pricing page and service documentation before selecting a class for production.

### 4.1 Choosing a storage class

Ask these questions:

1. How often will the object be accessed?
2. How quickly must it be retrieved?
3. Can the application tolerate a retrieval delay?
4. How long will the object remain stored?
5. What are the retrieval and transition costs?
6. Is multi-AZ resilience required?

Example:

| Data | Possible choice | Reason |
|---|---|---|
| Product images | Standard | Frequently accessed |
| Older reports | Standard-IA | Less frequent access |
| Unknown access pattern | Intelligent-Tiering | Access frequency may change |
| Long-term compliance archive | Glacier Deep Archive | Rarely retrieved |

Do not move every old object automatically to the cheapest class. Retrieval fees, minimum storage durations, and operational requirements matter.

## 5. Create an S3 Bucket

You can create a bucket through the AWS Console or AWS CLI.

### 5.1 AWS CLI configuration

Check your CLI identity:

```bash
aws sts get-caller-identity
```

Check the configured default Region:

```bash
aws configure get region
```

For this roadmap, examples use:

```text
ap-southeast-1
```

### 5.2 Create a bucket

Bucket creation syntax differs for `us-east-1` and other Regions. For a Region such as `ap-southeast-1`, specify the location constraint:

```bash
aws s3api create-bucket \
  --bucket my-unique-training-bucket-2026-example \
  --region ap-southeast-1 \
  --create-bucket-configuration LocationConstraint=ap-southeast-1
```

Replace the example bucket name with a globally unique name that follows S3 naming rules.

For `us-east-1`, the create-bucket request uses different location-constraint handling. Do not blindly reuse the command above in that Region.

### 5.3 List buckets

```bash
aws s3 ls
```

Or:

```bash
aws s3api list-buckets
```

### 5.4 Inspect a bucket's Region

```bash
aws s3api get-bucket-location \
  --bucket my-unique-training-bucket-2026-example
```

A `null` location result is historically used for `us-east-1`.

## 6. Upload, Download, and Manage Objects

The AWS CLI provides high-level S3 commands and lower-level S3 API commands.

### 6.1 Upload one file

```bash
aws s3 cp ./report.pdf \
  s3://my-unique-training-bucket-2026-example/reports/report.pdf
```

### 6.2 Download one object

```bash
aws s3 cp \
  s3://my-unique-training-bucket-2026-example/reports/report.pdf \
  ./report-downloaded.pdf
```

### 6.3 List objects

```bash
aws s3 ls \
  s3://my-unique-training-bucket-2026-example/ \
  --recursive
```

### 6.4 Copy an object

```bash
aws s3 cp \
  s3://my-unique-training-bucket-2026-example/reports/report.pdf \
  s3://my-unique-training-bucket-2026-example/archive/report.pdf
```

### 6.5 Move an object

```bash
aws s3 mv \
  s3://my-unique-training-bucket-2026-example/reports/old-report.pdf \
  s3://my-unique-training-bucket-2026-example/archive/old-report.pdf
```

A move is generally implemented as a copy followed by a delete. Confirm the destination before using it for important data.

### 6.6 Delete one object

```bash
aws s3 rm \
  s3://my-unique-training-bucket-2026-example/reports/test-file.txt
```

Deletion can be permanent when versioning is disabled. When versioning is enabled, a normal delete generally creates a delete marker rather than immediately removing prior versions.

### 6.7 Sync a directory

```bash
aws s3 sync ./uploads \
  s3://my-unique-training-bucket-2026-example/uploads/
```

Sync compares source and destination and transfers files as needed. Review the command carefully before using `--delete`, because that option can remove destination objects that are absent from the source.

## 7. S3 Versioning

Versioning preserves multiple variants of an object in the same bucket.

Example:

```text
Bucket: company-documents

Key: policies/security.pdf
   |
   +-- Version A: original document
   |
   +-- Version B: corrected document
   |
   +-- Version C: latest document
```

### 7.1 Enable versioning

```bash
aws s3api put-bucket-versioning \
  --bucket my-unique-training-bucket-2026-example \
  --versioning-configuration Status=Enabled
```

Inspect versioning:

```bash
aws s3api get-bucket-versioning \
  --bucket my-unique-training-bucket-2026-example
```

### 7.2 List object versions

```bash
aws s3api list-object-versions \
  --bucket my-unique-training-bucket-2026-example \
  --prefix reports/
```

### 7.3 Delete behavior

With versioning enabled, a normal delete usually adds a delete marker. Earlier versions can remain stored and may be recoverable by specifying a version ID.

Versioning is useful for recovery from accidental overwrites and deletes, but it can increase storage cost because old versions remain until explicitly removed or expired by lifecycle configuration.

For stronger protection against malicious or accidental deletion, evaluate S3 Object Lock and appropriate account-level security controls. Object Lock has specific configuration requirements and should be planned before production data is stored.

## 8. S3 Security Fundamentals

S3 security is a core part of application architecture.

### 8.1 Block Public Access

S3 Block Public Access settings help prevent public exposure.

They can be applied at the account level and bucket level. Account-level settings can override attempts to make buckets or objects public.

For most application buckets, keep Block Public Access enabled unless there is a reviewed and intentional public-access requirement.

### 8.2 IAM policies

IAM policies grant AWS identities permission to perform actions.

Example policy allowing an application role to list one bucket and read/write objects under one prefix:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ListApplicationPrefix",
      "Effect": "Allow",
      "Action": [
        "s3:ListBucket"
      ],
      "Resource": "arn:aws:s3:::my-unique-training-bucket-2026-example",
      "Condition": {
        "StringLike": {
          "s3:prefix": [
            "app-uploads",
            "app-uploads/*"
          ]
        }
      }
    },
    {
      "Sid": "ReadWriteApplicationObjects",
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:PutObject"
      ],
      "Resource": "arn:aws:s3:::my-unique-training-bucket-2026-example/app-uploads/*"
    }
  ]
}
```

This is an example of least-privilege access. Add delete permissions only if the application genuinely needs them. Review any additional requirements such as multipart uploads, encryption keys, tags, or object ownership.

### 8.3 Bucket policies

A bucket policy is a resource-based policy attached to a bucket.

It can grant or restrict access based on principals, actions, resources, and conditions.

Example: require TLS for requests to the bucket.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyInsecureTransport",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:*",
      "Resource": [
        "arn:aws:s3:::my-unique-training-bucket-2026-example",
        "arn:aws:s3:::my-unique-training-bucket-2026-example/*"
      ],
      "Condition": {
        "Bool": {
          "aws:SecureTransport": "false"
        }
      }
    }
  ]
}
```

Test policies carefully. An explicit Deny can override an Allow and can block legitimate access if written incorrectly.

### 8.4 Encryption

S3 supports encryption at rest.

Common options include:

- SSE-S3: S3-managed encryption keys.
- SSE-KMS: AWS Key Management Service keys.
- DSSE-KMS: Dual-layer server-side encryption with AWS KMS.

For many buckets, default encryption is enabled automatically with SSE-S3 unless configured otherwise. Choose SSE-KMS when key-management controls, auditability, or policy requirements call for it.

Encryption in transit should use HTTPS/TLS.

### 8.5 Do not make application buckets public by default

A common secure pattern:

```text
User
 |
 v
Spring Boot API
 |
 | IAM role permissions
 v
Private S3 bucket
```

The application authorizes the user and accesses S3 using its IAM role. The user does not need broad bucket permissions.

For direct browser uploads, a backend can issue a short-lived presigned URL after authorization. Presigned URLs are covered in a later lesson.

## 9. S3 Lifecycle Management

Lifecycle rules automate object transitions and expiration.

Examples:

- Transition older objects to a lower-cost storage class.
- Expire temporary files after a retention period.
- Remove noncurrent object versions after a defined period.
- Clean up incomplete multipart uploads.

Conceptual lifecycle:

```text
New object
   |
   | After 30 days
   v
Transition to a suitable infrequent-access class
   |
   | After 180 days
   v
Transition to an archive class
   |
   | After retention period
   v
Expire object, if policy permits
```

Do not copy this timeline into production without checking legal retention rules, retrieval requirements, storage-class minimum durations, and lifecycle pricing.

Lifecycle rules can apply to:
- Current object versions.
- Noncurrent versions.
- Objects with selected prefixes or tags.
- Incomplete multipart uploads.

Versioned buckets need special attention: expiring the current version and expiring noncurrent versions are different actions.

## 10. S3 and Static Website Hosting

S3 can host static website content such as:

- HTML.
- CSS.
- JavaScript.
- Images.
- Downloadable public assets.

A static website bucket does not execute server-side code such as Java or Spring Boot.

For a production website, a common architecture is:

```text
Browser
   |
   v
Amazon CloudFront
   |
   v
Private S3 origin
```

CloudFront can serve content globally and use Origin Access Control (OAC) to access a private S3 bucket. This is generally preferable to exposing the bucket publicly.

S3 website endpoints and S3 REST endpoints have different behavior. HTTPS and custom-domain architecture should be planned appropriately, commonly using CloudFront and ACM.

## 11. Spring Boot Integration with S3

A Spring Boot application can use the AWS SDK for Java 2.x to upload and download objects.

### 11.1 Architecture

```text
Browser / Mobile Client
          |
          v
    Spring Boot API
          |
          | IAM role
          v
      Amazon S3
          |
          v
   Private object bucket
```

The backend should validate authorization, file size, file type, and business rules before accepting uploads.

### 11.2 Maven dependency

Add the AWS SDK S3 dependency. Use a consistent AWS SDK version, ideally managed through the AWS SDK BOM.

```xml
<dependency>
    <groupId>software.amazon.awssdk</groupId>
    <artifactId>s3</artifactId>
</dependency>
```

Example BOM configuration:

```xml
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>software.amazon.awssdk</groupId>
            <artifactId>bom</artifactId>
            <version>2.XX.X</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>
```

Replace `2.XX.X` with a current compatible AWS SDK v2 release. Do not use a made-up version.

### 11.3 Application configuration

`application.yml`:

```yaml
app:
  aws:
    region: ap-southeast-1
    s3:
      bucket: my-unique-training-bucket-2026-example
```

Do not put AWS access keys in this file.

### 11.4 S3 client configuration

```java
package com.example.storage.config;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import software.amazon.awssdk.regions.Region;
import software.amazon.awssdk.services.s3.S3Client;

@Configuration
public class S3Config {

    @Bean
    public S3Client s3Client(
            @Value("${app.aws.region}") String region) {

        return S3Client.builder()
                .region(Region.of(region))
                .build();
    }
}
```

The AWS SDK default credentials provider chain can obtain credentials from an EC2 instance profile, ECS task role, environment, or other supported sources. In production, prefer an IAM role attached to the compute environment.

### 11.5 S3 service

This example uploads a byte array. For large files, use streaming or multipart upload patterns to avoid loading the entire file into application memory.

```java
package com.example.storage.service;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Service;
import software.amazon.awssdk.core.sync.RequestBody;
import software.amazon.awssdk.services.s3.S3Client;
import software.amazon.awssdk.services.s3.model.PutObjectRequest;

@Service
public class S3StorageService {

    private final S3Client s3Client;
    private final String bucket;

    public S3StorageService(
            S3Client s3Client,
            @Value("${app.aws.s3.bucket}") String bucket) {
        this.s3Client = s3Client;
        this.bucket = bucket;
    }

    public void upload(
            String objectKey,
            byte[] content,
            String contentType) {

        PutObjectRequest request = PutObjectRequest.builder()
                .bucket(bucket)
                .key(objectKey)
                .contentType(contentType)
                .build();

        s3Client.putObject(
                request,
                RequestBody.fromBytes(content)
        );
    }
}
```

### 11.6 Controller example

This simple example is for learning. A production endpoint should enforce authentication, authorization, maximum file size, allowed content types, malware scanning where appropriate, and safe object-key generation.

```java
package com.example.storage.controller;

import com.example.storage.service.S3StorageService;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;
import org.springframework.web.multipart.MultipartFile;

import java.io.IOException;
import java.util.UUID;

@RestController
@RequestMapping("/api/files")
public class FileController {

    private final S3StorageService storageService;

    public FileController(S3StorageService storageService) {
        this.storageService = storageService;
    }

    @PostMapping("/upload")
    public ResponseEntity<String> upload(
            @RequestParam("file") MultipartFile file)
            throws IOException {

        if (file.isEmpty()) {
            return ResponseEntity.badRequest()
                    .body("File is empty");
        }

        String originalName = file.getOriginalFilename() == null
                ? "upload"
                : file.getOriginalFilename();

        String safeName = originalName.replaceAll(
                "[^a-zA-Z0-9._-]", "_");

        String objectKey = "app-uploads/"
                + UUID.randomUUID()
                + "-"
                + safeName;

        String contentType = file.getContentType() == null
                ? "application/octet-stream"
                : file.getContentType();

        storageService.upload(
                objectKey,
                file.getBytes(),
                contentType
        );

        return ResponseEntity.ok(objectKey);
    }
}
```

For production, avoid trusting the client's content type as proof of file type. Validate file signatures and business rules. Do not expose arbitrary object keys without authorization checks.

### 11.7 Download design

A backend can download an object through `GetObject` and stream it to the client. For large files, avoid buffering the full object in memory. Another common design is to authorize the request and return a short-lived presigned URL so the browser downloads directly from S3.

The next S3 lesson will cover advanced object operations, presigned URLs, multipart upload, and stronger security patterns.

## 13. Hands-on Lab — Build a Private S3 File Store

### Goal

Create a private S3 bucket and use it to store application documents.

### Step 1 — Create a bucket

Use a globally unique name and choose `ap-southeast-1` for this lab.

```bash
aws s3api create-bucket \
  --bucket YOUR-UNIQUE-BUCKET-NAME \
  --region ap-southeast-1 \
  --create-bucket-configuration LocationConstraint=ap-southeast-1
```

### Step 2 — Keep public access blocked

Keep S3 Block Public Access enabled at account and bucket levels unless the lab has a reviewed reason to change it.

### Step 3 — Enable versioning

```bash
aws s3api put-bucket-versioning \
  --bucket YOUR-UNIQUE-BUCKET-NAME \
  --versioning-configuration Status=Enabled
```

### Step 4 — Upload a test file

```bash
echo "Hello from Amazon S3" > hello.txt

aws s3 cp hello.txt \
  s3://YOUR-UNIQUE-BUCKET-NAME/lab/hello.txt
```

### Step 5 — List and download

```bash
aws s3 ls s3://YOUR-UNIQUE-BUCKET-NAME/lab/

aws s3 cp \
  s3://YOUR-UNIQUE-BUCKET-NAME/lab/hello.txt \
  downloaded-hello.txt
```

### Step 6 — Test versioning

Change the local file:

```bash
echo "Updated content" > hello.txt

aws s3 cp hello.txt \
  s3://YOUR-UNIQUE-BUCKET-NAME/lab/hello.txt
```

List versions:

```bash
aws s3api list-object-versions \
  --bucket YOUR-UNIQUE-BUCKET-NAME \
  --prefix lab/hello.txt
```

You should see multiple versions for the same key.

### Step 7 — Create a least-privilege application role

Create or select an IAM role for your compute service. Grant only the required S3 actions for the application prefix. Avoid access keys embedded in source code.

### Step 8 — Connect Spring Boot

1. Add AWS SDK for Java 2.x.
2. Configure the bucket and Region.
3. Use `S3Client`.
4. Attach the IAM role to the compute environment.
5. Test an upload with a small file.
6. Verify that the object appears in the bucket.

### Step 9 — Review cost and clean up

S3 can incur charges for storage, requests, retrieval, data transfer, and certain management features. Versioned objects also consume storage.

After testing, delete lab objects and versions as appropriate, then remove the bucket if it is no longer needed. A versioned bucket must have its object versions and delete markers removed before it can be deleted.

Do not run cleanup commands against a bucket containing real data.

## 14. Troubleshooting

| Problem | Possible cause | What to check |
|---|---|---|
| AccessDenied | IAM or bucket policy denies access | Caller identity, identity policy, bucket policy, SCP, endpoint policy |
| NoSuchBucket | Wrong bucket name or partition | Bucket name and account |
| NoSuchKey | Wrong object key | Exact key, capitalization, prefix |
| Region redirect or endpoint error | Wrong Region configured | Bucket Region and SDK Region |
| Upload fails for large files | Timeout or memory pressure | Streaming or multipart upload design |
| Browser cannot read object | CORS or authorization configuration | CORS rules and access model |
| Object is unexpectedly public | Public policy or ACL-related configuration | Block Public Access, bucket policy, ownership settings |
| Old versions consume storage | Versioning retains historical objects | Lifecycle rules for noncurrent versions |
| Spring Boot cannot access S3 | Missing role or permissions | Instance/task role and SDK credential provider |

### Debugging checklist

1. Identify the AWS principal using `aws sts get-caller-identity`.
2. Confirm the bucket name and Region.
3. Confirm the exact object key.
4. Check IAM identity policies.
5. Check bucket policies and explicit Deny statements.
6. Check organization-level and VPC endpoint policies if relevant.
7. Check encryption and KMS permissions when using SSE-KMS.
8. Review CloudTrail data events if configured and needed for object-level auditing.

## 15. Exercises with Answers

### Exercise 1 — Object storage

What are the main components of an S3 object?

**Answer:** Object data, key, metadata, and a version ID when versioning is enabled.

### Exercise 2 — Bucket and key

Given:

```text
s3://company-files/customers/1001/avatar.png
```

What is the bucket name and what is the object key?

**Answer:**
- Bucket: `company-files`
- Key: `customers/1001/avatar.png`

### Exercise 3 — Prefix

What is the prefix in this key?

```text
reports/2026/november/report.csv
```

**Answer:** `reports/2026/november/` is a useful prefix. S3 does not require this prefix to represent a real directory.

### Exercise 4 — Durability and availability

What is the difference between durability and availability?

**Answer:** Durability concerns whether data remains intact. Availability concerns whether the service or object can be accessed.

### Exercise 5 — Storage classes

A document is rarely accessed but must be retrieved quickly when requested. Which class could be considered?

**Answer:** S3 Standard-IA or S3 Glacier Instant Retrieval may be candidates, depending on access frequency, retrieval requirements, minimum storage duration, and cost.

### Exercise 6 — Versioning

What happens when you upload a new object using a key that already exists in a versioned bucket?

**Answer:** S3 stores a new version under that key. Earlier versions remain available unless removed by an authorized action or lifecycle rule.

### Exercise 7 — Public access

Should a private application upload bucket normally allow public access?

**Answer:** No. Keep Block Public Access enabled and let the application access objects through a least-privilege IAM role.

### Exercise 8 — IAM role

Why should an EC2 application use an instance profile rather than hard-coded AWS access keys?

**Answer:** The instance profile provides temporary credentials through the AWS role mechanism and avoids embedding long-lived credentials in source code or configuration.

### Exercise 9 — Lifecycle

Why should you configure lifecycle rules carefully for a versioned bucket?

**Answer:** Current and noncurrent versions have different lifecycle behavior. Old versions can continue consuming storage even after a newer version is uploaded or a delete marker is created.

### Exercise 10 — Spring Boot

Why should a Spring Boot upload endpoint generate its own object key rather than blindly use the original filename?

**Answer:** Client filenames may collide or contain unsafe characters. A server-generated unique key reduces collisions and helps prevent path-like naming problems.

## 18. AWS Interview Questions and Answers

### 1. What is Amazon S3?

**Answer:** Amazon S3 is a scalable object storage service used to store and retrieve data such as documents, media, backups, and application files.

### 2. What is the difference between a bucket and an object?

**Answer:** A bucket is a container. An object is the stored data, identified by its key, with associated metadata and content.

### 3. Does S3 have real folders?

**Answer:** S3 uses a flat object namespace. Prefixes in object keys create a folder-like presentation in the console and tools.

### 4. What is the difference between durability and availability?

**Answer:** Durability measures protection against data loss; availability measures accessibility over time.

### 5. What is S3 Versioning?

**Answer:** Versioning stores multiple versions of an object under the same key, allowing recovery from some accidental overwrites and deletes.

### 6. What is the purpose of S3 Lifecycle?

**Answer:** Lifecycle rules automate object transitions between storage classes and expiration of objects or noncurrent versions.

### 7. What is the difference between SSE-S3 and SSE-KMS?

**Answer:** SSE-S3 uses S3-managed encryption keys. SSE-KMS uses AWS KMS keys and provides additional key-management and access-control capabilities.

### 8. How do you prevent public access to an S3 bucket?

**Answer:** Keep Block Public Access enabled, review bucket policies and access points, use least-privilege IAM policies, and monitor configuration changes.

### 9. What is a bucket policy?

**Answer:** A bucket policy is a resource-based IAM policy attached to an S3 bucket. It controls access to the bucket and its objects.

### 10. Why use an IAM role with S3?

**Answer:** An IAM role provides temporary credentials to an AWS workload and avoids storing long-lived access keys in the application.

### 11. Can S3 host a Spring Boot backend?

**Answer:** No. S3 can host static website content, but it does not execute server-side Java applications. A Spring Boot backend needs compute such as EC2, ECS, or Lambda where suitable.

### 12. What is the benefit of storing uploads in S3 instead of local EC2 storage?

**Answer:** S3 provides durable shared object storage independent of individual EC2 instance lifecycles. This is useful when an application runs on multiple instances or uses Auto Scaling.
