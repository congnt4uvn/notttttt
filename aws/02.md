# 1. Introduction to Cloud Deployment Models

## 1.1 What is a Cloud Deployment Model?

A Cloud Deployment Model describes how cloud infrastructure is organized, owned, managed, and made available to users.

In simple terms, it answers these questions:

- Who owns the infrastructure?
- Who manages the infrastructure?
- Where does the infrastructure run?
- Who can access the infrastructure?
- How are computing resources shared?
- How does the company control its data?

There are four major deployment models:

| Model         | Description                                                    |
| ------------- | -------------------------------------------------------------- |
| Public Cloud  | Cloud infrastructure provided to customers by a cloud provider |
| Private Cloud | Cloud infrastructure dedicated to one organization             |
| Hybrid Cloud  | Combination of private infrastructure and public cloud         |
| Multi-Cloud   | Using services from multiple cloud providers                   |

Important: Hybrid Cloud and Multi-Cloud are not the same.

- Hybrid Cloud combines different infrastructure environments, typically private infrastructure and public cloud.
- Multi-Cloud uses two or more cloud providers.

The four models represent different infrastructure strategies. A company can also combine Hybrid Cloud and Multi-Cloud in the same architecture.

# 2. Public Cloud

## 2.1 What is Public Cloud?

Public Cloud is a cloud computing model where a third-party cloud provider owns and operates the underlying infrastructure and provides computing resources to multiple customers over a network.

Customers rent resources instead of purchasing physical servers.

Popular Public Cloud providers include:

- Amazon Web Services (AWS)
- Microsoft Azure
- Google Cloud Platform (GCP)
- Oracle Cloud Infrastructure (OCI)

### Simple example

Imagine you are building an online shopping application.

You need:

- Application servers.
- Database.
- File storage.
- Networking.
- Security.
- Monitoring.

Instead of purchasing physical servers, you rent these resources from AWS.

AWS operates the physical infrastructure, while you configure and manage the cloud resources used by your application.

## 2.2 Public Cloud Architecture

```
                 PUBLIC CLOUD
                       |
                Cloud Provider
                       |
                 AWS Data Center
                       |
          +------------+------------+
          |            |            |
          v            v            v
       Customer A   Customer B   Customer C
          |            |            |
          v            v            v
         EC2          EC2          EC2
          |            |            |
          v            v            v
         RDS          S3           Lambda
```

This architecture illustrates multiple customers using the same cloud provider's infrastructure.

Important concept: Multi-tenancy

Multi-tenancy means multiple customers use shared underlying infrastructure while their resources and data are logically isolated.

For example:

- Company A creates EC2 instances.
- Company B creates EC2 instances.
- Company C creates RDS databases.

They use the same cloud provider but cannot access each other's resources unless permissions or configurations explicitly allow it.

AWS uses multiple isolation mechanisms to protect customer resources.

## 2.3 How does Public Cloud work?

Let's follow a typical workflow.

Step 1 — Create an AWS account

You register an account and access the AWS Management Console.

Step 2 — Provision resources

You create the required resources.

For example:

| Resource         | AWS Service |
| ---------------- | ----------- |
| Virtual server   | EC2         |
| Object storage   | S3          |
| Database         | RDS         |
| Private network  | VPC         |
| User permissions | IAM         |

Step 3 — Deploy applications

You deploy your Spring Boot application to EC2 or ECS.

Step 4 — Access through the Internet

Users access your application through a public endpoint or a suitable network connection.

Step 5 — Pay for usage

AWS charges according to the pricing model of each service.

## 2.4 Advantages of Public Cloud

| Advantage           | Explanation                                        |
| ------------------- | -------------------------------------------------- |
| Low upfront cost    | No need to purchase physical servers               |
| Scalability         | Increase or decrease computing resources           |
| Global availability | Access infrastructure in multiple Regions          |
| Fast provisioning   | Create resources in minutes                        |
| Managed services    | AWS manages many underlying infrastructure tasks   |
| Pay-as-you-go       | Pay based on resource usage or pricing commitments |
| Innovation          | Access AI, analytics and serverless services       |

## 2.5 Disadvantages of Public Cloud

| Disadvantage           | Explanation                                               |
| ---------------------- | --------------------------------------------------------- |
| Vendor dependency      | Applications may depend on provider-specific services     |
| Cost management        | Poor resource management can increase costs               |
| Less physical control  | Customers do not own the provider's data center hardware  |
| Internet dependency    | Public connectivity may be required for access            |
| Compliance complexity  | Some workloads require special data handling and controls |
| Security configuration | Incorrect permissions can expose resources                |

Remember: Public Cloud does not mean that all data is public.

For example, an S3 bucket can be private, encrypted, and accessible only to authorized identities.

# 3. Private Cloud

## 3.1 What is Private Cloud?

Private Cloud is a cloud computing environment dedicated to a single organization.

Unlike Public Cloud, the infrastructure is not shared among unrelated organizations as a common cloud environment.

A Private Cloud can be hosted:

- In the organization's own data center.
- In a third-party data center.
- In a dedicated hosted environment.

The organization has more control over its infrastructure and environment.

### Simple example

Imagine a bank that operates sensitive financial applications.

The bank wants:

- Strict access controls.
- Dedicated infrastructure.
- Specific hardware configurations.
- Control over data location.
- Custom network policies.

The bank can build or operate a Private Cloud environment.

## 3.2 Private Cloud Architecture

```
                   BANK

        |           |           |
        +-----------+-----------+
                    |

             Internal Users
```

Only the organization's authorized users and systems can access this environment.

## 3.3 How does Private Cloud work?

A company establishes a dedicated cloud environment.

Typical components:

A. Physical Infrastructure

- Physical servers.
- Storage devices.
- Networking equipment.
- Firewalls.
- Data center facilities.

B. Virtualization Layer

Virtualization enables the organization to create multiple virtual machines on physical servers.

Common technologies include:

- VMware vSphere.
- Microsoft Hyper-V.
- KVM.
- OpenStack-based virtualization environments.

C. Cloud Management Platform

A management platform helps administrators:

- Provision virtual machines.
- Allocate computing resources.
- Manage storage.
- Configure networks.
- Monitor infrastructure.
- Manage user permissions.

D. Internal Applications

Applications run inside the private environment.

Examples:

- Banking applications.
- ERP systems.
- Internal enterprise applications.
- Sensitive databases.

| Customization           | Configure hardware, networking and software         |
| Data governance         | More direct control over data location and handling |

## 3.8 Is AWS a Private Cloud provider?

AWS is primarily known as a Public Cloud provider, but it also offers dedicated infrastructure and hybrid solutions.

Examples:

AWS Dedicated Hosts

Provides physical EC2 servers dedicated to a single customer.

AWS Outposts

Allows customers to run supported AWS infrastructure and services in their own facilities or specified on-premises locations.

Important distinction:

Dedicated AWS resources do not automatically mean that you have a full Private Cloud.

A Private Cloud involves a broader dedicated cloud environment, including its management, networking, provisioning and operational model.

# 4. Hybrid Cloud

## 4.1 What is Hybrid Cloud?

Hybrid Cloud is a cloud computing model that combines private infrastructure, such as an on-premises data center or Private Cloud, with Public Cloud resources.

These environments are connected so that applications and data can work across them.

### Simple example

Imagine a bank already has its own data center.

It stores sensitive banking information on its internal infrastructure.

However, the bank wants to use AWS for:

- Application development.
- Backup storage.
- Analytics.
- Disaster recovery.
- Additional computing capacity.

Instead of migrating everything to AWS, the bank connects its existing infrastructure to AWS.

This is a Hybrid Cloud architecture.

## 4.2 Hybrid Cloud Architecture

```
                 HYBRID CLOUD
                       |
              +--------+--------+
              |                 |
              v                 v
         PRIVATE CLOUD      PUBLIC CLOUD
              |                 |
              v                 v
        Company Data       AWS Infrastructure
              |                 |
              v                 v
         Internal App       EC2 / S3 / RDS
              |                 |
              +--------+--------+
                       |
                       v
                Secure Connection
```

The private environment and public cloud communicate through a secure network connection.

## 4.3 How does Hybrid Cloud work?

A Hybrid Cloud environment typically involves several components.

A. On-Premises Infrastructure

The company maintains existing infrastructure.

Example:

- Physical servers.
- Internal databases.
- Legacy applications.
- Internal networks.

B. Public Cloud Infrastructure

The company uses AWS resources.

Example:

- EC2.
- S3.
- RDS.
- Lambda.
- CloudWatch.

C. Network Connectivity

The private environment must communicate with AWS.

Common options:

| Technology           | Purpose                                            |
| -------------------- | -------------------------------------------------- |
| AWS Site-to-Site VPN | Establish encrypted connectivity over the Internet |
| AWS Direct Connect   | Dedicated network connection to AWS                |
| AWS Transit Gateway  | Connect multiple VPCs and networks                 |
| VPC Peering          | Connect two VPCs privately                         |

D. Identity and Security Integration

The company configures access control and security across both environments.

Examples:

- IAM.
- Active Directory integration.
- AWS IAM Identity Center.
- Encryption.
- Network firewalls.

The bank can keep selected systems on-premises while using AWS for additional workloads.

## 4.5 Advantages of Hybrid Cloud

| Advantage           | Explanation                                                 |
| ------------------- | ----------------------------------------------------------- |
| Flexibility         | Choose where each workload runs                             |
| Gradual migration   | Move applications to cloud step by step                     |
| Existing investment | Continue using existing infrastructure                      |
| Scalability         | Extend computing capacity using Public Cloud                |
| Data control        | Retain selected workloads in private environments           |
| Disaster recovery   | Use cloud resources for recovery strategies                 |
| Modernization       | Modernize applications without migrating everything at once |

## 4.6 Disadvantages of Hybrid Cloud

| Disadvantage          | Explanation                                                            |
| --------------------- | ---------------------------------------------------------------------- |

| Network dependency    | Requires reliable connectivity                                         |
| Security challenges   | Secure communication and identities across environments                |
| Cost management       | Manage costs in both environments                                      |
| Monitoring complexity | Need visibility across multiple systems                                |
| Integration           | Legacy and modern applications may require additional integration work |

# 5. Multi-Cloud

## 5.1 What is Multi-Cloud?

Multi-Cloud means using cloud services from two or more cloud providers.

For example, a company uses:

- AWS for application hosting.
- Microsoft Azure for identity integration or other workloads.
- Google Cloud for data analytics or machine learning.

The company distributes its workloads across different providers.

### Simple example

A global company wants to use different cloud providers for different purposes.

It decides:

| Requirement                                   | Cloud Provider |
| --------------------------------------------- | -------------- |
| Application hosting                           | AWS            |
| Enterprise identity and Microsoft integration | Azure          |
| Data analytics                                | Google Cloud   |

This is Multi-Cloud.

## 5.2 Multi-Cloud Architecture

```
                  COMPANY
                     |
                     v
             MULTI-CLOUD SYSTEM
                     |
          +----------+----------+
          |          |          |
          v          v          v
         AWS        Azure     Google Cloud
          |          |          |
          v          v          v
         EC2        VM       Compute Engine
          |          |          |
          v          v          v
         RDS      Azure SQL   BigQuery
```

Each cloud provider offers different services.

The company manages workloads across these environments.

## 5.3 How does Multi-Cloud work?

Step 1 — Select cloud providers

The company chooses two or more providers.

Step 2 — Distribute workloads

Each application or workload is deployed to a suitable provider.

Step 3 — Integrate services

The systems communicate through APIs, private connections, or other networking solutions.

Step 4 — Manage identity and security

The company implements security policies across all cloud environments.

Step 5 — Monitor and optimize

The company monitors performance, security and costs across providers.

## 5.4 Advantages of Multi-Cloud

| Advantage               | Explanation                                        |
| ----------------------- | -------------------------------------------------- |
| Provider flexibility    | Choose different providers for different workloads |
| Avoid overdependence    | Reduce reliance on a single provider               |
| Best-of-breed services  | Select services based on specific requirements     |
| Geographic options      | Access different infrastructure locations          |
| Negotiation flexibility | Potentially improve commercial flexibility         |
| Resilience options      | Design recovery across providers                   |

## 5.5 Disadvantages of Multi-Cloud

| Disadvantage        | Explanation                                     |
| ------------------- | ----------------------------------------------- |
| Complexity          | Multiple platforms to manage                    |
| Different APIs      | Services and interfaces differ                  |
| Skill requirements  | Engineers need knowledge of several platforms   |
| Security management | Policies must be coordinated                    |
| Cost management     | Different billing systems and pricing models    |
| Integration         | Applications may require additional integration |

# 6. Comparison of the Four Cloud Deployment Models

## 6.1 Main comparison

| Criteria            | Public Cloud                            | Private Cloud                      | Hybrid Cloud               | Multi-Cloud                      |
| ------------------- | --------------------------------------- | ---------------------------------- | -------------------------- | -------------------------------- |
| Infrastructure      | Provider-operated shared infrastructure | Dedicated to one organization      | Private + Public           | Multiple cloud providers         |
| Ownership           | Cloud provider                          | Organization or dedicated provider | Multiple parties           | Multiple providers               |
| Initial investment  | Usually low                             | Usually high                       | Varies                     | Varies                           |
| Scalability         | High                                    | Depends on capacity                | High                       | High                             |
| Control             | Cloud resource-level control            | Greater infrastructure control     | Mixed                      | Mixed                            |
| Complexity          | Usually lower                           | High                               | High                       | High                             |
| Maintenance         | Shared responsibility                   | Organization/provider              | Shared across environments | Across providers                 |
| Provider dependency | Possible                                | Depends on technology              | Possible                   | Reduced reliance on one provider |
| Example             | AWS                                     | Dedicated Private Cloud            | On-premises + AWS          | AWS + Azure                      |

## 6.2 Comparison by cost

| Model         | Cost characteristics                                |
| ------------- | --------------------------------------------------- |
| Public Cloud  | Usage-based and commitment-based costs              |
| Private Cloud | Hardware, infrastructure and maintenance investment |
| Hybrid Cloud  | Costs of both private and public infrastructure     |
| Multi-Cloud   | Costs distributed across multiple providers         |

## 6.3 Comparison by security and control

| Model         | Security and control characteristics                                                        |
| ------------- | ------------------------------------------------------------------------------------------- |
| Public Cloud  | Provider manages physical infrastructure; customer manages its configurations and workloads |
| Private Cloud | Greater direct control over dedicated infrastructure                                        |
| Hybrid Cloud  | Security must be coordinated across private and public environments                         |
| Multi-Cloud   | Security policies must be coordinated across providers                                      |

Remember: More control does not automatically mean better security.

## 6.4 Which model should a company choose?

| Company scenario                                 | Recommended model  | Reason                                       |
| ------------------------------------------------ | ------------------ | -------------------------------------------- |
| Startup launching a website                      | Public Cloud       | Fast provisioning and low upfront investment |
| Bank requiring dedicated infrastructure          | Private Cloud      | Dedicated infrastructure and control         |
| Enterprise with existing data center             | Hybrid Cloud       | Gradual migration and integration            |
| Global company using AWS and Azure               | Multi-Cloud        | Multiple cloud providers                     |
| Company with private data center and AWS + Azure | Hybrid Multi-Cloud | Combines both strategies                     |

# 8. Real-world Case Study — Choose the Right Deployment Model

Imagine four companies.

## Company A — Startup

Requirements:

- Limited budget.
- Launch a website quickly.
- 10,000 customers.
- Scale as the business grows.

Recommended: Public Cloud

Reason:

The company can rent AWS infrastructure and avoid large upfront hardware investments.

## Company B — Banking Organization

Requirements:

- Dedicated infrastructure.
- Specific operational controls.
- Sensitive customer information.
- Existing data center.

Possible choice: Private Cloud

Reason:

The bank may prefer dedicated infrastructure for particular workloads and operational requirements.

However, regulated banking workloads can also run on Public Cloud when appropriate compliance and security controls are in place.

## Company C — Traditional Enterprise

Requirements:

- Existing data center.
- Legacy applications.
- Modern applications.
- Gradual migration to AWS.

Recommended: Hybrid Cloud

Reason:

The company can retain existing systems while moving selected workloads to AWS.

## Company D — Global Technology Company

Requirements:

- AWS for application hosting.
- Azure for enterprise integration.
- Google Cloud for analytics.

Recommended: Multi-Cloud

Reason:

The company distributes workloads across multiple cloud providers.

## 10.2 Daily conversation — B1

Question 1: What is Public Cloud?

Answer:

Public Cloud is a cloud computing model where a cloud provider offers computing resources to multiple customers. AWS, Azure, and Google Cloud are examples of Public Cloud providers.

Question 2: What is Private Cloud?

Answer:

Private Cloud is a cloud environment dedicated to one organization. It provides greater control over infrastructure and configuration.

Question 3: What is Hybrid Cloud?

Answer:

Hybrid Cloud combines private infrastructure with Public Cloud services. Companies can keep some applications on-premises and deploy other applications on AWS.

Question 4: What is Multi-Cloud?

Answer:

Multi-Cloud means using services from multiple cloud providers. For example, a company can use AWS for application hosting and Azure for enterprise services.

Question 5: What is the difference between Hybrid Cloud and Multi-Cloud?

Answer:

Hybrid Cloud combines private infrastructure and Public Cloud. Multi-Cloud uses multiple cloud providers. A company can use both models at the same time.

## 10.3 Five-minute speaking practice

Topic: Explain Cloud Deployment Models

Use this sample paragraph:

"Today, I want to talk about Cloud Deployment Models.

There are four main deployment models: Public Cloud, Private Cloud, Hybrid Cloud, and Multi-Cloud.

First, Public Cloud is provided by companies like AWS, Microsoft Azure, and Google Cloud. Companies can rent computing resources instead of purchasing physical servers.

Second, Private Cloud is dedicated to one organization. It provides greater control over infrastructure and resources.

Third, Hybrid Cloud combines private infrastructure with Public Cloud. For example, a company can keep its database in its own data center and run its applications on AWS.

Finally, Multi-Cloud means using multiple cloud providers. A company can use AWS, Azure, and Google Cloud for different purposes.

Each deployment model has advantages and disadvantages. Companies should choose the right model based on their budget, security requirements, workload, and business goals."
