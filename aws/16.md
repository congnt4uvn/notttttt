## 2. What Is Amazon S3?

**Amazon Simple Storage Service (Amazon S3)** is an object storage service. It stores data as objects inside buckets.

Common use cases include:

- Images and documents uploaded by users.
- Application logs and backups.
- Static website assets.
- Data lakes and analytics files.
- Software packages and deployment artifacts.
- Media files such as audio and video.
- Data exchange between applications.

S3 is designed for high durability and scalable object storage. It is not a traditional block disk or a shared file system.

### Basic S3 architecture

```text
                Spring Boot Application
                          |
                          | AWS SDK
                          v
                    Amazon S3
                          |
                    S3 Bucket
                          |
             +------------+------------+
             |            |            |
             v            v            v
          image.jpg    report.pdf   backup.zip
           Object       Object        Object
```

### S3 vs EBS vs EFS

| Service | Storage model | Typical use |
|---|---|---|
| Amazon S3 | Object storage | Images, documents, backups, data lakes |
| Amazon EBS | Block storage | EC2 boot disk, database disk, persistent server storage |
| Amazon EFS | Managed network file system | Shared file system for multiple Linux workloads |

Choose the service based on how the application accesses data. S3 objects are accessed through APIs, not mounted as a normal block device.

## 3. Core S3 Concepts

### 3.1 Bucket

A **bucket** is a container for objects.

A bucket has:

- A globally unique bucket name within the AWS partition's bucket namespace.
- A Region.
- Ownership and access configuration.
- Encryption and versioning settings.
- Lifecycle and logging configurations, when enabled.

Bucket names must follow S3 naming rules. Choose names that are meaningful but do not include sensitive information.

Example:

```text
company-app-prod-files
company-app-dev-backups
company-data-analytics
```

Avoid using personal information, secrets, or internal credentials in bucket names.

### 3.2 Object

An **object** is the data stored in S3.

An object consists of:

- Object data: the file content.
- Object key: the object's unique name within its bucket.
- Metadata: information associated with the object.
- Optional version ID when versioning is enabled.

Example:

```text
Bucket: company-app-prod-files
Object key: users/1001/profile/avatar.png
```

The bucket and key identify the object.

### 3.3 Object key and prefix

S3 uses a flat object namespace. The slash character `/` in a key is a naming convention that makes objects appear organized into folders in many tools.

Example keys:

```text
users/1001/avatar.png
users/1002/avatar.png
invoices/2026/11/invoice-001.pdf
invoices/2026/11/invoice-002.pdf
```

The prefix `invoices/2026/11/` helps group related objects.

These are not necessarily real folders in the traditional file-system sense. A console may display prefixes as folders for convenience.

### 3.4 Object metadata

S3 objects can have system metadata and user-defined metadata.

Examples include:

- Content-Type.
- Content-Length.
- Last-Modified.
- Cache-Control.
- Content-Disposition.
- User-defined metadata values.

Set an appropriate Content-Type when uploading files so browsers and downstream applications can handle them correctly.

## 4. S3 Regions and Bucket Naming

An S3 bucket is created in a specific AWS Region.

For this course, examples use Singapore:

```text
ap-southeast-1
```

Important points:

- Bucket names are globally unique within the relevant AWS partition.
- A bucket belongs to one Region.
- An application should use the correct Region and endpoint configuration.
- Data transfer, latency, compliance, and service availability should influence Region selection.
- Do not assume an S3 bucket is automatically replicated to another Region.

### Example

```text
AWS Region: ap-southeast-1
       |
       v
Bucket: company-app-prod-files
       |
       +---- users/1001/avatar.png
       +---- invoices/2026/invoice-001.pdf
       +---- exports/report.csv
```

If you need a copy in another Region for disaster recovery, configure an appropriate replication or backup design.

## 5. S3 Storage Classes

S3 offers storage classes for different access patterns, availability requirements, and cost profiles.

| Storage class | Typical access pattern | Main idea |
|---|---|---|
| S3 Standard | Frequently accessed | General-purpose active data |
| S3 Intelligent-Tiering | Unknown or changing access patterns | Automatically moves eligible objects between access tiers |
| S3 Standard-IA | Infrequently accessed | Lower storage cost with retrieval charges and minimum-duration considerations |
| S3 One Zone-IA | Infrequently accessed, recreatable data | Stores data in one Availability Zone |
| S3 Glacier Instant Retrieval | Archive data needing millisecond retrieval | Archive-oriented with fast access |
| S3 Glacier Flexible Retrieval | Archive data with retrieval delay acceptable | Multiple retrieval options and restore process |
| S3 Glacier Deep Archive | Very rarely accessed long-term archive | Lowest-cost long-term archive option among common S3 classes |

### How to choose

| Scenario | Possible starting point |
|---|---|
| User profile images used regularly | S3 Standard |
| Access pattern is unpredictable | S3 Intelligent-Tiering |
| Old reports accessed occasionally | S3 Standard-IA or an appropriate archive tier |
| Re-creatable intermediate data | S3 One Zone-IA, if its availability characteristics are acceptable |
| Long-term compliance archive | Glacier storage class selected for retrieval requirements |

Consider more than storage price:

- Retrieval charges.
- Minimum storage duration.
- Minimum billable object size, where applicable.
- Retrieval time.
- Availability and resilience requirements.
- Monitoring and automation costs.

Do not move critical data into an archive class without understanding how and when it can be restored.

### Intelligent-Tiering

S3 Intelligent-Tiering is designed for data with changing or unknown access patterns. It can automatically move eligible objects among access tiers based on access behavior.

Some tiers have different retrieval characteristics. Optional archive tiers may require configuration and have restore delays. Review current tier rules and monitoring charges before enabling them.

## 6. S3 Versioning

**Versioning** keeps multiple versions of an object in a bucket.

When versioning is enabled:

- Uploading an object with an existing key creates a new version.
- Deleting an object normally creates a delete marker rather than immediately removing all versions.
- A previous version can be restored or downloaded if it has not been permanently deleted.

### Example

```text
Bucket: company-app-prod-files

Key: reports/monthly.pdf
   |
   +---- Version A (older)
   |
   +---- Version B
   |
   +---- Version C (current)
```

### Why use versioning?

- Recover from accidental overwrites.
- Recover from some accidental deletes.
- Keep historical file versions.
- Support operational recovery workflows.

### Important considerations

- Versioning can increase storage usage.
- Deleting an object without specifying a version ID generally creates a delete marker in a versioning-enabled bucket.
- Permanently deleting a specific version requires the version ID and appropriate permissions.
- Versioning alone is not a complete backup strategy. Consider replication, retention controls, and recovery testing.

### Enable versioning with AWS CLI

```bash
aws s3api put-bucket-versioning \
  --bucket YOUR_BUCKET_NAME \
  --versioning-configuration Status=Enabled
```

Check versioning status:

```bash
aws s3api get-bucket-versioning \
  --bucket YOUR_BUCKET_NAME
```

## 7. S3 Lifecycle Rules

A **Lifecycle configuration** automates actions on objects as they age.

Typical actions include:

- Transitioning objects to another storage class.
- Expiring current objects.
- Removing noncurrent object versions.
- Cleaning up expired delete markers.
- Aborting incomplete multipart uploads.

### Example lifecycle policy

```text
New invoice
    |
    v
S3 Standard
    |
    | after an appropriate retention period
    v
S3 Standard-IA
    |
    | later, if archive access delay is acceptable
    v
S3 Glacier Flexible Retrieval
    |
    | after required retention period
    v
Expiration (only if policy permits)
```

This is an illustrative lifecycle. Choose transition dates based on access patterns, minimum-duration rules, legal retention requirements, and retrieval costs.

### Lifecycle with versioning

A versioned bucket may contain current and noncurrent versions. You may need separate lifecycle actions for:

- Current versions.
- Noncurrent versions.
- Expired delete markers.
- Incomplete multipart uploads.

Do not create expiration rules until you understand the retention requirements. An incorrect rule can remove data your organization needs.

## 8. S3 Security: IAM and Bucket Policies

S3 access can be controlled by several policy and configuration layers.

Common mechanisms include:

- IAM identity-based policies.
- S3 bucket policies.
- Access point policies.
- S3 Block Public Access settings.
- Object Ownership settings.
- Organization-level controls such as Service Control Policies.

Authorization depends on the complete request context and applicable policy layers. Explicit deny rules and public-access protections can prevent access even when another policy appears to allow it.

### 8.1 IAM identity-based policy

An IAM policy can grant a user or role permission to access a bucket or objects.

Example: allow an application role to list one bucket and read/write objects under a specific prefix.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ListApplicationBucket",
      "Effect": "Allow",
      "Action": [
        "s3:ListBucket"
      ],
      "Resource": "arn:aws:s3:::company-app-prod-files"
    },
    {
      "Sid": "ReadWriteApplicationObjects",
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:PutObject"
      ],
      "Resource": "arn:aws:s3:::company-app-prod-files/app/*"
    }
  ]
}
```

Notice the difference:

- Bucket-level actions such as `s3:ListBucket` use the bucket ARN.
- Object-level actions such as `s3:GetObject` and `s3:PutObject` use object ARNs.

This policy is illustrative. Add only the actions required by your application. Multipart uploads, tagging, encryption-key use, and other workflows may require additional permissions.

### 8.2 Bucket policy

A bucket policy is a resource-based policy attached to an S3 bucket.

It can grant or restrict access based on principals and request conditions.

Example: deny non-TLS requests to a bucket.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyInsecureTransport",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:*",
      "Resource": [
        "arn:aws:s3:::company-app-prod-files",
        "arn:aws:s3:::company-app-prod-files/*"
      ],
      "Condition": {
        "Bool": {
          "aws:SecureTransport": "false"
        }
      }
    }
  ]
}
```

Review policy interactions before deploying changes. A broad deny can unexpectedly block legitimate workloads.

### 8.3 Block Public Access

S3 Block Public Access provides account-level and bucket-level settings that help prevent public exposure.

For most private application buckets:

- Keep all relevant Block Public Access protections enabled.
- Use IAM roles and private access patterns.
- Avoid public bucket policies unless there is a reviewed business requirement.
- If public content is required, consider controlled delivery through CloudFront and an origin access control design.

### 8.4 Object Ownership

S3 Object Ownership settings help manage ownership and access behavior for objects uploaded by different AWS accounts.

The **Bucket owner enforced** setting disables ACLs and makes the bucket owner own objects in the bucket. This is a common recommended choice for many modern application buckets.

Avoid relying on object ACLs unless a specific compatibility requirement exists.

## 9. S3 Encryption

Encryption helps protect data at rest and in transit.

### 9.1 Encryption in transit

Use HTTPS/TLS for communication between applications and S3.

Example:

```text
Spring Boot Application
          |
          | HTTPS / TLS
          v
       Amazon S3
```

Do not send sensitive files or credentials over unencrypted HTTP.

### 9.2 Server-side encryption

S3 supports server-side encryption options, including:

| Option | Meaning |
|---|---|
| SSE-S3 | S3 manages encryption keys |
| SSE-KMS | AWS KMS keys are used for encryption-key management |
| DSSE-KMS | Dual-layer server-side encryption using AWS KMS |

The correct choice depends on compliance, audit, key-control, and cost requirements.

### 9.3 SSE-S3

S3 manages the encryption keys. It is a convenient option for many general-purpose storage needs.

### 9.4 SSE-KMS

SSE-KMS uses AWS KMS keys. It can provide more control over key policies, auditing, and key administration.

The principal accessing the object may need both appropriate S3 permissions and permission to use the KMS key, depending on the operation and key configuration.

### 9.5 Default bucket encryption

Configure default encryption so that new objects are encrypted automatically according to the bucket's settings.

Check the current configuration:

```bash
aws s3api get-bucket-encryption \
  --bucket YOUR_BUCKET_NAME
```

Encryption does not replace access control. A publicly accessible encrypted object can still be exposed to unauthorized users if permissions allow it.

## 10. S3 Data Protection and Resilience

S3 provides highly durable object storage, but application owners still need to design for accidental deletion, incorrect changes, compromised credentials, and regional incidents.

Useful controls include:

- Versioning.
- Lifecycle policies.
- Replication.
- Object Lock where retention or WORM requirements apply.
- CloudTrail data events when object-level auditing is required.
- Access logging or other monitoring options.
- Separate backup accounts or protected backup destinations.
- Recovery testing.

### Replication overview

S3 replication can automatically copy eligible objects between buckets.

Common patterns:

- Same-Region Replication (SRR).
- Cross-Region Replication (CRR).

Replication requires appropriate configuration, permissions, and versioning. It is not retroactive for every existing object unless you use an appropriate batch replication process. Replication also copies certain unwanted changes or deletions depending on configuration, so it should not be treated as the only backup.

### Object Lock

S3 Object Lock can help prevent objects from being deleted or overwritten for a defined retention period or indefinitely under a legal hold, depending on the mode and configuration.

Common concepts:

- Governance mode.
- Compliance mode.
- Legal hold.

Object Lock is useful for specific retention and compliance requirements. Configure it carefully because retention settings can be difficult or impossible to shorten, depending on mode.

## 11. AWS CLI: Work with S3

The examples use the Singapore Region:

```bash
aws configure set region ap-southeast-1
aws sts get-caller-identity
```

### 11.1 Create a bucket

S3 bucket names must be globally unique within the AWS partition. Choose a unique name.

For Regions other than `us-east-1`, specify the location constraint:

```bash
aws s3api create-bucket \
  --bucket YOUR_GLOBALLY_UNIQUE_BUCKET_NAME \
  --region ap-southeast-1 \
  --create-bucket-configuration LocationConstraint=ap-southeast-1
```

If the bucket name is already taken, choose another name. Do not include secrets or personal information in the name.

### 11.2 List buckets

```bash
aws s3 ls
```

### 11.3 List objects

```bash
aws s3 ls s3://YOUR_BUCKET_NAME/
```

List recursively:

```bash
aws s3 ls s3://YOUR_BUCKET_NAME/ --recursive
```

### 11.4 Upload a file

```bash
aws s3 cp ./report.pdf s3://YOUR_BUCKET_NAME/reports/report.pdf
```

### 11.5 Download a file

```bash
aws s3 cp s3://YOUR_BUCKET_NAME/reports/report.pdf ./report-downloaded.pdf
```

### 11.6 Copy a folder

```bash
aws s3 cp ./documents/ s3://YOUR_BUCKET_NAME/documents/ --recursive
```

### 11.7 Synchronize a directory

```bash
aws s3 sync ./static/ s3://YOUR_BUCKET_NAME/static/
```

`sync` compares source and destination and transfers files as needed. Review options carefully before using `--delete`, because it can remove destination objects that are not present in the source.

### 11.8 Inspect an object

```bash
aws s3api head-object \
  --bucket YOUR_BUCKET_NAME \
  --key reports/report.pdf
```

### 11.9 Get bucket location

```bash
aws s3api get-bucket-location \
  --bucket YOUR_BUCKET_NAME
```

### 11.10 Enable Block Public Access

For a private application bucket, configure all four public-access-block settings:

```bash
aws s3api put-public-access-block \
  --bucket YOUR_BUCKET_NAME \
  --public-access-block-configuration \
  BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
```

### 11.11 Delete an object

```bash
aws s3 rm s3://YOUR_BUCKET_NAME/reports/report.pdf
```

In a versioned bucket, this normally creates a delete marker unless a version ID is specified.

### 11.12 Delete a bucket

**Warning:** A bucket must be empty before it can be deleted. Versioned buckets may contain object versions and delete markers that must be handled. Make sure the bucket is yours and that all required data has been backed up.

For a simple, unversioned, nonempty lab bucket, you can remove objects and then delete the bucket:

```bash
aws s3 rm s3://YOUR_BUCKET_NAME --recursive

aws s3api delete-bucket \
  --bucket YOUR_BUCKET_NAME \
  --region ap-southeast-1
```

Do not run recursive deletion against a production bucket without a reviewed change and recovery plan.

## 12. Hands-on Lab: Create an S3 Bucket and Upload Files

### Lab objective

Create a private S3 bucket in Singapore, enable versioning, upload and download a file, and inspect the object.

**Cost and safety:** S3 storage, requests, data transfer, replication, and other features may incur charges. Review current pricing. Use a bucket created specifically for this lab and remove resources when finished.

### Step 1 — Verify your AWS account and Region

```bash
aws sts get-caller-identity
aws configure set region ap-southeast-1
```

Make sure you are using the intended AWS account.

### Step 2 — Choose a unique bucket name

Use a name that is globally unique within the AWS partition, for example:

```bash
BUCKET="my-s3-learning-bucket-REPLACE-WITH-UNIQUE-SUFFIX"
```

Replace the example suffix with a unique value. Do not use the same sample name as another learner.

### Step 3 — Create the bucket

```bash
aws s3api create-bucket \
  --bucket "$BUCKET" \
  --region ap-southeast-1 \
  --create-bucket-configuration LocationConstraint=ap-southeast-1
```

If the name is already taken, select another unique name.

### Step 4 — Keep the bucket private

```bash
aws s3api put-public-access-block \
  --bucket "$BUCKET" \
  --public-access-block-configuration \
  BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
```

### Step 5 — Enable versioning

```bash
aws s3api put-bucket-versioning \
  --bucket "$BUCKET" \
  --versioning-configuration Status=Enabled
```

Verify:

```bash
aws s3api get-bucket-versioning --bucket "$BUCKET"
```

### Step 6 — Create a sample file

Linux or macOS:

```bash
echo "Hello from Amazon S3" > hello-s3.txt
```

Windows PowerShell:

```powershell
"Hello from Amazon S3" | Out-File -Encoding utf8 hello-s3.txt
```

### Step 7 — Upload the file

```bash
aws s3 cp ./hello-s3.txt "s3://$BUCKET/lab/hello-s3.txt"
```

### Step 8 — List the object

```bash
aws s3 ls "s3://$BUCKET/lab/"
```

### Step 9 — Download the object

```bash
aws s3 cp "s3://$BUCKET/lab/hello-s3.txt" ./hello-s3-downloaded.txt
```

Compare the downloaded file with the original.

### Step 10 — Upload a new version

Change the file:

```bash
echo "This is version two" > hello-s3.txt
```

Upload it again:

```bash
aws s3 cp ./hello-s3.txt "s3://$BUCKET/lab/hello-s3.txt"
```

List object versions:

```bash
aws s3api list-object-versions \
  --bucket "$BUCKET" \
  --prefix lab/hello-s3.txt
```

You should see more than one version if versioning was enabled before both uploads.

### Step 11 — Inspect metadata

```bash
aws s3api head-object \
  --bucket "$BUCKET" \
  --key lab/hello-s3.txt
```

Review fields such as ContentLength, ContentType, LastModified, and VersionId when returned.

### Step 12 — Clean up

For a simple lab bucket, first inspect its contents and versions. If versioning is enabled, deleting only the current key does not permanently remove older versions.

You can list versions and delete markers:

```bash
aws s3api list-object-versions --bucket "$BUCKET"
```

Only after confirming that the bucket contains no data you need, remove all object versions and delete markers using their exact key and version IDs, then delete the bucket. Do not run an unreviewed bulk deletion command against a bucket that may contain important data.

## 13. Spring Boot Integration with Amazon S3

A common use case is allowing users to upload documents through a Spring Boot REST API.

### Architecture

```text
             Web / Mobile Client
                     |
                     | HTTPS
                     v
              Spring Boot API
                     |
                     | AWS SDK for Java 2.x
                     v
                 Amazon S3
                     |
                 S3 Bucket
                     |
             documents/user-id/file
```

The application should use an IAM role rather than hardcoded access keys when running on EC2 or another AWS compute service that supports role credentials.

### 13.1 Add Maven dependency

Example using AWS SDK for Java 2.x:

```xml
<dependency>
    <groupId>software.amazon.awssdk</groupId>
    <artifactId>s3</artifactId>
</dependency>
```

For a production project, manage AWS SDK versions consistently, preferably through the AWS SDK BOM in Maven dependency management.

### 13.2 Configure the bucket name

`application.yml`:

```yaml
app:
  aws:
    s3:
      bucket: company-app-prod-files
```

The bucket name is configuration, not a secret. Credentials should not be placed in this file.

### 13.3 Create an S3 client bean

```java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import software.amazon.awssdk.regions.Region;
import software.amazon.awssdk.services.s3.S3Client;

@Configuration
public class S3Config {

    @Bean
    public S3Client s3Client() {
        return S3Client.builder()
                .region(Region.AP_SOUTHEAST_1)
                .build();
    }
}
```

The AWS SDK default credential provider chain can locate credentials from supported sources. On EC2, configure an instance profile with the required permissions.

### 13.4 Create an S3 service

This example uploads a file to a controlled prefix. A real application must validate file size, content, authorization, and allowed file types.

```java
import java.io.IOException;
import java.util.UUID;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Service;
import org.springframework.web.multipart.MultipartFile;

import software.amazon.awssdk.core.sync.RequestBody;
import software.amazon.awssdk.services.s3.S3Client;
import software.amazon.awssdk.services.s3.model.PutObjectRequest;

@Service
public class S3StorageService {

    private final S3Client s3Client;
    private final String bucketName;

    public S3StorageService(
            S3Client s3Client,
            @Value("${app.aws.s3.bucket}") String bucketName) {
        this.s3Client = s3Client;
        this.bucketName = bucketName;
    }

    public String upload(MultipartFile file) throws IOException {
        String safeObjectKey = "uploads/" + UUID.randomUUID();

        String contentType = file.getContentType();
        if (contentType == null || contentType.isBlank()) {
            contentType = "application/octet-stream";
        }

        PutObjectRequest request = PutObjectRequest.builder()
                .bucket(bucketName)
                .key(safeObjectKey)
                .contentType(contentType)
                .build();

        s3Client.putObject(
                request,
                RequestBody.fromInputStream(file.getInputStream(), file.getSize())
        );

        return safeObjectKey;
    }
}
```

This is a compact teaching example. Production code should also handle empty files, size limits, filename and content validation, exception mapping, timeouts, observability, and cleanup of failed or abandoned uploads.

### 13.5 Create a REST controller

```java
import java.io.IOException;

import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;
import org.springframework.web.multipart.MultipartFile;

@RestController
@RequestMapping("/api/files")
public class FileController {

    private final S3StorageService storageService;

    public FileController(S3StorageService storageService) {
        this.storageService = storageService;
    }

    @PostMapping("/upload")
    public ResponseEntity<String> upload(
            @RequestParam("file") MultipartFile file) throws IOException {

        String objectKey = storageService.upload(file);
        return ResponseEntity.ok(objectKey);
    }
}
```

### 13.6 Test the API

Example using curl:

```bash
curl -X POST \
  -F "file=@./sample.pdf" \
  http://localhost:8080/api/files/upload
```

For local development, configure credentials through an appropriate AWS profile or another supported credential provider. Never commit access keys to source control.

### 13.7 Production security checklist

- Authenticate the user.
- Authorize the user to upload to the intended account or tenant.
- Generate object keys on the server; do not trust client-supplied paths.
- Enforce file-size limits.
- Validate actual file content, not only the supplied Content-Type.
- Consider malware scanning for untrusted uploads.
- Keep the bucket private.
- Grant only required S3 permissions to the application role.
- Use TLS.
- Enable appropriate encryption.
- Avoid returning permanent public object URLs.
- Use short-lived presigned URLs when direct client upload or download is appropriate.
- Log relevant actions without logging file contents or credentials.

## 14. Presigned URLs: Overview

A **presigned URL** grants temporary access to a specific S3 operation, such as uploading or downloading an object.

It is useful when:

- A browser uploads a large file directly to S3.
- A mobile application downloads a private object.
- The backend should not proxy every byte of a large file.

### Upload flow

```text
Client
  |
  | 1. Request upload permission
  v
Spring Boot API
  |
  | 2. Authorize user and create short-lived URL
  v
S3 Presigned URL
  |
  | 3. Upload directly using HTTPS
  v
Amazon S3
  |
  | 4. Notify backend / complete workflow
  v
Spring Boot API
```

A presigned URL is a bearer credential: anyone who obtains it may be able to use it until it expires or the underlying authorization becomes invalid. Do not log it or expose it unnecessarily.

For secure uploads, validate the requested object key, expiry, allowed content size and type, and the user's authorization before generating the URL.

## 15. Common S3 Mistakes

1. Making a bucket public when the application only needs private access.
2. Confusing object keys and prefixes with real file-system folders.
3. Using an IAM policy with a bucket ARN for an object-level action.
4. Using an object ARN for `s3:ListBucket`.
5. Assuming encryption makes public data private.
6. Enabling versioning but forgetting that old versions consume storage.
7. Creating lifecycle expiration rules without checking retention requirements.
8. Choosing an archive class without understanding restore time and retrieval charges.
9. Treating replication as a complete backup strategy.
10. Hardcoding AWS access keys in Spring Boot.
11. Trusting the original filename or Content-Type supplied by a client.
12. Returning permanent public URLs for private documents.
13. Using `aws s3 sync --delete` without checking what it will remove.

## 16. Practical Exercises

### Exercise 1 — S3 basics

**Question:** What is Amazon S3?

**Answer:** Amazon S3 is an object storage service. It stores objects in buckets and provides API-based access to those objects.

### Exercise 2 — Bucket and object

**Question:** What is the difference between a bucket and an object?

**Answer:** A bucket is a container for objects. An object is the stored data, identified by its key within the bucket.

### Exercise 3 — Object key

**Question:** Is `invoices/2026/11/invoice-001.pdf` a real directory path in S3?

**Answer:** It is an object key. The slash characters form prefixes that tools may display like folders, but S3 uses a flat object namespace.

### Exercise 4 — Storage classes

**Question:** Which storage class would you evaluate for data with unknown or changing access patterns?

**Answer:** S3 Intelligent-Tiering is a possible choice because it can automatically move eligible objects between access tiers based on access patterns.

### Exercise 5 — Versioning

**Question:** What happens when you upload a new object using the same key in a versioning-enabled bucket?

**Answer:** S3 stores a new object version while retaining earlier versions, subject to lifecycle and deletion actions.

### Exercise 6 — Lifecycle

**Question:** What is an S3 Lifecycle rule?

**Answer:** It automates object management actions, such as transitioning objects between storage classes or expiring objects and noncurrent versions.

### Exercise 7 — IAM policy

**Question:** Which ARN should be used for `s3:ListBucket`?

**Answer:** The bucket ARN, such as `arn:aws:s3:::example-bucket`.

### Exercise 8 — Object permission

**Question:** Which ARN should be used for `s3:GetObject`?

**Answer:** An object ARN, such as `arn:aws:s3:::example-bucket/path/*`.

### Exercise 9 — Public access

**Question:** What does S3 Block Public Access help prevent?

**Answer:** It helps prevent public access through public ACLs and bucket policies, according to the enabled account- and bucket-level settings.

### Exercise 10 — Encryption

**Question:** Does SSE-KMS remove the need for S3 access permissions?

**Answer:** No. The requester still needs appropriate S3 permissions and, depending on the operation and key configuration, permission to use the KMS key.

### Exercise 11 — Spring Boot

**Question:** How should a Spring Boot application running on EC2 authenticate to S3?

**Answer:** Use an IAM role attached to the EC2 instance through an instance profile, and let the AWS SDK obtain temporary credentials.

### Exercise 12 — Presigned URL

**Question:** What is a presigned URL?

**Answer:** It is a time-limited URL that grants permission to perform a specified S3 operation without giving the client long-term AWS credentials.

## 19. AWS Interview Questions and Answers

### Q1. What is Amazon S3?

Amazon S3 is an object storage service that stores objects in buckets and provides scalable API-based access.

### Q2. What is the difference between S3 and EBS?

S3 is object storage accessed through APIs. EBS is block storage commonly attached to EC2 instances as a virtual disk.

### Q3. What is an S3 object key?

An object key is the name that identifies an object within a bucket. Prefixes and slash characters can organize keys in a folder-like way.

### Q4. Are S3 folders real directories?

Not in the traditional file-system sense. S3 uses a flat object namespace. Console folders are commonly represented by key prefixes.

### Q5. What is S3 versioning?

Versioning stores multiple versions of objects. It can help recover from overwrites and accidental deletion, but it can increase storage usage.

### Q6. What is an S3 Lifecycle policy?

A lifecycle configuration automates actions such as transitioning objects to other storage classes, expiring objects, managing noncurrent versions, and aborting incomplete multipart uploads.

### Q7. What is the difference between S3 Standard and S3 Glacier classes?

S3 Standard is designed for frequently accessed data. Glacier classes are designed for archive use cases with different retrieval characteristics and costs.

### Q8. What is the difference between an IAM policy and a bucket policy?

An IAM identity-based policy is attached to an IAM identity such as a user or role. A bucket policy is a resource-based policy attached to an S3 bucket.

### Q9. What is S3 Block Public Access?

It is a set of controls at the account and bucket levels that helps prevent public access through public ACLs and policies.

### Q10. What is SSE-KMS?

SSE-KMS is server-side encryption using AWS KMS keys. It supports key-management controls and auditing, subject to the configured permissions and key policies.

### Q11. What is S3 Cross-Region Replication?

CRR automatically replicates eligible objects from a source bucket to a destination bucket in another Region, when configured with the required permissions and settings.

### Q12. Is replication a complete backup strategy?

Not by itself. Replication can copy unwanted changes or deletions depending on configuration. Combine it with versioning, retention controls, protected backups, and recovery testing as required.

### Q13. What is a presigned URL?

A presigned URL provides temporary permission to perform a specified S3 operation, such as uploading or downloading an object.

### Q14. How should a Spring Boot application access S3?

Use the AWS SDK for Java and an IAM role when running on AWS compute with role support. Grant only the necessary bucket and object permissions.

### Q15. How do you protect user-uploaded files?

Authenticate and authorize users, validate file content and size, generate server-controlled object keys, keep the bucket private, use encryption, and consider malware scanning and short-lived presigned URLs.
