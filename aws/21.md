## 2. VPC Module Overview

An Amazon Virtual Private Cloud (VPC) is a logically isolated virtual network in an AWS Region. You choose an IP address range and create subnets, route tables, and network controls.

A VPC is the foundation for network connectivity between AWS resources.

### Main components

| Component | Purpose |
|---|---|
| VPC | Logically isolated virtual network |
| CIDR block | IP address range assigned to the VPC or subnet |
| Subnet | IP address range in one Availability Zone |
| Route table | Determines where network traffic is sent |
| Internet Gateway | Enables supported Internet connectivity for a VPC |
| NAT Gateway | Allows private subnet resources to initiate outbound IPv4 connections |
| Security Group | Stateful resource-level network firewall |
| Network ACL | Stateless subnet-level network filter |
| VPC Endpoint | Private connectivity to supported services |
| VPC Peering | Direct network connection between two VPCs |
| Transit Gateway | Central hub for connecting multiple networks |
| VPC Flow Logs | Traffic metadata for monitoring and troubleshooting |

### Example VPC architecture

```text
                         AWS Region
                 +------------------------+
                 |       VPC              |
                 |     10.60.0.0/16       |
                 |                        |
Internet --------+---- Internet Gateway   |
                 |          |             |
                 |     Public Subnets     |
                 |       ALB / NAT        |
                 |          |             |
                 |   Private App Subnets  |
                 |     Spring Boot        |
                 |          |             |
                 |  Private DB Subnets    |
                 |        RDS             |
                 +------------------------+
```

A VPC spans the Availability Zones you choose in a Region. Each subnet belongs to one Availability Zone.

## 3. CIDR and Subnet Planning

Before creating a VPC, plan its address range.

Example:

| Network | CIDR |
|---|---|
| VPC | `10.60.0.0/16` |
| Public subnet AZ A | `10.60.1.0/24` |
| Public subnet AZ B | `10.60.2.0/24` |
| Application subnet AZ A | `10.60.11.0/24` |
| Application subnet AZ B | `10.60.12.0/24` |
| Database subnet AZ A | `10.60.21.0/24` |
| Database subnet AZ B | `10.60.22.0/24` |

### CIDR reminders

- A smaller prefix number represents a larger IPv4 address range.
- `10.60.0.0/16` contains the ranges used by the example subnets.
- `10.60.1.0/24` contains 256 IPv4 addresses in the CIDR block, although AWS reserves some addresses in each subnet.
- Avoid overlapping address ranges if networks may later connect through peering, Transit Gateway, VPN, or Direct Connect.

### Multi-AZ design

Use multiple Availability Zones for production workloads where the service architecture supports it.

```text
                  Application VPC
                  10.60.0.0/16
                         |
              +----------+----------+
              |                     |
              v                     v
          AZ A                    AZ B
       +----------+            +----------+
       | Public   |            | Public   |
       | Subnet   |            | Subnet   |
       | ALB/NAT  |            | ALB/NAT  |
       +----------+            +----------+
       | App      |            | App      |
       | Subnet   |            | Subnet   |
       +----------+            +----------+
       | DB       |            | DB       |
       | Subnet   |            | Subnet   |
       +----------+            +----------+
```

A multi-AZ design improves resilience, but it does not automatically make an application highly available. The application, database, load balancer, and dependencies must also be configured for resilience.

## 4. Public and Private Subnets

A subnet is commonly called public when its associated route table has a route to an Internet Gateway.

A subnet is commonly called private when it does not have a direct route to an Internet Gateway for direct Internet access.

The subnet name itself does not make it public or private. Routing and resource configuration determine connectivity.

### Public subnet

Common resources:

- Internet-facing Application Load Balancer.
- NAT Gateway.
- Bastion host, only when there is a justified need and appropriate controls.

Example route table:

| Destination | Target |
|---|---|
| `10.60.0.0/16` | local |
| `0.0.0.0/0` | Internet Gateway |

### Private application subnet

Common resources:

- Spring Boot EC2 instances.
- ECS tasks.
- Internal application services.

Example route table when a NAT Gateway is used:

| Destination | Target |
|---|---|
| `10.60.0.0/16` | local |
| `0.0.0.0/0` | NAT Gateway |
| S3 prefix list | S3 Gateway Endpoint |

### Private database subnet

Common resources:

- Amazon RDS.
- Database-related services.

A database subnet route table generally does not need a default route to the Internet. Add only routes required by the architecture.

### Internet Gateway vs NAT Gateway

| Feature | Internet Gateway | NAT Gateway |
|---|---|---|
| Main role | Internet connectivity for eligible resources with suitable public addressing and routes | Outbound connectivity for private subnet resources |
| Common placement | Attached to VPC; used by public subnet route tables | Deployed in a subnet, commonly public |
| Allows unsolicited inbound Internet access to private instances | No | No |
| Typical use | Internet-facing load balancer | Private application instances needing outbound IPv4 access |

A NAT Gateway does not make a private instance publicly addressable.

## 5. Route Tables and Traffic Paths

A route table determines where traffic is directed based on its destination IP address.

Every subnet is associated with a route table. If you do not explicitly associate a subnet with a custom route table, it uses the VPC's main route table.

### Example route table

| Destination | Target | Meaning |
|---|---|---|
| `10.60.0.0/16` | local | Traffic inside the VPC |
| `0.0.0.0/0` | `igw-...` | Default IPv4 route to Internet Gateway |
| `pl-...` | `vpce-...` | Traffic to a service through a prefix-list route, such as an S3 Gateway Endpoint |

### Example: User to Spring Boot

```text
User Browser
    |
    | HTTPS 443
    v
Internet Gateway
    |
    v
Public Application Load Balancer
    |
    | Application port
    v
Private Spring Boot Instance
    |
    | Database port
    v
Private RDS Database
```

The actual path depends on the load balancer subnet routes, target configuration, Security Groups, NACLs, and application settings.

### Return traffic

A working connection needs a valid return path. When troubleshooting, do not inspect only the route from source to destination.

## 6. Internet Gateway and NAT Gateway Review

### Internet Gateway

An Internet Gateway is attached to a VPC. A resource typically needs:

- A route to the Internet Gateway.
- A public IPv4 address or another supported public addressing arrangement.
- Security controls that allow the intended traffic.

### NAT Gateway

A NAT Gateway allows resources in private subnets to initiate outbound IPv4 connections to external destinations.

Typical route:

```text
Private App Subnet
       |
       | 0.0.0.0/0
       v
NAT Gateway in Public Subnet
       |
       v
Internet Gateway
       |
       v
Internet
```

### NAT Gateway design considerations

- A NAT Gateway is deployed in a specific Availability Zone.
- For resilient multi-AZ designs, consider the failure and cross-AZ data-transfer implications of the NAT architecture.
- NAT Gateways have hourly and data-processing charges.
- A NAT Gateway is not a firewall policy engine.
- Restrict outbound traffic with suitable security controls and consider centralized egress inspection where required.

## 7. VPC Endpoints

VPC endpoints allow private connectivity to supported AWS services without requiring the workload to use a public Internet path for that service.

### Gateway endpoint

Gateway endpoints are available for:

- Amazon S3.
- Amazon DynamoDB.

They use route-table integration and do not create endpoint network interfaces.

### Interface endpoint

Interface endpoints create elastic network interfaces in selected subnets and use AWS PrivateLink.

They are used for many supported AWS services and endpoint services.

### Comparison

| Feature | Gateway Endpoint | Interface Endpoint |
|---|---|---|
| Common services | S3, DynamoDB | Many AWS services and PrivateLink services |
| Implementation | Route-table target | Endpoint network interfaces |
| Security Group | Not attached to the endpoint in the same way as interface endpoints | Endpoint ENIs can use Security Groups |
| Common pricing model | No hourly endpoint charge for gateway endpoint itself; other related charges may apply | Hourly and data-processing charges generally apply |
| DNS | Uses service endpoint routing behavior | Private DNS can be enabled for supported services |

### Example: Private S3 access

```text
Spring Boot EC2
Private Application Subnet
          |
          v
     Route Table
          |
          v
   S3 Gateway Endpoint
          |
          v
      Amazon S3
```

Review the endpoint policy, IAM policy, and S3 bucket policy together. An endpoint does not automatically grant access to every bucket.

## 8. VPC-to-VPC Connectivity Review

### VPC Peering

VPC Peering creates a direct network connection between two VPCs.

Important points:

- Routes are required on both sides.
- Security controls must permit the traffic.
- VPC Peering does not provide transitive routing.
- Overlapping IPv4 CIDR ranges prevent ordinary VPC Peering.

```text
VPC A <------ Peering ------> VPC B
```

### Transit Gateway

Transit Gateway is a central hub for connecting multiple VPCs and supported network attachments.

```text
                VPC A
                  |
                  |
VPC B ------ Transit Gateway ------ VPC C
                  |
                  |
             VPN / On-Prem
```

Important points:

- VPC attachments connect VPCs to the hub.
- Transit Gateway route tables control forwarding.
- VPC subnet route tables also need appropriate routes.
- Return paths and security rules are required.
- Route-table associations and propagations can be used to segment connectivity.

### Choosing between them

| Requirement | Candidate |
|---|---|
| Two VPCs need direct communication | VPC Peering |
| Many VPCs need central routing | Transit Gateway |
| One service must be shared privately | PrivateLink |
| On-premises connection over Internet | Site-to-Site VPN |
| Dedicated hybrid connection | Direct Connect |

## 9. Hybrid Connectivity Review

Organizations may connect an on-premises data center to AWS.

### Site-to-Site VPN

- Commonly uses IPsec tunnels over the Internet.
- Can connect to a Virtual Private Gateway or Transit Gateway in supported designs.
- Commonly provides two tunnels for availability.
- Supports static or dynamic routing configurations.

### Direct Connect

- Provides a dedicated network connection to AWS.
- Uses supported Direct Connect locations and virtual interfaces.
- Is not encrypted by default.
- Can be combined with VPN or other encryption where required.

### Example hybrid architecture

```text
             Company Data Center
                  172.20.0.0/16
                         |
                  Customer Router
                         |
              +----------+----------+
              |                     |
              v                     v
        Site-to-Site VPN       Direct Connect
              |                     |
              +----------+----------+
                         |
                  Transit Gateway
                         |
              +----------+----------+
              |          |          |
              v          v          v
          Production   Shared     Analytics
             VPC      Services      VPC
```

The exact design depends on availability requirements, routing, bandwidth, encryption, service support, and cost.

## 10. Security Groups and Network ACLs Review

### Security Groups

- Stateful.
- Associated with supported resources or network interfaces.
- Allow rules only.
- Return traffic for tracked connections is automatically allowed.
- Can reference other Security Groups where supported.

### Network ACLs

- Stateless.
- Associated with subnets.
- Support allow and deny rules.
- Rules are evaluated in ascending rule-number order.
- Return traffic must be explicitly allowed.

### Example three-tier Security Group design

| Security Group | Inbound rule | Source |
|---|---|---|
| `sg-alb` | TCP 443 | Approved client sources |
| `sg-app` | TCP 8080 | `sg-alb` |
| `sg-db` | TCP 5432 | `sg-app` |

This example uses PostgreSQL's default port. Use the actual database engine and port configured in your environment.

### Security design principles

1. Do not expose database ports to the Internet.
2. Avoid unrestricted SSH or RDP access.
3. Prefer Security Group references over broad CIDRs when appropriate.
4. Keep application workloads in private subnets where practical.
5. Review outbound rules, not only inbound rules.
6. Apply NACL rules only when their subnet-level filtering is needed and understood.
7. Use IAM to restrict who can modify network security.

## 11. Monitoring and Troubleshooting Review

### VPC Flow Logs

Flow Logs record metadata about IP traffic.

They can help identify:

- Source and destination IPs.
- Ports and protocols.
- Accepted or rejected traffic.
- Traffic volume and time windows.

They do not capture packet payloads.

### Reachability Analyzer

Reachability Analyzer evaluates supported network paths based on configuration.

It can help find:

- Missing routes.
- Security Group blockers.
- NACL blockers.
- Other configuration problems in supported paths.

It does not prove application health.

### Troubleshooting workflow

```text
User reports connection failure
             |
             v
       Check DNS resolution
             |
             v
       Check destination IP/port
             |
             v
       Check source route table
             |
             v
       Check destination route
             |
             v
       Check return route
             |
             v
       Check Security Groups
             |
             v
       Check NACLs / firewalls
             |
             v
       Check Flow Logs
             |
             v
       Check host and application
```

### Common symptoms

| Symptom | Areas to inspect |
|---|---|
| DNS lookup fails | VPC DNS settings, Route 53, resolver rules, client DNS |
| Connection times out | Routes, Security Groups, NACLs, firewall, return path |
| Connection refused | Application process, listener, host firewall, port |
| ALB target unhealthy | Health-check path, port, target SG, application response |
| Database connection fails | DB endpoint, route, DB SG, NACL, credentials, database state |
| S3 access denied | IAM policy, bucket policy, endpoint policy, encryption permissions |

## 12. Mini Project — Secure Spring Boot E-Commerce Network

### Project scenario

Design an AWS network for an e-commerce application.

Requirements:

- Customers access the application over HTTPS.
- An Application Load Balancer receives public traffic.
- Spring Boot services run in private subnets across two Availability Zones.
- RDS runs in private database subnets.
- Application services access product images in S3.
- Administrative access should not require opening SSH to the Internet.
- Network traffic must be observable.
- The design should support future integration with a corporate data center.

### Step 1 — Define the architecture

```text
                           Customers
                               |
                               v
                         Route 53 DNS
                               |
                               v
                           AWS WAF
                               |
                               v
                  Application Load Balancer
                     Public Subnets AZ A/B
                               |
                     +---------+---------+
                     |                   |
                     v                   v
               Spring Boot A       Spring Boot B
               Private App A       Private App B
                     |                   |
                     +---------+---------+
                               |
                               v
                         Amazon RDS
                      Private DB Subnets
                               |
                               v
                         Database Data

                Spring Boot ---- S3 Gateway Endpoint ---- S3

                VPC Flow Logs ---- CloudWatch / S3
```

This is a logical architecture. A production implementation needs detailed route tables, endpoint policies, IAM roles, logging configuration, and service-specific security settings.

### Step 2 — Choose CIDR ranges

| Component | CIDR |
|---|---|
| VPC | `10.70.0.0/16` |
| Public AZ A | `10.70.1.0/24` |
| Public AZ B | `10.70.2.0/24` |
| Application AZ A | `10.70.11.0/24` |
| Application AZ B | `10.70.12.0/24` |
| Database AZ A | `10.70.21.0/24` |
| Database AZ B | `10.70.22.0/24` |

Check for overlapping CIDRs before creating the network.

### Step 3 — Define route-table behavior

**Public route table**

| Destination | Target |
|---|---|
| `10.70.0.0/16` | local |
| `0.0.0.0/0` | Internet Gateway |

**Private application route table**

| Destination | Target |
|---|---|
| `10.70.0.0/16` | local |
| `0.0.0.0/0` | NAT Gateway, if outbound Internet access is required |
| S3 prefix list | S3 Gateway Endpoint |

**Private database route table**

| Destination | Target |
|---|---|
| `10.70.0.0/16` | local |

Add other routes only when required by an approved architecture.

### Step 4 — Define Security Groups

**ALB Security Group**

- Inbound TCP 443 from intended customer sources.
- Outbound TCP 8080 to the application Security Group.

**Application Security Group**

- Inbound TCP 8080 from the ALB Security Group.
- Outbound TCP 5432 to the database Security Group.
- Outbound access to required AWS services through approved endpoints or egress routes.

**Database Security Group**

- Inbound TCP 5432 from the application Security Group.
- No public inbound access.

### Step 5 — Design administrative access

Prefer AWS Systems Manager Session Manager for supported managed instances rather than opening SSH to the entire Internet.

Requirements may include:

- Appropriate instance profile permissions.
- SSM Agent installed and running.
- Network access to required Systems Manager endpoints.
- IAM permissions for authorized operators.
- Logging and session controls appropriate to the organization.

Do not assume that Session Manager works without the required agent, IAM role, and network connectivity.

### Step 6 — Design S3 access

Use an S3 Gateway VPC Endpoint for private S3 connectivity.

Review:

- Endpoint policy.
- Application IAM role permissions.
- S3 bucket policy.
- Encryption requirements.
- Object-level permissions.

### Step 7 — Enable monitoring

Consider:

- VPC Flow Logs.
- ALB access logs.
- Application logs.
- RDS monitoring.
- CloudWatch metrics and alarms.
- Security findings and configuration monitoring.

Set retention and access permissions deliberately.

### Step 8 — Plan future hybrid connectivity

If the company later needs to connect a data center:

- Evaluate Site-to-Site VPN for encrypted connectivity over the Internet.
- Evaluate Direct Connect for dedicated connectivity.
- Evaluate Transit Gateway if multiple VPCs need central routing.
- Reserve non-overlapping CIDR ranges.
- Define route segmentation and approved traffic flows.

### Step 9 — Test the design

| Test | Expected result |
|---|---|
| Customer to ALB over HTTPS | Allowed |
| Internet directly to application instance | Not allowed |
| ALB to Spring Boot | Allowed |
| Unapproved source to Spring Boot port | Not allowed |
| Spring Boot to RDS | Allowed |
| Internet to RDS | Not allowed |
| Spring Boot to approved S3 bucket | Allowed |
| Unauthorized workload to S3 bucket | Denied |
| Authorized operator through Session Manager | Allowed if configured |
| Unapproved operator session | Denied |

### Step 10 — Document the project

Create a small architecture document with:

- Network diagram.
- CIDR plan.
- Subnet and Availability Zone mapping.
- Route tables.
- Security Group rules.
- NACL rules, if used.
- Endpoint policies.
- IAM roles and permissions.
- Monitoring and log destinations.
- Recovery and connectivity assumptions.
- Estimated cost categories.

## 13. AWS CLI Review

The following commands are primarily for inspection. Replace placeholders with actual resource IDs.

Set the Region:

```bash
aws configure set region ap-southeast-1
aws sts get-caller-identity
```

### List VPCs

```bash
aws ec2 describe-vpcs \
  --query "Vpcs[].[VpcId,CidrBlock,State]" \
  --output table
```

### List subnets

```bash
aws ec2 describe-subnets \
  --filters Name=vpc-id,Values=vpc-REPLACE_ME \
  --query "Subnets[].[SubnetId,AvailabilityZone,CidrBlock,MapPublicIpOnLaunch]" \
  --output table
```

### List route tables

```bash
aws ec2 describe-route-tables \
  --filters Name=vpc-id,Values=vpc-REPLACE_ME
```

### List Internet Gateways

```bash
aws ec2 describe-internet-gateways \
```

```bash
aws ec2 describe-nat-gateways \
  --filter Name=vpc-id,Values=vpc-REPLACE_ME \
```

```bash
aws ec2 describe-security-groups \
```

```bash
aws ec2 describe-network-acls \
  --filters Name=vpc-id,Values=vpc-REPLACE_ME
```

```bash
aws ec2 describe-vpc-endpoints \
  --filters Name=vpc-id,Values=vpc-REPLACE_ME \
```

```bash
aws ec2 describe-flow-logs \
  --query "FlowLogs[].[FlowLogId,ResourceId,TrafficType,LogDestinationType,FlowLogStatus]" \
  --output table
```

### List peering connections

```bash
aws ec2 describe-vpc-peering-connections \
  --query "VpcPeeringConnections[].[VpcPeeringConnectionId,Status.Code]" \
  --output table
```

### List Transit Gateways

```bash
aws ec2 describe-transit-gateways \
  --query "TransitGateways[].[TransitGatewayId,State]" \
  --output table
```

### CLI safety notes

- These commands inspect configuration and do not prove end-to-end application connectivity.
- Use an IAM identity with only the permissions needed.
- Do not paste secrets or access keys into shell history.
- Review any proposed create, modify, or delete command before executing it.
- Network resources such as NAT Gateways, Transit Gateway attachments, endpoints, and logging destinations may incur charges.

## 14. Practical Exercises

### Exercise 1 — VPC

**Question:** What is an Amazon VPC?

**Answer:** A logically isolated virtual network in an AWS Region where you can define IP ranges, subnets, routing, and network controls.

### Exercise 2 — Subnets

**Question:** Can one subnet span multiple Availability Zones?

**Answer:** No. A subnet belongs to one Availability Zone.

### Exercise 3 — Public subnet

**Question:** What commonly makes a subnet public?

**Answer:** Its associated route table has a route to an Internet Gateway. Resources still need appropriate addressing and security configuration for Internet connectivity.

### Exercise 4 — NAT Gateway

**Question:** What is the purpose of a NAT Gateway?

**Answer:** It allows resources in private subnets to initiate outbound IPv4 connections to external destinations.

### Exercise 5 — VPC Endpoint

**Question:** Which endpoint type is commonly used for S3?

**Answer:** An S3 Gateway VPC Endpoint.

### Exercise 6 — Peering

**Question:** Does VPC Peering support transitive routing?

**Answer:** No. It connects two VPCs directly and does not provide transitive routing.

### Exercise 7 — Transit Gateway

**Question:** When should you evaluate Transit Gateway?

**Answer:** When multiple VPCs or supported network attachments need central routing and network segmentation.

### Exercise 8 — Security Group

**Question:** Is a Security Group stateful?

**Answer:** Yes. Return traffic for tracked connections is automatically permitted.

### Exercise 9 — NACL

**Question:** Is a Network ACL stateful?

**Answer:** No. It is stateless, so return traffic must be explicitly allowed.

### Exercise 10 — Flow Logs

**Question:** What do VPC Flow Logs record?

**Answer:** Metadata about IP traffic, such as source, destination, ports, protocol, and traffic action.

### Exercise 11 — Hybrid networking

**Question:** What is the difference between Site-to-Site VPN and Direct Connect?

**Answer:** Site-to-Site VPN commonly uses encrypted IPsec tunnels over the Internet. Direct Connect provides a dedicated network connection and is not encrypted by default.

### Exercise 12 — Database isolation

**Question:** How should an application connect to a private database?

**Answer:** Through private network routes, with the database Security Group allowing only the required application source and port.

### Exercise 13 — Troubleshooting

**Question:** A Spring Boot instance cannot connect to RDS. What should you inspect?

**Answer:** Database hostname and port, VPC routes, Security Groups, NACLs, database status, credentials, TLS settings, host firewall, and application configuration.

### Exercise 14 — Architecture choice

**Question:** A company has several VPCs and needs centralized connectivity to an on-premises data center. What service should it evaluate?

**Answer:** Transit Gateway, together with Site-to-Site VPN or Direct Connect depending on connectivity requirements.

## 16. English Speaking Practice

Practice speaking for 3–5 minutes. Read each model answer and then explain the architecture using your own words.

### Question 1: What is a VPC?

Model answer:

> An Amazon VPC is a logically isolated virtual network in AWS. I can define an IP address range, create subnets, configure route tables, and apply network security controls. It provides the network foundation for my AWS application.

### Question 2: What is the difference between a public and a private subnet?

Model answer:

> A public subnet has a route to an Internet Gateway. A private subnet does not have a direct route to an Internet Gateway for direct Internet access. I usually place the load balancer in public subnets and application and database resources in private subnets.

### Question 3: What is a NAT Gateway?

Model answer:

> A NAT Gateway allows resources in a private subnet to initiate outbound IPv4 connections to external destinations. It does not make those private resources directly accessible from the Internet.

### Question 4: What is the difference between a Security Group and a Network ACL?

Model answer:

> A Security Group is stateful and applies to supported resources or network interfaces. A Network ACL is stateless and applies at the subnet level. Security Groups use allow rules, while Network ACLs support allow and deny rules.

### Question 5: How would you secure a Spring Boot application on AWS?

Model answer:

> I would use an Application Load Balancer in public subnets and run Spring Boot in private subnets. The application Security Group would allow traffic only from the ALB Security Group. The database Security Group would allow traffic only from the application Security Group. I would also use IAM roles, private endpoints, logging, and secure secrets.

### Question 6: How do you troubleshoot a network connection problem?

Model answer:

> First, I check DNS resolution and the destination IP address. Then I inspect the source and destination route tables, return routes, Security Groups, and Network ACLs. I also review VPC Flow Logs and use Reachability Analyzer when appropriate. Finally, I check the host firewall and application logs.

## 17. AWS Interview Questions and Answers

### Q1. What is an Amazon VPC?

A VPC is a logically isolated virtual network in an AWS Region. It provides control over IP ranges, subnets, routing, and network security.

### Q2. What is a subnet?

A subnet is a range of IP addresses within a VPC. Each subnet belongs to one Availability Zone.

### Q3. What makes a subnet public?

A subnet is commonly considered public when its associated route table has a route to an Internet Gateway. Resources also need suitable addressing and security configuration to communicate with the Internet.

### Q4. What is the difference between an Internet Gateway and a NAT Gateway?

An Internet Gateway provides Internet connectivity for eligible resources with appropriate routes and addressing. A NAT Gateway allows private subnet resources to initiate outbound IPv4 connections without making those resources directly addressable from the Internet.

### Q5. What is a route table?

A route table contains routes that determine where network traffic is directed based on its destination.

### Q6. What is a VPC Endpoint?

A VPC Endpoint provides private connectivity from a VPC to supported AWS services or endpoint services without requiring a public Internet path for that service.

### Q7. What is the difference between Gateway and Interface Endpoints?

Gateway Endpoints are used for S3 and DynamoDB and integrate with route tables. Interface Endpoints create network interfaces in subnets and use AWS PrivateLink.

### Q8. What is VPC Peering?

VPC Peering creates a direct network connection between two VPCs. It does not support transitive routing.

### Q9. What is Transit Gateway?

Transit Gateway is a central hub for connecting multiple VPCs and supported network attachments through configured routing.

### Q10. What is the difference between a Security Group and a Network ACL?

A Security Group is stateful and applies to supported resources or network interfaces. A Network ACL is stateless and applies at the subnet level.

### Q11. What are VPC Flow Logs?

Flow Logs capture metadata about IP traffic to and from supported network interfaces, subnets, or VPCs.

### Q12. Do Flow Logs capture packet contents?

No. They record traffic metadata, not packet payloads.

### Q13. How can a private EC2 instance access S3 without using a NAT Gateway?

Use an S3 Gateway VPC Endpoint, with suitable route-table association and access policies.

### Q14. How would you connect an on-premises network to AWS?

Evaluate Site-to-Site VPN for encrypted connectivity over the Internet or Direct Connect for a dedicated connection. Use Transit Gateway when central routing across multiple VPCs is required.

### Q15. How would you secure a database in AWS?

Place it in private subnets, restrict its Security Group to approved application sources, avoid public access, protect credentials, use encryption, and enable monitoring and backups.

### Q16. What causes a connection timeout?

Possible causes include missing routes, blocked Security Group or NACL rules, firewall restrictions, missing return paths, DNS problems, or an unavailable destination.

### Q17. What is the purpose of Reachability Analyzer?

It analyzes supported network paths based on AWS configuration and helps identify potential routing or security blockers.

### Q18. How would you design a highly available VPC architecture?

Use multiple Availability Zones, deploy supported application components across them, configure load balancing and health checks, use resilient data services, and design network paths and dependencies for failure scenarios.

### Q19. Why is CIDR planning important?

It prevents overlapping address ranges and makes future connectivity to other VPCs, Regions, and on-premises networks easier to manage.

### Q20. How would you explain your VPC architecture in an interview?

I would describe the VPC CIDR, subnet layout, Availability Zones, route tables, Internet and NAT Gateways, Security Groups, endpoints, connectivity requirements, monitoring, and how the architecture handles failures.
