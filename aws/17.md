## 2. Why Do We Need Advanced S3 Features?

A basic application may upload a small profile image to S3. A production system may need to handle:

- Large video files.
- Thousands of uploads per minute.
- Users uploading from different continents.
- Automatic image resizing.
- Malware scanning.
- Document conversion.
- Cross-Region disaster recovery.
- Long-term retention for compliance.
- Secure temporary download links.

Advanced S3 features help build these workflows without forcing the application server to handle every operation itself.

### Example architecture

```text
                  Web / Mobile Client
                          |
                          v
                   Spring Boot API
                          |
                 Validate and authorize
                          |
                          v
                    Amazon S3
                          |
                   Object created
                          |
                          v
                 S3 Event Notification
                          |
                          v
                   Amazon SQS Queue
                          |
                          v
                File Processing Worker
                          |
             +------------+------------+
             |                         |
             v                         v
         Processed S3              Database
         Object                    Metadata
```

This architecture separates file upload from file processing. The API can respond after the upload is accepted, while background workers process files asynchronously.

## 3. Multipart Upload

**Multipart upload** allows a large object to be uploaded as separate parts and then assembled by S3.

Instead of sending one large request, the client:

1. Starts a multipart upload.
2. Uploads individual parts.
3. Records each part's number and ETag.
4. Completes the upload by providing the uploaded part information.

If a part fails, the client can retry that part rather than restarting the entire file upload.

### Multipart upload flow

```text
                Large File
                    |
                    v
             Split into Parts
              /     |     \
             v      v      v
          Part 1  Part 2  Part 3
             |      |      |
             v      v      v
          Upload  Upload  Upload
             \      |      /
              \     |     /
               v    v    v
             Complete Multipart
                    |
                    v
                S3 Object
```

### Benefits

- Supports efficient transfer of large objects.
- Allows parallel part uploads.
- Allows retrying failed parts.
- Can improve resilience over unstable networks.
- Supports resumable upload workflows when the application stores upload state.

### Important concepts

| Concept | Meaning |
|---|---|
| Upload ID | Identifies a multipart upload session |
| Part number | Identifies an individual part |
| ETag | Identifier returned for an uploaded part; do not assume it is always an MD5 checksum |
| Complete | Combines the uploaded parts into an object |
| Abort | Cancels the multipart upload and removes uploaded parts |

S3 has minimum and maximum part-size requirements and a maximum number of parts. Check the current multipart upload limits before implementing a custom uploader.

### Incomplete multipart uploads

If an application starts a multipart upload but never completes or aborts it, uploaded parts can remain and incur storage charges.

Use an S3 Lifecycle rule to abort incomplete multipart uploads after an appropriate number of days.

Example lifecycle rule concept:

```text
Multipart upload started
        |
        v
Parts uploaded
        |
        +---- Complete ----> Final S3 object
        |
        +---- Abort -------> Parts removed
        |
        +---- Abandoned ---> Lifecycle cleanup
```

### When should you use multipart upload?

- Large media files.
- Large data exports.
- Backup files.
- Unreliable network connections.
- Parallel high-throughput uploads.

For small files, a simple `PutObject` request is usually easier.

## 4. S3 Transfer Acceleration

**S3 Transfer Acceleration** can improve transfer performance for users who are geographically distant from the destination bucket.

It uses AWS edge network infrastructure to route data toward the S3 bucket.

### Basic flow

```text
User in another country
          |
          v
AWS Edge Location
          |
          v
AWS Network
          |
          v
S3 Bucket Region
```

### When to evaluate it

- Users are geographically distributed.
- Uploads are large.
- Network distance is a significant part of transfer time.
- Testing shows a meaningful improvement.

### Important considerations

- Transfer Acceleration must be enabled for the bucket.
- Use the acceleration endpoint when supported by the client.
- It may introduce additional transfer charges.
- It does not guarantee faster transfers for every user or every network.
- Benchmark with representative files and locations before enabling it broadly.

### CLI overview

Check bucket acceleration configuration:

```bash
aws s3api get-bucket-accelerate-configuration \
  --bucket YOUR_BUCKET_NAME
```

Enable acceleration:

```bash
aws s3api put-bucket-accelerate-configuration \
  --bucket YOUR_BUCKET_NAME \
  --accelerate-configuration Status=Enabled
```

Use the S3 acceleration endpoint in a compatible client configuration. Do not assume a normal regional endpoint automatically uses Transfer Acceleration.

## 5. S3 Event Notifications

S3 can publish event notifications when certain actions occur, such as:

- An object is created.
- An object is removed.
- An object is restored.
- Replication events occur, where supported.
- Other supported S3 event types occur.

A common event is `ObjectCreated`, which can trigger processing after a file upload.

### Example: automatic image processing

```text
User uploads image
        |
        v
     Amazon S3
        |
        | ObjectCreated event
        v
   Event destination
        |
        v
   AWS Lambda
        |
        v
 Resize / validate image
        |
        v
 Save thumbnail to S3
```

### Supported destinations

Common S3 event notification destinations include:

- Amazon SNS topic.
- Amazon SQS queue.
- AWS Lambda function.
- EventBridge, when S3 event delivery to EventBridge is enabled.

For direct S3 notifications to SNS, SQS, or Lambda, the destination must satisfy the required Region and permission constraints. Check current service documentation for exact compatibility.

### Event notification configuration

An event notification configuration can specify:

- Event types.
- Destination.
- Optional key prefix filters.
- Optional key suffix filters.

Example filter idea:

```text
Only trigger for:
uploads/images/*.jpg
```

In S3 notification configuration, filters are based on key prefixes and suffixes, not arbitrary regular expressions.

### Avoid event loops

A common mistake is using the same bucket and prefix for both incoming and generated files.

Example of a loop:

```text
Upload original
     |
     v
S3 event triggers Lambda
     |
     v
Lambda writes processed file to same watched prefix
     |
     v
Another S3 event triggers Lambda
     |
     +---- Repeats
```

Prevent loops by:

- Writing processed objects to a different prefix, such as `processed/`.
- Using separate buckets for source and output.
- Filtering notifications to only the intended input prefix or suffix.

### Event delivery and processing design

Do not assume that notifications are delivered exactly once or in a globally ordered sequence. Design consumers to tolerate duplicate and out-of-order events.

A robust consumer should:

- Be idempotent.
- Validate the bucket and object key.
- Handle retries.
- Record processing status.
- Avoid overwriting newer output with stale work.
- Send permanently failing messages to a dead-letter queue when appropriate.

## 6. SQS, SNS, Lambda, and EventBridge

These services can be used with S3 notifications, but they solve different problems.

### Amazon SQS

**Amazon Simple Queue Service (SQS)** is a managed message queue.

Use it when:

- Processing should happen asynchronously.
- Workers need to consume messages at their own pace.
- You need buffering during traffic spikes.
- Failed messages need retry and dead-letter handling.

```text
S3
 |
 v
SQS Queue
 |
 +---- Worker 1
 |
 +---- Worker 2
 |
 +---- Worker 3
```

SQS helps decouple producers from consumers.

### Amazon SNS

**Amazon Simple Notification Service (SNS)** is a pub/sub messaging service.

Use it when one event should be distributed to multiple subscribers.

```text
                 S3 Event
                    |
                    v
                  SNS
               /   |   \
              v    v    v
            SQS  Lambda Email/Other
```

SNS can fan out a notification to multiple subscribers.

### AWS Lambda

Lambda runs code in response to supported events without requiring you to manage EC2 servers.

Use it for:

- Image resizing.
- Lightweight validation.
- Metadata extraction.
- Event-driven file processing.
- Short background tasks.

Consider execution duration, memory, concurrency, payload size, and retry behavior when designing a Lambda workflow.

### Amazon EventBridge

EventBridge provides event routing and rules. S3 can send events to EventBridge after the feature is enabled for the bucket.

EventBridge can route events based on event patterns to supported targets and can support more flexible event-driven architectures.

### Comparison

| Service | Main purpose | Example |
|---|---|---|
| SQS | Queue messages for consumers | Buffer document-processing jobs |
| SNS | Publish to multiple subscribers | Notify multiple systems |
| Lambda | Run code in response to events | Generate thumbnails |
| EventBridge | Route events using rules | Route S3 events by event pattern |

### Choosing a design

| Requirement | Possible design |
|---|---|
| One simple processing task | S3 → Lambda |
| Buffer jobs for worker fleet | S3 → SQS → EC2/ECS worker |
| Notify several independent systems | S3 → SNS → subscribers |
| Flexible event filtering and routing | S3 → EventBridge → targets |
| Long-running or resource-heavy processing | S3 → SQS → ECS/EC2 workers |

## 7. S3 Replication in More Detail

Replication automatically copies eligible objects from a source bucket to a destination bucket.

### Same-Region Replication (SRR)

Copies objects to another bucket in the same AWS Region.

Possible use cases:

- Separate production and analytics buckets.
- Maintain another copy for a specific operational workflow.
- Centralize data for another application in the same Region.

### Cross-Region Replication (CRR)

Copies eligible objects to a bucket in a different Region.

Possible use cases:

- Geographic disaster recovery.
- Regional data access.
- Compliance or data distribution requirements.

### Replication architecture

```text
Source Bucket
Region A
    |
    | Replication configuration
    v
Destination Bucket
Region B
```

### Requirements and considerations

A typical replication configuration requires:

- Versioning enabled on source and destination buckets.
- A replication IAM role.
- A destination bucket.
- A replication rule.
- Appropriate ownership and encryption configuration.

Additional considerations:

- Replication is asynchronous.
- Replication does not mean every object is copied instantly.
- Existing objects may require S3 Batch Replication.
- Delete-marker replication behavior depends on configuration.
- Objects encrypted with customer-managed KMS keys require suitable KMS permissions and compatible configuration.
- Replication can incur storage, request, and data-transfer charges.
- Replication does not automatically protect against every type of logical deletion or malicious change.

### Replication vs backup

| Replication | Backup |
|---|---|
| Copies eligible changes to another bucket | Preserves recoverable copies according to a backup policy |
| Often asynchronous | Can use retention and isolation controls |
| May replicate unwanted changes | Can be designed to protect against accidental or malicious deletion |
| Useful for data distribution and regional resilience | Useful for recovery from data loss and corruption |

Replication can be part of a backup strategy, but should not automatically be treated as the only backup.

## 8. S3 Object Lock

**S3 Object Lock** helps prevent objects from being deleted or overwritten for a defined retention period or under a legal hold.

It is commonly used for records that must be retained for regulatory, legal, or governance reasons.

### Retention modes

| Mode | Meaning |
|---|---|
| Governance mode | Users with specific permissions can bypass retention |
| Compliance mode | Protected versions cannot be overwritten or deleted before retention expires, including by the account root user |
| Legal hold | Holds an object version until the legal hold is removed; it does not require a fixed end date |

### Governance mode

Governance mode protects objects from ordinary deletion, but specially authorized users can bypass governance retention when the required permission and request settings are used.

Use this when controlled administrative override is required.

### Compliance mode

Compliance mode provides stronger protection. A protected object version cannot be overwritten or deleted before the retention period expires, including by the account root user.

Use it only when the retention requirement is understood and approved.

### Legal hold

A legal hold can be applied independently of a fixed retention period. It remains in effect until an authorized user removes it.

### Important warnings

- Object Lock is configured for a bucket with Object Lock enabled.
- Retention settings can have significant legal and operational consequences.
- Compliance-mode retention cannot simply be shortened by an administrator.
- Object Lock does not eliminate the need for access controls, encryption, monitoring, and recovery planning.
- Test the configuration in a dedicated environment before using it for regulated records.

## 9. S3 Access Points

An **S3 Access Point** is a named network endpoint with its own access policy for accessing objects in a bucket.

Access Points can simplify access management when many applications or teams use the same bucket.

### Without Access Points

A large bucket policy may become difficult to manage when many applications need different permissions.

### With Access Points

```text
                  S3 Bucket
                      |
          +-----------+-----------+
          |           |           |
          v           v           v
      Access Point A  Access B  Access C
      Analytics       Finance   Upload API
          |           |           |
          v           v           v
      Analytics      Finance    Spring Boot
      Application    Service    Application
```

Each Access Point can have a policy that scopes access to a particular application or use case.

### Benefits

- Separate access policies for different teams.
- Easier management of application-specific access.
- Support for network-origin restrictions through supported Access Point configurations.
- Better organization of shared-bucket access patterns.

### Important notes

- An Access Point does not create a separate copy of the objects.
- The underlying bucket policy and other applicable access controls still matter.
- Access Point policy permissions do not override explicit denies or other security restrictions.
- VPC-origin Access Points can restrict access to requests originating through a specified VPC, subject to the service configuration.

## 10. Presigned URLs in More Depth

A presigned URL grants temporary permission to perform a specific S3 operation.

Common uses:

- Upload a file directly from a browser.
- Download a private document.
- Share a file temporarily with an authorized recipient.

### Download flow

```text
User
 |
 | 1. Request document
 v
Spring Boot API
 |
 | 2. Authenticate and authorize user
 v
Generate presigned GET URL
 |
 | 3. Return temporary URL
 v
User Browser
 |
 | 4. HTTPS GET
 v
Amazon S3
```

### Security rules

- Use short expiration times appropriate to the task.
- Generate the URL only after authenticating and authorizing the user.
- Restrict the bucket and object key.
- Do not log or expose the URL unnecessarily.
- Treat the URL as a bearer credential.
- Remember that the underlying IAM or bucket permissions must allow the signed operation.
- A URL cannot grant more permissions than the signing principal has.
- A presigned URL may stop working if the credentials used to sign it expire or are revoked.

### Upload with presigned URLs

For a direct browser upload:

1. The client asks the backend to start an upload.
2. The backend authenticates the user.
3. The backend chooses a safe object key.
4. The backend generates a presigned PUT URL.
5. The client uploads directly to S3.
6. The backend verifies the uploaded object and records metadata.

Do not trust the client to choose arbitrary bucket names or object keys.

### Spring Boot example: presigned GET URL

Maven dependency:

```xml
<dependency>
    <groupId>software.amazon.awssdk</groupId>
    <artifactId>s3</artifactId>
</dependency>
<dependency>
    <groupId>software.amazon.awssdk</groupId>
    <artifactId>s3-presigner</artifactId>
</dependency>
```

Create a presigner:

```java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import software.amazon.awssdk.regions.Region;
import software.amazon.awssdk.services.s3.presigner.S3Presigner;

@Configuration
public class S3PresignerConfig {

    @Bean
    public S3Presigner s3Presigner() {
        return S3Presigner.builder()
                .region(Region.AP_SOUTHEAST_1)
                .build();
    }
}
```

Service method:

```java
import java.time.Duration;

import org.springframework.stereotype.Service;

import software.amazon.awssdk.services.s3.model.GetObjectRequest;
import software.amazon.awssdk.services.s3.presigner.S3Presigner;
import software.amazon.awssdk.services.s3.presigner.model.GetObjectPresignRequest;
import software.amazon.awssdk.services.s3.presigner.model.PresignedGetObjectRequest;

@Service
public class S3PresignedUrlService {

    private final S3Presigner presigner;

    public S3PresignedUrlService(S3Presigner presigner) {
        this.presigner = presigner;
    }

    public String createDownloadUrl(String bucket, String key) {
        GetObjectRequest getObjectRequest = GetObjectRequest.builder()
                .bucket(bucket)
                .key(key)
                .build();

        GetObjectPresignRequest presignRequest =
                GetObjectPresignRequest.builder()
                        .signatureDuration(Duration.ofMinutes(10))
                        .getObjectRequest(getObjectRequest)
                        .build();

        PresignedGetObjectRequest presigned =
                presigner.presignGetObject(presignRequest);

        return presigned.url().toString();
    }
}
```

This is a teaching example. Before returning a URL, the application must verify that the current user is allowed to access that exact object. The bucket name and key should come from trusted server-side records, not directly from an untrusted request.

## 11. S3 Static Website Hosting and CloudFront

S3 can host static website content such as HTML, CSS, JavaScript, and images.

### S3 static website hosting

A bucket can be configured for static website hosting with an index document and optional error document.

Important considerations:

- The S3 website endpoint is an HTTP website endpoint, not an HTTPS endpoint.
- Direct website hosting commonly requires public-read access to website content.
- Public bucket access is not suitable for private application documents.
- Website hosting is not a replacement for a dynamic application server.

### CloudFront in front of S3

For production static content, a common design is CloudFront with a private S3 origin and Origin Access Control (OAC).

```text
                  Website Visitor
                         |
                         | HTTPS
                         v
                     CloudFront
                         |
                         | Origin Access Control
                         v
                    Private S3 Bucket
                         |
                 HTML / CSS / JS / Images
```

Benefits:

- HTTPS delivery.
- Edge caching.
- Reduced repeated origin requests.
- Custom domain support.
- Better control over access to the origin bucket.

### Static website hosting vs CloudFront

| Feature | S3 website endpoint | CloudFront + private S3 origin |
|---|---|---|
| HTTPS | Website endpoint does not provide HTTPS directly | Supports HTTPS |
| Caching | Basic object caching behavior | Configurable edge caching |
| Private origin access | Website endpoint commonly uses public content | OAC can keep the S3 origin private |
| Custom domain | Additional DNS and TLS considerations | Commonly supported with an appropriate certificate |
| Dynamic backend | Not supported by S3 static hosting itself | Requires an origin or backend service |

For a private document system, do not make the bucket public just to serve files. Use authenticated APIs or carefully scoped presigned URLs.

## 12. S3 Cost Optimization

S3 cost is not only the amount of data stored.

Potential cost components include:

- Storage by storage class.
- Requests.
- Data retrieval.
- Data transfer.
- Replication.
- Monitoring features.
- Data processing integrations.
- Minimum storage duration and minimum billable object size for some classes.

### Cost optimization techniques

1. Choose a storage class based on real access patterns.
2. Use lifecycle policies for aging data.
3. Abort incomplete multipart uploads.
4. Remove unnecessary object versions according to retention policy.
5. Avoid storing duplicate files unnecessarily.
6. Use CloudFront caching for frequently downloaded public content.
7. Review replication scope and destination retention.
8. Monitor request patterns and data transfer.
9. Use S3 Storage Lens or other appropriate visibility tools.
10. Set budgets and alerts for relevant services.

### Example lifecycle design

```text
Recently uploaded data
        |
        v
    S3 Standard
        |
        | after access declines
        v
  Intelligent-Tiering
        |
        | long-term archive requirement
        v
 Appropriate Glacier class
        |
        | retention expires and policy allows
        v
      Expiration
```

This is only an example. Actual transitions should be based on measured access patterns, retrieval needs, and legal retention.

### Small-object consideration

For millions of very small objects, request overhead and per-object management can matter. Consider whether your application can safely combine small records into larger objects, while preserving the access and update behavior it needs.

Do not combine files if doing so makes authorization, retrieval, or lifecycle management more complicated than the cost savings justify.

## 14. Hands-on Lab: Event-Driven File Processing Design

### Lab objective

Design a workflow that automatically processes an uploaded document.

The system will:

1. Receive a file upload.
2. Store the original file in S3.
3. Send an event to a queue.
4. Process the file asynchronously.
5. Store the result in a separate prefix.
6. Record processing status.

This lab focuses on the architecture and safe design. Creating SQS queues, Lambda functions, event notifications, and related IAM roles in a live AWS account can incur charges.

### Step 1 — Choose bucket prefixes

Use separate prefixes:

```text
incoming/
processed/
rejected/
```

The event rule should watch only `incoming/`.

The worker writes outputs to `processed/` or `rejected/`, avoiding a notification loop.

### Step 2 — Design the event flow

```text
Client
  |
  v
Spring Boot API
  |
  v
S3: incoming/
  |
  | ObjectCreated
  v
SQS Queue
  |
  v
Worker
  |
  +---- Valid ----> S3: processed/
  |
  +---- Invalid --> S3: rejected/
  |
  v
Database: processing status
```

### Step 3 — Configure permissions

The uploader role should have only the required upload permissions for the `incoming/` prefix.

The worker role may need:

- Permission to read objects in `incoming/`.
- Permission to write objects in `processed/` and `rejected/`.
- Permission to consume messages from the SQS queue.
- Permission to write processing status to the chosen database, if required.

Avoid granting `s3:*` or `sqs:*` unless there is a reviewed and justified need.

### Step 4 — Make processing idempotent

S3 notifications and queue processing can result in duplicate work. Use a unique processing record, such as a combination of bucket, object key, and version ID.

Before processing:

1. Check whether that exact object version has already been processed.
2. If completed, acknowledge the message without repeating side effects.
3. If not completed, process it and store the result.
4. Record success or failure.

### Step 5 — Handle failures

Configure:

- Retry behavior.
- A dead-letter queue.
- Visibility timeout appropriate to processing duration.
- Monitoring for queue depth and age of oldest message.
- Alerting for repeated failures.

Do not delete a queue message until processing has completed successfully.

### Step 6 — Protect uploaded files

Validate file size, content, and expected format. Consider malware scanning for untrusted uploads. Keep original files private and restrict access to processed outputs.

### Step 7 — Test the workflow

Test:

- A valid document.
- An invalid file type.
- A file that causes a processing error.
- Duplicate event delivery.
- A worker restart during processing.
- A large file.
- A message that reaches the dead-letter queue.

### Step 8 — Clean up

After the lab, inspect the bucket, queue, worker, logs, and any other resources. Delete only resources created for the lab and only after confirming that no required data remains.

## 15. Common S3 Advanced Mistakes

1. Using simple uploads for very large files when multipart upload would be more resilient.
2. Forgetting to abort abandoned multipart uploads.
3. Enabling Transfer Acceleration without measuring the improvement.
4. Assuming S3 notifications are delivered exactly once and in order.
5. Creating a notification loop by writing output into the watched prefix.
6. Building event consumers that cannot handle duplicate messages.
7. Assuming replication is immediate.
8. Treating replication as a complete backup.
9. Enabling Compliance-mode Object Lock without an approved retention design.
10. Returning presigned URLs without checking the user's authorization.
11. Making a bucket public to serve private documents.
12. Forgetting that S3 website endpoints do not provide HTTPS directly.
13. Using CloudFront without restricting direct origin access when private origin behavior is required.
14. Ignoring data retrieval and request charges when selecting a storage class.

## 16. Practical Exercises

### Exercise 1 — Multipart upload

**Question:** Why use multipart upload for a large file?

**Answer:** It allows the file to be uploaded in parts, supports parallel transfer, and allows failed parts to be retried without restarting the entire upload.

### Exercise 2 — Incomplete uploads

**Question:** How can you clean up abandoned multipart uploads?

**Answer:** Abort them explicitly or configure an S3 Lifecycle rule to abort incomplete multipart uploads after an appropriate period.

### Exercise 3 — Transfer Acceleration

**Question:** When should you evaluate S3 Transfer Acceleration?

**Answer:** When users are geographically distant from the bucket and testing indicates that the AWS edge network can improve upload or download performance enough to justify the cost.

### Exercise 4 — Event notifications

**Question:** What event can trigger image processing after an upload?

**Answer:** An S3 object-created event can trigger a configured destination such as Lambda, SQS, SNS, or EventBridge.

### Exercise 5 — Event loop

**Question:** How can you prevent a Lambda function from repeatedly triggering itself?

**Answer:** Use separate input and output prefixes or buckets, and configure event filters to watch only the intended input objects.

### Exercise 6 — SQS

**Question:** Why put SQS between S3 and a worker?

**Answer:** SQS buffers jobs, decouples upload traffic from processing capacity, and supports retry and dead-letter handling.

### Exercise 7 — Replication

**Question:** Does Cross-Region Replication copy every old object automatically when first enabled?

**Answer:** Not necessarily. Existing objects may require S3 Batch Replication. Check the replication setup and use the appropriate process for existing data.

### Exercise 8 — Object Lock

**Question:** What is the difference between Governance and Compliance retention modes?

**Answer:** Governance mode can be bypassed by specially authorized users. Compliance mode provides stronger retention protection that cannot be bypassed or shortened before expiry, including by the account root user.

### Exercise 9 — Access Points

**Question:** What is the main benefit of S3 Access Points?

**Answer:** They provide named endpoints with separate access policies, making it easier to manage different applications or teams accessing a shared bucket.

### Exercise 10 — Presigned URL

**Question:** Why should a presigned URL be treated like a secret?

**Answer:** Anyone who obtains it may be able to perform the signed operation until it expires or becomes invalid.

### Exercise 11 — CloudFront

**Question:** Why put CloudFront in front of a private S3 bucket?

**Answer:** CloudFront can deliver content over HTTPS, cache it at edge locations, and use Origin Access Control to access a private S3 origin.

### Exercise 12 — Idempotency

**Question:** Why should an S3 event-processing worker be idempotent?

**Answer:** Notifications or queue messages can be delivered more than once. Idempotency prevents duplicate processing from creating incorrect or repeated side effects.

## 19. AWS Interview Questions and Answers

### Q1. What is multipart upload?

Multipart upload divides a large object into parts. Each part can be uploaded independently, and S3 combines them when the upload is completed.

### Q2. What happens if a multipart upload is never completed?

Uploaded parts can remain and incur storage charges. Abort the upload or configure a lifecycle rule to clean up incomplete multipart uploads.

### Q3. What is S3 Transfer Acceleration?

It is an S3 feature that can improve transfer performance for geographically distant clients by using AWS edge network infrastructure.

### Q4. What are S3 event notifications?

They are notifications generated for supported S3 events, such as object creation or removal, and delivered to configured destinations.

### Q5. Are S3 event notifications guaranteed to be delivered exactly once and in order?

Do not design on that assumption. Consumers should tolerate duplicate and out-of-order events and should use idempotent processing.

### Q6. What is the difference between SQS and SNS?

SQS is a queue that stores messages for consumers to process. SNS is a pub/sub service that distributes messages to subscribers.

### Q7. When would you use Lambda with S3?

Use Lambda for event-driven tasks such as image resizing, metadata extraction, validation, and other supported short-running processing tasks.

### Q8. What is Cross-Region Replication?

CRR copies eligible objects from a source S3 bucket to a destination bucket in another Region, subject to replication configuration and permissions.

### Q9. Does replication replace backups?

No. Replication can copy unwanted changes or deletions depending on configuration. Use an appropriate backup, retention, and recovery strategy.

### Q10. What is S3 Object Lock?

Object Lock helps prevent object versions from being deleted or overwritten for a retention period or while a legal hold is active.

### Q11. What is the difference between Governance and Compliance mode?

Governance mode can be bypassed by specially authorized users. Compliance mode provides stronger retention protection and cannot be bypassed before the retention period expires.

### Q12. What is an S3 Access Point?

It is a named endpoint with its own access policy for accessing objects in an S3 bucket. It can simplify access management for multiple applications or teams.

### Q13. What is a presigned URL?

A presigned URL grants temporary permission to perform a specified S3 operation. It is commonly used for private file uploads and downloads.

### Q14. How can CloudFront securely serve a private S3 bucket?

Configure CloudFront with Origin Access Control and a bucket policy that permits the intended CloudFront distribution to access the origin. Keep direct public access blocked.

### Q15. How do you prevent duplicate S3 event processing?

Use idempotency keys based on the bucket, object key, and version ID or another stable event identity. Record processing state and make repeated processing safe.

### Q16. How would you design a scalable file-processing system?

Store uploaded files in S3, send object-created events to SQS, process them with a scalable worker fleet or Lambda, write outputs to a separate prefix, and store processing status in a database. Add retries, a dead-letter queue, monitoring, and idempotency.
