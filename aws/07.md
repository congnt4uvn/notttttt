# PART 1 — Detailed revision

## 2. DAY 1: Introduction to Cloud Computing

### 2.1 What is Cloud Computing?

Cloud Computing is the delivery of computing resources over the internet.

Instead of purchasing and maintaining physical servers, companies can rent computing resources from cloud providers such as AWS.

Examples of computing resources:

- Compute power.
- Storage.
- Databases.
- Networking.
- Security.
- Machine Learning.
- Monitoring.

### 2.2 On-Premises vs Cloud Computing

| Category           | On-Premises            | Cloud Computing                     |
| ------------------ | ---------------------- | ----------------------------------- |
| Infrastructure     | Company-owned          | Cloud provider                      |
| Hardware           | Purchase hardware      | Rent resources                      |
| Maintenance        | Company                | Shared responsibilities             |
| Scalability        | Requires hardware      | Flexible scaling                    |
| Initial investment | Usually high           | Usually lower                       |
| Cost model         | Often CapEx            | Often OpEx                          |
| Availability       | Company designs it     | Cloud services provide capabilities |
| Deployment         | Can take days or weeks | Often much faster                   |

### 2.3 CapEx vs OpEx

| Concept | Meaning                 | Example                          |
| ------- | ----------------------- | -------------------------------- |
| CapEx   | Capital Expenditure     | Buying physical servers          |
| OpEx    | Operational Expenditure | Paying monthly AWS usage charges |

Real-world example:

A startup wants to deploy a Spring Boot application.

Option A: Purchase servers, networking equipment, and storage.

Option B: Launch an EC2 instance, use RDS, and store files in S3.

The second option allows the startup to start with less infrastructure investment.

## 3. DAY 2: Cloud Deployment Models

There are four common deployment models.

| Model         | Description                                            | Example                                |
| ------------- | ------------------------------------------------------ | -------------------------------------- |
| Public Cloud  | Shared cloud infrastructure operated by a provider     | AWS                                    |
| Private Cloud | Cloud infrastructure dedicated to an organization      | Private VMware-based cloud             |
| Hybrid Cloud  | Combination of private infrastructure and public cloud | On-premises database + AWS application |
| Multi-Cloud   | Using multiple cloud providers                         | AWS + Azure                            |

### 3.1 Architecture examples

Public Cloud

```

Internet

  v
AWS Cloud
```

Hybrid Cloud

```
      AWS Cloud

    Secure VPN Connection

          |
```

Multi-Cloud

```
             Users

               v
          Application
               |
       +-------+-------+
       |               |
       v               v
   AWS Cloud        Azure Cloud
       |               |
       v               v
    Database        Analytics
```

### 3.2 When should companies use each model?

| Situation                                       | Recommended model |
| ----------------------------------------------- | ----------------- |
| New startup with no existing infrastructure     | Public Cloud      |
| Organization requiring dedicated infrastructure | Private Cloud     |
| Company migrating gradually from on-premises    | Hybrid Cloud      |
| Organization using multiple cloud providers     | Multi-Cloud       |

## 4. DAY 3: Cloud Service Models

There are three fundamental service models.

### 4.1 IaaS — Infrastructure as a Service

AWS provides virtual infrastructure.

Example: Amazon EC2.

You manage:

- Operating system.
- Runtime.
- Application.
- Application data.
- Security configuration.

### 4.2 PaaS — Platform as a Service

AWS provides a managed application platform.

Examples include AWS Elastic Beanstalk and AWS App Runner.

You mainly focus on application deployment, configuration, and application-level security.

### 4.3 SaaS — Software as a Service

You consume a complete software application.

Examples include Amazon QuickSight and other managed business applications.

### Comparison

| Feature                   | IaaS     | PaaS               | SaaS                                    |
| ------------------------- | -------- | ------------------ | --------------------------------------- |
| Infrastructure            | Provider | Provider           | Provider                                |
| Operating system          | Customer | Generally provider | Provider                                |
| Runtime                   | Customer | Generally provider | Provider                                |
| Application               | Customer | Customer           | Provider                                |
| Data responsibility       | Customer | Customer           | Customer's data responsibilities remain |
| Flexibility               | High     | Medium             | Lower                                   |
| Infrastructure management | High     | Lower              | Minimal                                 |

### 4.4 Which model should you choose?

Imagine you have a Java Spring Boot application.

| Requirement                              | Suitable approach |
| ---------------------------------------- | ----------------- |
| Full control of Linux and Java           | EC2 / IaaS        |
| Easier application deployment            | Elastic Beanstalk |
| Managed container application deployment | App Runner        |
| Fully managed software consumption       | SaaS              |

Remember: Real AWS services can have responsibilities that do not fit perfectly into a simple IaaS/PaaS/SaaS classification.

## 5. DAY 4: AWS Global Infrastructure

AWS operates infrastructure in multiple geographical locations.

Three important concepts:

- Region.
- Availability Zone.
- Edge Location.

### 5.1 Region

A Region is a separate geographical area containing multiple Availability Zones.

Examples:

| AWS Region            | Region code      |
| --------------------- | ---------------- |
| Singapore             | `ap-southeast-1` |
| Tokyo                 | `ap-northeast-1` |
| Seoul                 | `ap-northeast-2` |
| Sydney                | `ap-southeast-2` |
| US East (N. Virginia) | `us-east-1`      |

### 5.2 Availability Zone

An Availability Zone (AZ) consists of one or more isolated data centers within an AWS Region.

Using multiple AZs can improve application availability.

Example:

```
             AWS Region
           ap-southeast-1
                  |
        +---------+---------+
        |                   |
        v                   v
   Availability Zone A  Availability Zone B
        |                   |
        v                   v
      EC2 A               EC2 B
        |                   |
        +---------+---------+
                  |
                  v
             Load Balancer
```

### 5.3 Edge Location

An Edge Location helps deliver content closer to users through services such as Amazon CloudFront.

Example:

A user in Vietnam requests an image from a website.

CloudFront can serve cached content from an appropriate edge location instead of always retrieving it from the origin server.

### 5.4 Regional vs Global services

| Service    | Scope                                              |
| ---------- | -------------------------------------------------- |
| Amazon EC2 | Regional                                           |
| Amazon RDS | Regional                                           |
| Amazon VPC | Regional                                           |
| Amazon S3  | Regional service with globally unique bucket names |
| IAM        | Global                                             |
| Route 53   | Global                                             |
| CloudFront | Global                                             |

### 5.5 High Availability vs Fault Tolerance

| Concept           | Meaning                                       |
| ----------------- | --------------------------------------------- |
| High Availability | Minimize service downtime                     |
| Fault Tolerance   | Continue operating despite specified failures |
| Disaster Recovery | Restore operations after a major disruption   |
| Scalability       | Handle changing workload demands              |

Remember: Multi-AZ architecture is commonly used to improve availability, while Multi-Region architecture can support disaster recovery and geographic resilience.

### 6.3 Authentication and Authorization

| Concept        | Meaning                                                      |
| -------------- | ------------------------------------------------------------ |
| Authentication | Verify identity                                              |
| Authorization  | Verify permissions                                           |
| IAM User       | An IAM identity for a person or application where applicable |
| IAM Role       | An identity that provides temporary permissions              |
| IAM Policy     | A document defining permissions                              |

Recommended security practices:

- Enable MFA for the root user.
- Avoid using root credentials for everyday tasks.
- Prefer IAM Identity Center for human access.
- Prefer IAM roles and temporary credentials for workloads.
- Apply least privilege.
- Never commit AWS access keys to Git.

## 7. DAY 6: AWS Shared Responsibility Model

AWS and customers share responsibility for security.

### 7.1 Security of the Cloud

AWS manages:

- Physical data centers.
- Physical servers.
- Physical networking.
- Hardware.
- Underlying infrastructure.

### 7.2 Security in the Cloud

Customers manage or configure:

- Application code.
- Customer data.
- IAM permissions.
- Network access.
- Application authentication.
- Service security settings.
- Operating systems where applicable.

### 7.3 Compare responsibility by service

| Responsibility            | EC2      | RDS      | S3       | Lambda   |
| ------------------------- | -------- | -------- | -------- | -------- |
| Physical infrastructure   | AWS      | AWS      | AWS      | AWS      |
| Guest OS                  | Customer | AWS      | AWS      | AWS      |
| Application code          | Customer | Customer | N/A      | Customer |
| Data access configuration | Customer | Customer | Customer | Customer |
| Service infrastructure    | AWS      | AWS      | AWS      | AWS      |

Key principle: More managed services reduce infrastructure management, but customers still have responsibilities for their applications, data, permissions, and configurations.

# PART 2 — Practical architecture scenarios

## 8. Scenario 1: Deploy a Spring Boot application on AWS

Business requirement:

A company wants to deploy an e-commerce application.

Requirements:

- Java Spring Boot backend.
- PostgreSQL database.
- Product images.
- Secure network access.
- High availability.
- Application monitoring.

### Recommended architecture

```
                       Internet
                          |
                          v
                    Route 53
                          |
                          v
                  Application Load
                     Balancer
                          |
              +-----------+-----------+
              |                       |
              v                       v
        Availability Zone A     Availability Zone B
              |                       |
              v                       v
            EC2 A                   EC2 B
         Spring Boot             Spring Boot
              |                       |
              +-----------+-----------+
                          |
              +-----------+-----------+
              |                       |
              v                       v
          Amazon RDS              Amazon S3
          PostgreSQL            Product Images
              |
              v
        Automated Backups
```

### Component responsibilities

| Component                 | Purpose                         |
| ------------------------- | ------------------------------- |
| Route 53                  | DNS management                  |
| Application Load Balancer | Distribute HTTP/HTTPS requests  |
| EC2                       | Run Spring Boot application     |
| RDS                       | Store relational data           |
| S3                        | Store product images            |
| IAM Role                  | Provide application permissions |
| CloudWatch                | Monitor logs and metrics        |

### Security configuration

1. EC2 instances should not expose unnecessary ports.
2. Only the load balancer should accept public application traffic.
3. RDS should be private and accessible from the application security group.
4. EC2 should use an IAM role to access S3.
5. S3 should block public access unless public access is specifically needed.
6. Use HTTPS for external application traffic.
7. Store database credentials in Secrets Manager or another secure secret-management solution.

## 9. Scenario 2: A company wants to migrate from on-premises to AWS

Current infrastructure:

```
Company Data Center
   |
   +-- Physical Servers
   +-- MySQL Database
   +-- File Storage
   +-- Internal Network
```

The company wants to migrate gradually.

### Recommended approach: Hybrid Cloud

```
               Company Users
                     |
                     v
             Company Network
                     |
                     v
             VPN / Direct Connect
                     |
             +-------+-------+
             |               |
             v               v
       On-Premises         AWS Cloud
             |               |
             v               v
       Legacy Database    Spring Boot API
                             |
                             v
                         Amazon S3
```

Why hybrid?

- Existing systems can continue operating.
- New applications can run on AWS.
- Data migration can happen gradually.
- The company avoids migrating everything at once.

## 10. Scenario 3: A startup wants to minimize infrastructure management

Business requirement:

A startup has a small development team and wants to deploy a Java application without managing virtual machines.

Possible solution:

- AWS App Runner for the containerized Spring Boot application.
- Amazon RDS for PostgreSQL.
- Amazon S3 for file storage.
- IAM for permissions.
- CloudWatch for monitoring.

Architecture:

```
        Internet
           |
           v
      AWS App Runner
           |
           v
      Spring Boot API
           |
       +---+---+
       |       |
       v       v
      RDS     S3
       |
       v
    Database
```

This reduces server management compared with deploying directly on EC2.

## 15. Exercise 4: Architecture questions

Question 1: You need to deploy a Spring Boot application. You want complete control over the operating system. Which service should you use?

Answer: Amazon EC2.

Reason: EC2 provides virtual machines where you manage the guest operating system.

Question 2: Your application needs to store uploaded PDF documents.

Answer: Amazon S3.

Reason: S3 is designed for object storage.

Question 3: Your application needs a managed PostgreSQL database.

Answer: Amazon RDS for PostgreSQL.

Reason: RDS provides managed relational database infrastructure.

Question 4: Your application must remain available if one Availability Zone experiences a failure.

Answer: Design a Multi-AZ architecture.

Reason: Distributing workloads across multiple AZs can reduce the impact of an AZ failure.

Question 5: Your Spring Boot application running on EC2 needs access to S3. What should you use?

Answer: An IAM role attached to the EC2 instance.

Reason: The role provides temporary credentials without hardcoding access keys.

Question 6: A company wants to migrate gradually from its data center to AWS.

Answer: Hybrid Cloud.

Reason: It allows on-premises infrastructure and AWS to operate together during migration.

# PART 5 — Interview questions and answers

## 16. AWS fundamentals interview preparation

Q1. What is AWS?

Answer:

AWS is a cloud computing platform that provides services such as computing, storage, databases, networking, security, and machine learning.

Q2. What is the difference between EC2 and Lambda?

Answer:

EC2 provides virtual machines where customers manage the operating system and application environment. Lambda runs code without customers managing the underlying servers.

Q3. What is the difference between an AWS Region and an Availability Zone?

Answer:

A Region is a geographical area containing multiple Availability Zones. An Availability Zone is an isolated location within a Region.

Q4. What is the difference between S3 and EBS?

Answer:

S3 is object storage used for files and unstructured data. EBS provides block storage volumes that can be attached to EC2 instances.

Q5. What is High Availability?

Answer:

High Availability is the ability of a system to minimize downtime and remain accessible despite certain failures.

Q6. What is the AWS Shared Responsibility Model?

Answer:

It defines how security responsibilities are divided between AWS and customers. AWS secures the underlying cloud infrastructure, while customers secure their applications, data, and configurations.

Q7. What is the difference between AWS CLI and AWS SDK?

Answer:

AWS CLI is used to manage AWS resources through terminal commands. AWS SDK provides programming libraries that allow applications to interact with AWS services.

Q8. What is Multi-Cloud?

Answer:

Multi-Cloud is an architecture that uses multiple cloud providers, such as AWS and Azure.

Q9. Why do we use IAM roles?

Answer:

IAM roles provide temporary permissions to users or workloads, helping avoid the need to store long-lived access keys in applications.

Q10. How would you design a highly available Spring Boot application on AWS?

Answer:

I would deploy the application across multiple Availability Zones using an Application Load Balancer. I would use Amazon RDS with Multi-AZ deployment for database availability, S3 for file storage, IAM roles for secure access, and CloudWatch for monitoring.
