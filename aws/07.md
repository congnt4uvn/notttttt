## 2. Review: Cloud Computing Fundamentals

### 2.1 What is cloud computing?

Cloud computing is the on-demand delivery of computing resources over a network, usually the internet, with usage-based pricing.

Common resources include:

- Compute
- Storage
- Databases
- Networking
- Security
- Analytics
- Application services

Instead of buying and maintaining all physical infrastructure, an organization can use cloud services when needed.

### 2.2 Main benefits

| Benefit | Explanation | Example |
|---|---|---|
| On-demand resources | Provision resources when needed | Launch an EC2 instance |
| Pay-as-you-go | Pay according to usage and pricing rules | Pay for storage consumed |
| Scalability | Increase or decrease capacity | Add application instances |
| Elasticity | Adjust capacity as demand changes | Scale out during a traffic peak |
| Global reach | Deploy in multiple geographic areas | Serve users from suitable Regions |
| Managed services | Reduce infrastructure administration | Use Amazon RDS |
| Agility | Provision resources faster | Create a test environment quickly |

Cloud does not automatically mean that every workload is cheaper. Costs depend on architecture, usage, data transfer, licensing, operations, and service selection.

### 2.3 On-premises vs cloud

| Topic | On-premises | Cloud |
|---|---|---|
| Hardware | Organization buys and owns it | Provider supplies cloud infrastructure |
| Initial investment | Often high | Often lower initial infrastructure investment |
| Maintenance | Organization maintains physical infrastructure | Provider maintains cloud physical infrastructure |
| Scaling | May require purchasing hardware | Often faster to provision resources |
| Capacity planning | Plan and purchase ahead | Can provision and adjust capacity |
| Control | Direct control over physical environment | Control depends on service model |

### 2.4 CapEx vs OpEx

- **CapEx (Capital Expenditure):** Spending on long-term assets, such as servers and data-centre equipment.
- **OpEx (Operational Expenditure):** Ongoing operating expenses, such as service usage, support, and operations.

Cloud adoption can shift some spending from large upfront infrastructure purchases toward operating expenses. It does not mean every cloud cost is automatically OpEx for accounting purposes; accounting treatment depends on the contract and applicable accounting standards.

## 3. Review: Cloud Deployment Models

### 3.1 Public Cloud

Cloud services are provided over a shared provider infrastructure, with logical separation between customers.

Example: A company runs its application using AWS services.

### 3.2 Private Cloud

Cloud infrastructure is dedicated to one organization. It may be operated by the organization or a service provider.

Example technologies can include VMware-based private cloud platforms or OpenStack.

### 3.3 Hybrid Cloud

Hybrid cloud combines private infrastructure with public cloud services, with connectivity or integration between them.

Example:

```text
Company data centre
        |
        | VPN / Direct Connect
        |
        v
AWS VPC
        |
        +-- Application services
        +-- Storage
        +-- Backup or recovery services
```

### 3.4 Multi-Cloud

Multi-cloud means using services from more than one cloud provider.

Example: An organization uses AWS for its application platform and another cloud provider for a separate analytics workload.

### 3.5 Comparison

| Model | Main idea | Example use case |
|---|---|---|
| Public cloud | Use services from a public cloud provider | Host a web application on AWS |
| Private cloud | Dedicated cloud environment for one organization | Workloads requiring dedicated infrastructure |
| Hybrid cloud | Connect private infrastructure and public cloud | Keep selected systems on-premises while using AWS |
| Multi-cloud | Use multiple cloud providers | Use different providers for different business needs |

**Remember:** Hybrid cloud describes a combination of private and public environments. Multi-cloud describes the use of multiple cloud providers. A company can use both.

## 4. Review: Cloud Service Models

The three main service models describe how much of the technology stack the provider manages.

### 4.1 IaaS — Infrastructure as a Service

The provider supplies virtual infrastructure. The customer manages more of the software stack.

Example: Amazon EC2.

Typical customer responsibilities include:

- Guest operating system.
- OS updates and patches.
- Runtime and middleware.
- Application code.
- Application data.
- Workload configuration.

### 4.2 PaaS — Platform as a Service

The provider manages more of the underlying platform so developers can focus on deploying and operating applications.

Example: AWS Elastic Beanstalk is commonly described as PaaS-like.

The customer still manages application code, data, permissions, and service configuration.

### 4.3 SaaS — Software as a Service

The provider delivers a complete application.

Examples:

- Salesforce
- Microsoft 365
- Google Workspace
- Slack

The customer manages users, access, settings, and business data according to the product's capabilities.

### 4.4 Comparison

| Topic | IaaS | PaaS | SaaS |
|---|---|---|---|
| Provides | Virtual infrastructure | Managed application platform | Complete application |
| Customer control | High | Medium | Lower |
| Infrastructure work for customer | More | Less | Usually least |
| Customer focus | OS, runtime, application, data | Application, configuration, data | Use and configure the application |
| Example | Amazon EC2 | Elastic Beanstalk (PaaS-like) | Salesforce |

### 4.5 Related concept: Serverless

Serverless does not mean there are no servers. It means the provider manages server provisioning and much of the underlying infrastructure.

AWS Lambda is a serverless function-compute service, often described as FaaS (Function as a Service). Customers still manage function code, permissions, triggers, application logic, and data access.

## 5. Review: AWS Global Infrastructure

### 5.1 Region

A Region is a separate geographic area where AWS operates infrastructure.

Examples:

- `ap-southeast-1` — Asia Pacific (Singapore)
- `ap-southeast-2` — Asia Pacific (Sydney)
- `ap-northeast-1` — Asia Pacific (Tokyo)
- `us-east-1` — US East (N. Virginia)

Choose a Region based on latency, service availability, cost, compliance, connectivity, and resilience requirements.

### 5.2 Availability Zone

An Availability Zone (AZ) is an isolated location within an AWS Region, consisting of one or more discrete data centres.

Deploying application resources across multiple AZs can improve availability if the application and its dependencies are designed for failover.

### 5.3 Edge Location

An Edge Location is part of AWS's edge network. Services such as CloudFront use the edge network to deliver content closer to users.

### 5.4 Quick comparison

| Concept | Meaning | Main purpose |
|---|---|---|
| Region | Geographic AWS area | Regional deployment |
| Availability Zone | Isolated location within a Region | Availability and fault isolation |
| Edge Location | Site in AWS's edge network | Content delivery closer to users |

### 5.5 High availability and disaster recovery

- **High Availability (HA):** Design a service to remain accessible with minimal interruption.
- **Fault tolerance:** Continue operating despite certain component failures.
- **Disaster Recovery (DR):** Restore service after a major disruption.
- **RTO:** Target time to restore service.
- **RPO:** Target maximum data-loss window measured in time.

Example:

```text
Users
  |
  v
Application Load Balancer
  |
  +--------------------+
  |                    |
  v                    v
AZ-A                  AZ-B
EC2                   EC2
  |                    |
  +---------+----------+
            |
            v
       RDS Multi-AZ
```

Multi-AZ improves resilience within a Region. Multi-Region designs may support geographic disaster recovery, but introduce additional complexity.

## 6. Review: AWS Account and Management Tools

### 6.1 AWS account

An AWS account is a boundary for resources, identities, permissions, and billing.

Organizations may use multiple accounts to separate development, testing, production, teams, or business units.

### 6.2 Root user, IAM user, and IAM role

| Identity | Description | Typical use |
|---|---|---|
| Root user | Original identity for an AWS account with unrestricted account access | Account tasks that specifically require root |
| IAM user | Identity in an AWS account with configured credentials and permissions | Limited or legacy use cases |
| IAM role | Assumable identity that provides temporary credentials | AWS workloads and federated access |

Security recommendations:

- Protect the root user with MFA.
- Avoid using root for everyday tasks.
- Prefer federated access for human users where appropriate.
- Prefer IAM roles and temporary credentials for workloads.
- Apply least privilege.

### 6.3 AWS management tools

| Tool | Purpose | Example |
|---|---|---|
| Management Console | Browser-based resource management | Create an S3 bucket |
| AWS CLI | Terminal-based commands and automation | List EC2 instances |
| AWS SDK | Integrate AWS APIs into application code | Spring Boot uploads a file to S3 |
| CloudShell | Browser-based command-line environment | Run AWS CLI commands without local installation |

### 6.4 Basic CLI commands

Check the CLI version:

```bash
aws --version
```

Check the active identity:

```bash
aws sts get-caller-identity
```

Check the configured Region:

```bash
aws configure get region
```

List configured profiles:

```bash
aws configure list-profiles
```

List S3 buckets:

```bash
aws s3 ls
```

List EC2 instances in Singapore:

```bash
aws ec2 describe-instances --region ap-southeast-1
```

These commands require valid credentials and appropriate permissions. The resource-listing commands may return no results if there are no matching resources.

## 7. Review: AWS Shared Responsibility Model

The Shared Responsibility Model divides security responsibilities between AWS and the customer.

### 7.1 Security OF the cloud — AWS

AWS is responsible for the infrastructure that runs AWS services, including:

- Physical data centres.
- Physical servers and storage.
- Physical networking.
- Virtualization infrastructure.
- Infrastructure supporting managed AWS services.

### 7.2 Security IN the cloud — Customer

Customers are responsible for securing their workloads and configurations, including:

- Data and data access.
- IAM identities and permissions.
- Application code and dependencies.
- Network configuration.
- Guest OS patching on EC2.
- Service configuration and monitoring.

### 7.3 Responsibility varies by service

| Responsibility | EC2 | RDS | S3 | Lambda |
|---|---|---|---|---|
| Physical infrastructure | AWS | AWS | AWS | AWS |
| Underlying service infrastructure | AWS | AWS | AWS | AWS |
| Guest OS management | Customer | AWS manages underlying service OS | AWS | AWS |
| Application code | Customer | Customer's application | Customer's application | Customer |
| Data access decisions | Customer | Customer | Customer | Customer |
| IAM permissions | Customer configures | Customer configures | Customer configures | Customer configures |

This is a simplified learning table. The exact responsibility boundary depends on the service and its configuration.

### 7.4 Important security principle

Using a managed service reduces some infrastructure responsibilities, but it does not remove customer responsibilities for data, identities, permissions, application logic, and configuration.

## 8. Integrated Architecture — Spring Boot E-commerce Application

The following architecture combines concepts from Days 1–6.

```text
                         Customers
                             |
                             v
                         Route 53
                             |
                             v
                    Application Load Balancer
                             |
                 +-----------+-----------+
                 |                       |
                 v                       v
               AZ-A                     AZ-B
                 |                       |
          Spring Boot EC2         Spring Boot EC2
                 |                       |
                 +-----------+-----------+
                             |
               +-------------+-------------+
               |                           |
               v                           v
          Amazon RDS                  Amazon S3
       Order/customer data           Product images
               ^                           ^
               |                           |
               +-------------+-------------+
                             |
                        IAM role
                   (limited permissions)

Images are delivered through CloudFront.

Monitoring:
Application and AWS resources
             |
             v
        CloudWatch

Account API activity
             |
             v
         CloudTrail
```

### 8.1 Identify the concepts

| Architecture component | Related lesson concept |
|---|---|
| AWS Region | Global infrastructure |
| AZ-A and AZ-B | Availability Zones and high availability |
| EC2 | IaaS |
| RDS | Managed database service |
| S3 | Object storage |
| CloudFront | Edge content delivery |
| IAM role | Identity and access management |
| CloudWatch | Monitoring |
| CloudTrail | Account activity and audit events |
| Shared Responsibility Model | Security responsibility boundary |

### 8.2 Example request flow

1. A customer opens the e-commerce website.
2. Route 53 resolves the domain name.
3. The Application Load Balancer routes the request to a healthy Spring Boot instance.
4. The application reads or writes order data in RDS.
5. The application uses its IAM role to access permitted S3 objects.
6. CloudFront delivers cached product images where appropriate.
7. CloudWatch collects configured metrics and logs.
8. CloudTrail records supported account activity and API events.

### Exercise 5 — Architecture decision

**Scenario:** A Spring Boot application runs on EC2 and needs to read product images from S3. The team plans to store an IAM access key in `application.properties`.

**Question:** Is this a good design?

**Answer:** No. Use an IAM role attached to the EC2 instance with only the required S3 permissions. The AWS SDK can obtain temporary credentials through its default credential provider chain.

### Exercise 6 — Availability

**Question:** The application has two EC2 instances in different AZs, but both depend on a database deployed in only one AZ. Is the whole application fully protected from an AZ failure?

**Answer:** No. The database may still be a single point of failure. The team must design the database and other dependencies for the required availability level.

### Exercise 7 — CLI identity check

**Question:** Which command helps verify the active AWS identity before you make an important change?

**Answer:**

```bash
aws sts get-caller-identity
```

### Exercise 8 — Short architecture explanation

**Question:** Explain why an e-commerce application might use EC2, RDS, S3, CloudFront, and IAM roles.

**Model answer:**

EC2 runs the Spring Boot application. RDS stores relational data such as orders and customers. S3 stores product images. CloudFront delivers images closer to users. IAM roles provide the application with controlled access to AWS services without hard-coded credentials.

## 12. English Speaking Practice

Read each question aloud, then practise answering with the model answer.

### Question 1: What is cloud computing?

**Model answer:**

Cloud computing is the delivery of computing resources over the internet. Companies can use servers, storage, databases, and networking without buying all the physical hardware themselves.

### Question 2: What is the difference between IaaS, PaaS, and SaaS?

**Model answer:**

IaaS provides virtual infrastructure, PaaS provides a managed application platform, and SaaS provides a complete application. The main difference is how much the cloud provider manages.

### Question 3: What is an Availability Zone?

**Model answer:**

An Availability Zone is an isolated location within an AWS Region. Deploying an application across multiple Availability Zones can improve availability.

### Question 4: What is the AWS Shared Responsibility Model?

**Model answer:**

The AWS Shared Responsibility Model explains how security responsibilities are divided between AWS and customers. AWS secures the cloud infrastructure, while customers secure their data, identities, applications, and configurations.

### Question 5: What is the difference between AWS CLI and AWS SDK?

**Model answer:**

AWS CLI is a command-line tool for managing AWS services. AWS SDK is a set of libraries that allows application code to call AWS services. For example, a Spring Boot application can use the AWS SDK for Java to access S3.

### Question 6: How would you make a Spring Boot application more available on AWS?

**Model answer:**

I would deploy application instances across multiple Availability Zones and use a load balancer with health checks. I would also make sure the database and other dependencies have an appropriate availability and recovery design.

## 13. AWS Interview Questions and Answers

### Q1. What is cloud computing?

**Answer:** Cloud computing is the on-demand delivery of computing resources over a network, usually with usage-based pricing.

### Q2. What are the main cloud deployment models?

**Answer:** Public cloud, private cloud, hybrid cloud, and multi-cloud.

### Q3. What are IaaS, PaaS, and SaaS?

**Answer:** IaaS provides virtual infrastructure, PaaS provides a managed application platform, and SaaS provides a complete application.

### Q4. What is the difference between a Region and an Availability Zone?

**Answer:** A Region is a geographic AWS area. An Availability Zone is an isolated location within a Region.

### Q5. What is the purpose of CloudFront?

**Answer:** CloudFront is a content delivery network that can cache and deliver content through AWS's global edge network.

### Q6. What is the AWS Shared Responsibility Model?

**Answer:** It defines how security responsibilities are divided between AWS and customers. AWS is responsible for security of the cloud, while customers are responsible for security in the cloud. The exact boundary depends on the service.

### Q7. Who manages the guest operating system on EC2?

**Answer:** The customer is responsible for managing and patching the guest operating system on EC2.

### Q8. Who manages the physical infrastructure for RDS?

**Answer:** AWS manages the underlying physical infrastructure and managed-service infrastructure. Customers remain responsible for database data, users, permissions, and their application configuration.

### Q9. Why should an EC2 application use an IAM role?

**Answer:** An IAM role provides temporary credentials and controlled permissions without requiring long-lived access keys to be stored in the application.

### Q10. How can you verify which AWS identity your CLI is using?

**Answer:**

```bash
aws sts get-caller-identity
```

### Q11. What is the difference between RTO and RPO?

**Answer:** RTO is the target time to restore a service. RPO is the target maximum data-loss window measured in time.

### Q12. What is the principle of least privilege?

**Answer:** It means granting only the permissions needed to perform a task and avoiding unnecessary access.
