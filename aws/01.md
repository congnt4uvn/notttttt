# 1. What is Cloud Computing?

## 1.1 Definition

Cloud Computing is the delivery of computing resources over the Internet.

Instead of buying and maintaining physical servers, storage devices, databases, and networking equipment, companies can rent these resources from cloud providers.

These resources include:

- Computing power (CPU and RAM).
- Storage (files, images, videos).
- Databases.
- Networking.
- Security services.
- Application hosting.
- Machine Learning and AI services.

Simple definition:

Cloud Computing means using computing resources over the Internet instead of owning and managing all the physical infrastructure yourself.

### Real-world example

Imagine that you want to build an online shopping application.

Your application needs:

| Requirement | Purpose                                |
| ----------- | -------------------------------------- |
| Server      | Run your Java Spring Boot application  |
| Database    | Store customer and order information   |
| Storage     | Store product images                   |
| Network     | Allow users to access your application |
| Security    | Protect data and applications          |
| Monitoring  | Monitor application performance        |

There are two ways to build this system.

Option 1: Buy your own infrastructure

You need to:

1. Buy physical servers.
2. Buy networking equipment.
3. Buy storage devices.
4. Set up a server room.
5. Configure networking.
6. Install an operating system.
7. Configure security.
8. Maintain hardware.
9. Replace hardware when it fails.

Option 2: Use Cloud Computing

You can rent infrastructure from AWS.

For example:

| Requirement         | AWS Service       |
| ------------------- | ----------------- |
| Application server  | Amazon EC2        |
| File storage        | Amazon S3         |
| Database            | Amazon RDS        |
| Network             | Amazon VPC        |
| Security and access | AWS IAM           |
| Monitoring          | Amazon CloudWatch |

You can create these resources in minutes without buying physical servers.

## 1.2 How does Cloud Computing work?

Cloud Computing works through a combination of:

1. Physical Data Centers.
2. Virtualization.
3. Networking.
4. Distributed Infrastructure.
5. Internet Connectivity.

Let's understand each component.

A. Physical Data Centers

Cloud providers operate large data centers around the world.

These data centers contain:

- Physical servers.
- Storage systems.
- Network switches.
- Routers.
- Cooling systems.
- Power systems.
- Security systems.

For example, AWS operates data centers across multiple geographical regions.

B. Virtualization

Virtualization allows one physical server to run multiple virtual machines.

## 1.3 Characteristics of Cloud Computing

There are five important characteristics commonly associated with Cloud Computing.

| Characteristic         | Explanation                                                |
| ---------------------- | ---------------------------------------------------------- |
| On-demand self-service | Create resources whenever needed                           |
| Broad network access   | Access services through networks and standard devices      |
| Resource pooling       | Providers share underlying infrastructure across customers |
| Rapid elasticity       | Scale resources up or down quickly                         |
| Measured service       | Resource usage is measured for billing                     |

Let's understand an example.

Suppose your e-commerce application normally has 1,000 users per day.

During a major promotion, traffic increases to 100,000 users.

With cloud infrastructure, you can scale your application to handle the additional traffic and scale down afterward.

This is called Elasticity.

A. Region

A Region is a separate geographical area where AWS operates infrastructure.

Examples:

- US East (N. Virginia): `us-east-1`
- Asia Pacific (Singapore): `ap-southeast-1`
- Asia Pacific (Tokyo): `ap-northeast-1`

A company can choose a Region based on:

- Customer location.
- Application latency.
- Regulatory requirements.
- Service availability.
- Cost.

B. Availability Zone (AZ)

An Availability Zone is one or more isolated data centers within an AWS Region, designed to operate independently from other Availability Zones.

A Region contains multiple Availability Zones.

For example:

```
       AWS Region
       ap-southeast-1
             |
     +-------+-------+
     |       |       |
     v       v       v
    AZ-a    AZ-b    AZ-c
     |       |       |
    EC2     EC2     EC2
     |       |       |
     +-------+-------+
             |
           RDS
```

Why use multiple Availability Zones?

If one Availability Zone experiences an outage, an application designed for high availability can continue operating using resources in another Availability Zone.

C. Edge Locations

Edge Locations are infrastructure locations used by AWS services such as CloudFront to deliver content closer to end users.

Example:

A customer in Vietnam accesses your website.

Instead of downloading every static image directly from your origin server in Singapore, CloudFront can deliver cached content from a nearby edge location when available.

### Important comparison

| Component         | Meaning                                          |
| ----------------- | ------------------------------------------------ |
| Region            | Geographical AWS area                            |
| Availability Zone | Isolated infrastructure location within a Region |
| Edge Location     | Content delivery location                        |

# 3. Why do companies use AWS?

Companies use AWS because they need scalable, reliable, secure, and cost-effective infrastructure.

Let's explore the main reasons.

## 3.1 Reduce Infrastructure Costs

Without AWS, a company may need to purchase:

- Physical servers.
- Storage equipment.
- Networking equipment.
- Cooling systems.
- Backup power systems.
- Data center facilities.

These investments can be expensive.

With AWS, companies can rent computing resources and pay according to the pricing model of each service.

Example:

A startup wants to launch an application.

Instead of purchasing a physical server, it launches an EC2 instance and pays for its usage.

## 3.2 Scalability

Scalability means the ability of a system to handle increasing workloads.

There are two main types.

Vertical Scaling (Scale Up)

Increase the resources of an existing server.

Example:

```
Before:
EC2 Instance
2 vCPU
4 GB RAM

After:
EC2 Instance
8 vCPU
16 GB RAM
```

Horizontal Scaling (Scale Out)

Add more servers to handle additional traffic.

```
             Load Balancer
                   |
          +--------+--------+
          |        |        |
          v        v        v
         EC2      EC2      EC2
         #1       #2       #3
```

AWS services that support scaling include:

- EC2 Auto Scaling.
- Elastic Load Balancing.
- ECS Service Auto Scaling.
- EKS Horizontal Pod Autoscaler.
- DynamoDB On-Demand Capacity.

## 3.3 High Availability

High Availability means designing systems to remain operational with minimal downtime.

For example, you deploy your application across two Availability Zones.

```
              Application
                   |
             Load Balancer
                   |
           +-------+-------+
           |               |
           v               v
        AZ - A           AZ - B
           |               |
         EC2 #1          EC2 #2
           |               |
           +-------+-------+
                   |
              RDS Multi-AZ
```

If one Availability Zone becomes unavailable, the system can continue operating through the other zone, assuming the architecture and failover mechanisms are configured correctly.

## 3.4 Global Reach

AWS has infrastructure in multiple geographical regions.

Companies can deploy applications closer to their customers.

For example:

| Customer      | Possible AWS Region |
| ------------- | ------------------- |
| Vietnam       | Singapore           |
| Japan         | Tokyo               |
| United States | N. Virginia         |
| Germany       | Frankfurt           |

This can help reduce network latency.

## 3.5 Faster Development and Deployment

Developers can create infrastructure using automation.

For example:

Instead of manually configuring servers, you can use Terraform.


Infrastructure as Code makes it easier to reproduce environments.

AWS provides security-related services and capabilities.

## 4.1 Scalability vs Elasticity

These two concepts are frequently confused.

Scalability: The system can increase its capacity to handle more workloads.

Elasticity: The system can automatically or dynamically increase and decrease capacity according to demand.

Example:

| Situation                                                                 | Concept                |
| ------------------------------------------------------------------------- | ---------------------- |
| Upgrade EC2 from 2 CPU to 8 CPU                                           | Vertical scalability   |
| Add 5 more EC2 instances                                                  | Horizontal scalability |
| Automatically add instances during high traffic and remove them afterward | Elasticity             |

## 4.2 High Availability vs Fault Tolerance

High Availability (HA):

The system is designed to minimize downtime and recover quickly from failures.

Fault Tolerance (FT):

The system is designed to continue operating despite certain component failures, potentially with no interruption to the service.

Example:

- High Availability: Application fails over to another Availability Zone.
- Fault Tolerance: Redundant components allow operations to continue without interruption when a component fails.

- Managing hardware.
- Maintaining networking.
- Installing operating systems.
- Managing storage.
- Managing backups.
- Physical security.
- Power and cooling.

Example:

A bank operates its own data center with physical servers running banking applications.

## 5.5 Real-world example

Imagine a company has 10,000 customers.

During normal operations, it needs 2 application servers.

During a major sale, it needs 20 application servers.

On-Premises approach:

The company must purchase enough hardware to support peak demand or accept capacity constraints.

The additional hardware may remain underutilized during normal periods.

Cloud approach:

The company can use Auto Scaling to increase the number of application instances when demand increases and reduce them when demand decreases.

This allows the company to align infrastructure capacity more closely with actual demand.

## 5.6 When should companies use On-Premises?

On-Premises may be suitable when:

- Organizations require specific physical infrastructure control.
- Legacy applications depend on specialized hardware.
- Regulatory or operational requirements dictate particular hosting arrangements.
- Existing infrastructure investments are significant.
- Local processing requirements make cloud hosting less suitable.

## 5.7 When should companies use Cloud Computing?

Cloud Computing may be suitable when:

- Applications need rapid scaling.
- Companies want to launch products quickly.
- Infrastructure demand changes frequently.
- Organizations need global deployment.
- Teams want to automate infrastructure.
- Companies want managed databases and services.

Important: Cloud is not always cheaper than On-Premises. Cost depends on workload, utilization, architecture, licensing, networking, data transfer and operational requirements.

# 6. CapEx vs OpEx

This is an important concept in Cloud Computing and AWS certification exams.

## 6.1 What is CapEx?

CapEx (Capital Expenditure) refers to money spent to purchase or improve long-term assets.

Examples:

- Purchasing physical servers.
- Purchasing storage systems.
- Purchasing network equipment.
- Building data centers.
- Installing cooling systems.

A company invests money upfront to own infrastructure.

### Example

A company wants to build its own data center.

| Item              | Cost     |
| ----------------- | -------- |
| Physical servers  | $50,000  |
| Storage systems   | $20,000  |
| Network equipment | $10,000  |
| Cooling and power | $15,000  |
| Data center setup | $25,000  |
| Total             | $120,000 |

The company invests $120,000 before running its applications.

This is primarily CapEx.

## 6.2 What is OpEx?

OpEx (Operational Expenditure) refers to ongoing expenses required to operate a business.

Examples:

- Monthly cloud bills.
- Electricity.
- Internet connectivity.
- Software subscriptions.
- Maintenance services.
- Operational support.

With AWS, companies can pay for cloud resources based on their usage or chosen pricing commitments.

### Example

Instead of purchasing physical servers, the company uses AWS.

| AWS Resource   | Monthly Cost |
| -------------- | ------------ |
| EC2            | $100         |
| RDS            | $80          |
| S3             | $20          |
| Data Transfer  | $30          |
| Other Services | $20          |
| Total          | $250/month   |

These are illustrative figures, not current AWS prices.

The company pays for the resources it uses.

This is generally treated as OpEx.

## 6.3 CapEx vs OpEx Comparison

| Criteria    | CapEx                    | OpEx                         |
| ----------- | ------------------------ | ---------------------------- |
| Meaning     | Capital Expenditure      | Operational Expenditure      |
| Payment     | Large upfront investment | Ongoing expenses             |
| Ownership   | Usually owns the assets  | Often rents or subscribes    |
| Cost        | Initial investment       | Recurring costs              |
| Flexibility | Less flexible            | Often more flexible          |
| Maintenance | Asset owner manages      | Depends on service agreement |
| Example     | Buy physical server      | Rent EC2 instance            |

## Exercise 3 — Scenario-Based Questions

Question 1:

A company wants to deploy a Spring Boot application but does not want to purchase physical servers.

Which AWS service should it consider?

Answer: Amazon EC2

Explanation: EC2 provides virtual computing instances to run applications.

Question 2:

An application normally receives 1,000 requests per hour. During a promotion, it receives 100,000 requests per hour.

Which cloud concept is important?

Answer: Scalability and Elasticity

Explanation: The application needs to increase its capacity to handle traffic spikes.

Question 3:

A company purchases physical servers for $100,000.

Is this CapEx or OpEx?

Answer: CapEx

Explanation: Purchasing long-term physical infrastructure is capital expenditure.

Question 4:

A company rents an EC2 instance and pays monthly for its usage.

Is this CapEx or OpEx?

Answer: Generally OpEx

Explanation: The company pays an ongoing service expense rather than purchasing the physical server.

Question 5:

A company wants its application to continue operating if one Availability Zone becomes unavailable.

What should it implement?

Answer: Multi-AZ Architecture

Explanation: Deploy redundant application resources across multiple Availability Zones and configure appropriate failover.
