## 2. What Are Cloud Service Models?

Cloud service models describe **how much of the technology stack the cloud provider manages for you** and how much you manage yourself.

Think about deploying a Spring Boot application. A complete application environment may contain:

1. Physical data centre and hardware
2. Networking and virtualization
3. Operating system
4. Middleware and runtime (for example, Java)
5. Application code
6. Application data

The service model determines which layers you manage and which layers the provider manages.

There are three widely used models:

- **IaaS** — Infrastructure as a Service
- **PaaS** — Platform as a Service
- **SaaS** — Software as a Service

A useful rule:

> IaaS gives you infrastructure, PaaS gives you an application platform, and SaaS gives you a complete application.

## 3. IaaS — Infrastructure as a Service

### 3.1 Definition

IaaS provides fundamental computing resources over the internet, such as virtual machines, storage, and networking.

The cloud provider manages the physical infrastructure and virtualization. You manage the operating system and most of the software stack running on your virtual resources.

### 3.2 What do you manage?

With a typical IaaS virtual machine:

- The provider manages the physical data centre, physical servers, networking hardware, and virtualization.
- You manage the guest operating system, OS updates, installed software, Java runtime, application code, application configuration, and data.
- You are also responsible for configuring access controls, security groups, and other resources within your account.

### 3.3 AWS examples

| AWS service | What it provides | Typical customer responsibility |
|---|---|---|
| Amazon EC2 | Virtual servers | Guest OS, patches, runtime, application, data |
| Amazon EBS | Block storage volumes | Data stored on the volume, encryption/configuration choices |
| Amazon VPC | Isolated virtual networking | Subnets, route tables, security groups, network design |
| Amazon EFS | Managed network file storage | File permissions, data, access configuration |

Amazon EC2 is a classic IaaS example. You choose an instance type, launch a virtual machine, install Java, configure your application, and maintain the guest operating system.

### 3.4 Example: Deploy Spring Boot on EC2

Architecture:

```text
Users
  |
  v
Internet
  |
  v
Internet Gateway
  |
  v
EC2 Instance
  |
  +-- Linux operating system (you manage)
  +-- Java runtime (you manage)
  +-- Spring Boot application (you manage)
  +-- Application logs and configuration (you manage)
  |
  v
Amazon RDS (managed database service)
```

A simplified deployment process:

1. Launch an EC2 instance.
2. Configure its security group.
3. Install a supported operating system package and Java runtime.
4. Copy your Spring Boot JAR file to the instance.
5. Configure environment variables and secrets securely.
6. Run the application as a managed service.
7. Monitor logs, CPU, memory, and application health.
8. Apply OS security updates and maintain the instance.

Example command to run a JAR on a Linux server:

```bash
java -jar app.jar
```

This is only a minimal demonstration. In production, use a service manager such as `systemd`, a deployment pipeline, secure secret storage, health checks, and monitoring rather than relying on a terminal session.

### 3.5 Advantages and disadvantages

| Advantages | Disadvantages |
|---|---|
| High control over the operating system and environment | You must maintain the OS and runtime |
| Flexible configuration | More operational work |
| Supports many application types | Security configuration requires care |
| Useful for legacy or specialized workloads | Scaling and deployment automation are your responsibility unless you add managed services |

**When should you choose IaaS?**

Choose IaaS when you need significant control over the operating system, network, installed software, or runtime environment.

## 4. PaaS — Platform as a Service

### 4.1 Definition

PaaS provides a managed platform for building, deploying, and running applications.

The provider manages more of the underlying infrastructure and platform. Developers can focus primarily on application code, deployment configuration, and data.

The exact division of responsibility depends on the service and its configuration.

### 4.2 What do you manage?

In a typical PaaS-style deployment:

- The provider manages physical infrastructure, virtualization, operating system, and much of the application platform.
- You manage application code, application configuration, data, user access, and the security of your application.
- You still need to understand the platform's limits, supported runtimes, scaling settings, and deployment behavior.

### 4.3 AWS examples

| AWS service | How it fits |
|---|---|
| AWS Elastic Beanstalk | A managed application platform; commonly described as PaaS-like |
| AWS App Runner | Managed service for building and running web applications and APIs |
| AWS Elastic Container Service (ECS) with Fargate | Managed container orchestration and serverless compute; PaaS-like in some architectures, but not a strict traditional PaaS |
| AWS Lambda | Serverless function compute; often discussed separately as FaaS rather than simply called PaaS |

AWS services do not always fit perfectly into one textbook category. Use these labels as a way to understand the management model, not as rigid product classifications.

### 4.4 Example: Deploy Spring Boot with Elastic Beanstalk

Instead of manually installing Java and configuring an EC2 instance, you package your application and deploy it to Elastic Beanstalk.

Architecture:

```text
Users
  |
  v
Elastic Load Balancer
  |
  v
Elastic Beanstalk environment
  |
  +-- Managed application environment
  +-- Spring Boot application (you build and maintain)
  |
  v
Amazon RDS
```

A typical workflow:

1. Develop and test the Spring Boot application locally.
2. Build the application package.
3. Create an Elastic Beanstalk application and environment.
4. Select a supported platform and configure environment settings.
5. Deploy the application package.
6. Configure health checks, scaling, environment variables, and database connectivity.
7. Monitor application health and logs.

Elastic Beanstalk reduces infrastructure management, but it does not remove your responsibility for application security, data, IAM permissions, or configuration.

### 4.5 Advantages and disadvantages

| Advantages | Disadvantages |
|---|---|
| Less infrastructure administration | Less control over the underlying environment |
| Faster application deployment | Platform constraints may apply |
| Easier integration with managed scaling and monitoring | Platform configuration still needs attention |
| Developers can focus on application code | Moving to another platform may require changes |

**When should you choose PaaS?**

Choose a PaaS-style service when you want to deploy and operate applications without managing every server and operating-system detail.

## 5. SaaS — Software as a Service

### 5.1 Definition

SaaS delivers a complete software application over the internet. Users normally access it through a web browser, mobile application, or API.

The provider operates the application and its underlying infrastructure. Customers configure the product, manage users and permissions, and control the data they put into it.

### 5.2 Common examples

| SaaS product | Typical use |
|---|---|
| Salesforce | Customer relationship management (CRM) |
| Microsoft 365 | Email, documents, collaboration |
| Google Workspace | Email, documents, collaboration |
| Slack | Team communication |
| Zoom | Video meetings |

These are examples of SaaS products, not AWS infrastructure services.

### 5.3 What do you manage?

As a SaaS customer, you commonly manage:

- User accounts and access permissions
- Organization settings
- Data entered into the application
- Sharing and retention settings available to you
- Safe use of the product and compliance with your organization's policies

The SaaS provider manages the application software, platform, operating systems, servers, and physical infrastructure.

### 5.4 Advantages and disadvantages

| Advantages | Disadvantages |
|---|---|
| Ready-to-use application | Less control over the software itself |
| No need to maintain application servers | Customization may be limited |
| Provider handles updates and infrastructure | Dependence on provider availability and service terms |
| Usually accessible from many devices | Data location, export, and integration need consideration |

**When should you choose SaaS?**

Choose SaaS when your organization needs a complete application and does not need to build or operate the underlying software.

## 6. IaaS vs PaaS vs SaaS — Comparison

### 6.1 Main comparison

| Category | IaaS | PaaS | SaaS |
|---|---|---|---|
| Full name | Infrastructure as a Service | Platform as a Service | Software as a Service |
| Provides | Virtual infrastructure | Managed application platform | Complete application |
| Customer control | High | Medium | Lower |
| Infrastructure management by provider | Physical infrastructure and virtualization | Infrastructure plus more platform layers | Almost the entire technology stack |
| Customer focuses on | OS, runtime, application, data | Application, configuration, data | Using and configuring the application |
| Operational effort | Usually highest | Medium | Usually lowest |
| Example | Amazon EC2 | Elastic Beanstalk (PaaS-like) | Salesforce |

### 6.2 Who manages each layer?

The following is a simplified learning model. Actual responsibility varies by provider and service.

| Technology layer | IaaS | PaaS | SaaS |
|---|---|---|---|
| Application and application data | Customer | Customer | Shared/customer-controlled data and settings |
| Runtime and middleware | Customer | Provider | Provider |
| Operating system | Customer | Provider | Provider |
| Virtualization | Provider | Provider | Provider |
| Physical servers, storage, networking | Provider | Provider | Provider |

Remember: even when a provider manages a layer, the customer may still have security, configuration, access, or compliance responsibilities related to how the service is used.

### 6.3 Easy way to remember

Imagine you want to eat dinner:

- **IaaS:** You rent a kitchen. You manage the equipment and prepare the meal.
- **PaaS:** You use a prepared kitchen with tools and facilities provided. You focus on preparing your meal.
- **SaaS:** You order a finished meal and consume it.

This analogy is simplified, but it helps you remember the difference.

## 7. Serverless and FaaS — An Important Related Concept

Serverless does not mean that there are no servers. It means the cloud provider manages server provisioning and much of the infrastructure operation for you.

**FaaS** means Function as a Service. You deploy individual functions that run in response to events.

### AWS Lambda example

A Spring Boot application might receive an order request and publish an event. A Lambda function can process that event, for example by sending a notification or updating a record.

```text
Customer places an order
        |
        v
Spring Boot API
        |
        v
Amazon EventBridge
        |
        v
AWS Lambda function
        |
        v
Send notification / process event
```

With Lambda, AWS manages the underlying compute infrastructure. You still manage:

- Function code and dependencies
- IAM execution permissions
- Event source and trigger configuration
- Application logic and error handling
- Data access and security
- Resource settings such as memory and timeout

Lambda is commonly classified as serverless function compute or FaaS. It is related to PaaS because the provider manages the runtime infrastructure, but the terms are not interchangeable.

## 8. Introduction to the AWS Shared Responsibility Model

Cloud service models are closely related to the **Shared Responsibility Model**.

AWS describes security responsibilities as security **of** the cloud and security **in** the cloud.

### 8.1 AWS responsibility: Security of the cloud

AWS is responsible for protecting the infrastructure that runs AWS services, including:

- Physical data centres
- Physical servers and storage hardware
- Physical networking
- Virtualization infrastructure
- The underlying infrastructure for managed services

### 8.2 Customer responsibility: Security in the cloud

Customers are responsible for securing what they deploy and configure in AWS. Examples include:

- Data and data classification
- IAM users, roles, and permissions
- Application code and application security
- Network configuration, such as security groups
- Encryption choices and key access configuration
- Operating-system patching on services such as EC2

### 8.3 Responsibilities change by service

| Responsibility | Amazon EC2 | Amazon RDS |
|---|---|---|
| Physical data centre | AWS | AWS |
| Physical hardware | AWS | AWS |
| Virtualization | AWS | AWS |
| Guest OS maintenance | Customer | AWS manages the underlying host OS; service-specific customer configuration still matters |
| Database engine infrastructure maintenance | Customer if self-managed on EC2 | AWS manages much of the managed database service maintenance |
| Database schema and application queries | Customer | Customer |
| Data access and IAM configuration | Customer | Customer |
| Application security | Customer | Customer |

The table is intentionally simplified. Exact responsibilities depend on the service, selected options, and configuration. For example, RDS customers still need to manage database users, permissions, data, schema, and secure connectivity.

**Key point:** Moving from EC2 to a more managed service usually reduces infrastructure work, but it does not eliminate customer security responsibilities.

## 9. Choosing a Service Model for a Spring Boot Application

Imagine your team is building an online shopping system.

### Option A — IaaS with EC2

Use EC2 when:

- You need control over the operating system.
- You have special system dependencies.
- Your team can manage patching, deployment, monitoring, and scaling.

You are responsible for maintaining the server environment as well as the application.

### Option B — PaaS-style deployment with Elastic Beanstalk

Use Elastic Beanstalk when:

- You want a simpler application deployment workflow.
- You prefer AWS to manage more of the environment.
- Your application fits the supported platform and deployment model.

You still manage the application, its configuration, permissions, and data.

### Option C — SaaS for business functions

Use a SaaS product when:

- You need an existing CRM, email, collaboration, or support application.
- Building that application yourself would not provide enough business value.
- The SaaS product meets your security, integration, and compliance needs.

For example, your e-commerce application might use Salesforce as a CRM while your own Spring Boot APIs run on AWS.

### Suggested architecture

```text
                         Customers
                             |
                             v
                       Web / Mobile UI
                             |
                             v
                    Spring Boot REST API
                             |
              +--------------+--------------+
              |                             |
              v                             v
        Amazon RDS                    Amazon S3
        Product / order data          Product images
              |
              v
        Amazon EventBridge
              |
              v
          AWS Lambda
              |
              v
       Notification service

Business team
     |
     v
Salesforce CRM (SaaS)
```

A real architecture may use additional services for authentication, secrets, observability, caching, and network protection. This diagram focuses on service-model concepts.

## 10. AWS CLI — Basic Environment Checks

You do not need to create paid AWS resources for this lesson. These commands inspect your local AWS CLI configuration and identity.

### 10.1 Check the AWS CLI version

```bash
aws --version
```

### 10.2 Check the configured Region

```bash
aws configure get region
```

### 10.3 Check the identity used by the CLI

```bash
aws sts get-caller-identity
```

This returns information about the AWS account and IAM identity associated with the current credentials.

### 10.4 Optional: List EC2 instances

```bash
aws ec2 describe-instances
```

This command queries EC2 resources and may return a large response. It does not create an instance. Your IAM identity must have permission to call it.

### 10.5 Security reminders

- Never paste AWS access keys into source code or public repositories.
- Prefer IAM roles and temporary credentials where possible.
- Give identities only the permissions they need.
- Do not create resources just to practise a command unless you understand the possible cost.

## 13. English Speaking Practice

Read each question aloud, then practise answering without looking at the model answer.

### Question 1: What is IaaS?

**Model answer:**

IaaS stands for Infrastructure as a Service. It provides virtual infrastructure, such as servers, storage, and networking. With Amazon EC2, I can launch a virtual machine and install my own operating system and software.

### Question 2: What is PaaS?

**Model answer:**

PaaS stands for Platform as a Service. It provides a managed platform for deploying applications. Developers can focus more on application code instead of managing every server and operating-system detail.

### Question 3: What is SaaS?

**Model answer:**

SaaS stands for Software as a Service. It provides a complete application over the internet. For example, I can use Salesforce or Microsoft 365 without managing the application servers.

### Question 4: What is the difference between IaaS and PaaS?

**Model answer:**

With IaaS, customers manage more of the software stack, including the operating system. With PaaS, the provider manages more of the platform, so developers can focus on building and deploying applications.

**Model answer:**

It depends on the project requirements. I would choose EC2 if I needed more control over the server. I would consider Elastic Beanstalk if I wanted a simpler deployment process and less infrastructure management.

## 14. AWS Interview Questions and Answers

### Q1. What are the three main cloud service models?

**Answer:** IaaS, PaaS, and SaaS. IaaS provides virtual infrastructure, PaaS provides a managed application platform, and SaaS provides a complete software application.

### Q2. Is Amazon EC2 IaaS or PaaS?

**Answer:** EC2 is generally classified as IaaS because customers manage the guest operating system, runtime, and applications running on the virtual machine.

### Q3. Is AWS Elastic Beanstalk PaaS?

**Answer:** Elastic Beanstalk is commonly described as PaaS-like because it provides a managed application deployment platform. However, the exact responsibilities depend on the environment and configuration.

### Q4. Is Salesforce SaaS?

**Answer:** Yes. Salesforce is a SaaS product that provides a complete CRM application over the internet.

### Q5. What is the main advantage of PaaS?

**Answer:** PaaS reduces the amount of infrastructure and platform management required, allowing developers to focus more on application development and deployment.

### Q6. Does serverless mean there are no servers?

**Answer:** No. Servers still exist, but the cloud provider manages the provisioning and operation of the underlying compute infrastructure.

### Q7. What is the AWS Shared Responsibility Model?

**Answer:** It explains how security responsibilities are divided between AWS and the customer. AWS is responsible for security of the cloud, while customers are responsible for security in the cloud. The exact division depends on the AWS service.

### Q8. Who patches the guest operating system on an EC2 instance?

**Answer:** The customer is responsible for patching and maintaining the guest operating system on EC2.

### Q9. Does using a managed service remove all customer security responsibilities?

**Answer:** No. Customers still manage responsibilities such as data, identities, permissions, application security, and service configuration.

### Q10. When would you choose SaaS instead of building your own application?

**Answer:** I would choose SaaS when an existing product meets the business requirements and building and maintaining a custom application would add unnecessary cost and complexity.

## 15. Lesson Summary

- **IaaS:** You rent virtual infrastructure and manage more of the software stack. Example: Amazon EC2.
- **PaaS:** You use a managed application platform and focus more on application development. Example: AWS Elastic Beanstalk is PaaS-like.
- **SaaS:** You use a complete application managed by a provider. Examples: Salesforce and Microsoft 365.
- **Serverless/FaaS:** The provider manages the underlying compute infrastructure, while you manage functions, permissions, triggers, and application logic.
- **Shared Responsibility Model:** AWS secures the cloud infrastructure; customers secure their workloads, data, identities, and configurations. The exact split depends on the service.

### Quick memory rule

```text
IaaS = Manage more of the server and software stack
PaaS = Focus more on deploying and running your application
SaaS = Use a complete application
```
