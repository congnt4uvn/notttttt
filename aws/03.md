# 1. Introduction to Cloud Service Models

## 1.1 What is a Cloud Service Model?

A Cloud Service Model describes what computing resources a cloud provider delivers to customers and which responsibilities remain with the customer.

In simple terms, it answers:

- What does the cloud provider manage?
- What does the customer manage?
- How much infrastructure control does the customer have?
- How much responsibility does the customer have for maintaining the application?

There are three traditional cloud service models:

| Model | Full name                   | Main idea                    |
| ----- | --------------------------- | ---------------------------- |
| IaaS  | Infrastructure as a Service | Rent infrastructure          |
| PaaS  | Platform as a Service       | Rent an application platform |
| SaaS  | Software as a Service       | Use ready-made software      |

### Simple example

Imagine you want to build and run a Java Spring Boot application.

You have three choices.

Option 1 — IaaS

You rent a virtual server from AWS.

You install:

- Linux.
- Java.
- Docker.
- Your Spring Boot application.

Option 2 — PaaS

You provide your application code or deployment artifact to a managed application platform.

The platform handles much of the infrastructure and runtime management.

Option 3 — SaaS

You use an existing software application through a browser.

For example:

- Gmail.
- Microsoft 365.
- Salesforce.

You don't need to build or manage the underlying application infrastructure.

# 2. Infrastructure as a Service (IaaS)

## 2.1 What is IaaS?

IaaS (Infrastructure as a Service) is a cloud service model that provides virtualized computing infrastructure over the Internet.

The cloud provider manages the physical infrastructure, while customers manage the operating systems, applications and other configurations according to the service.

IaaS typically provides:

- Virtual machines.
- Computing power.
- Storage.
- Networking.
- Firewalls and network controls.
- Load balancing capabilities.

### Simple definition

IaaS means renting virtual infrastructure instead of purchasing physical servers.

## 2.2 IaaS Architecture

```
             CUSTOMER
                 |
                 v
       +-------------------+
       |    Application    |
       +-------------------+
       |     Middleware    |
       +-------------------+
       |    Operating      |
       |      System       |
       +-------------------+
       |   Virtualization  |
       +-------------------+
                 |
                 v
          CLOUD PROVIDER
       +-------------------+
       | Physical Servers  |
       +-------------------+
       | Physical Storage  |
       +-------------------+
       | Physical Network  |
       +-------------------+
       | Data Center       |
       +-------------------+
```

The customer controls the virtual machine and its operating system.

The cloud provider manages the underlying physical infrastructure.

## 2.3 What does the customer manage?

In a typical IaaS environment:

| Component                     | Responsible party |
| ----------------------------- | ----------------- |
| Physical data center          | Cloud provider    |
| Physical servers              | Cloud provider    |
| Physical networking           | Cloud provider    |
| Physical storage              | Cloud provider    |
| Virtualization infrastructure | Cloud provider    |
| Operating system              | Customer          |
| Middleware                    | Customer          |
| Runtime                       | Customer          |
| Application                   | Customer          |
| Application data              | Customer          |

The exact division can vary by service and configuration.

## 2.4 AWS services for IaaS

Important AWS services include:

| AWS Service            | Purpose                    |
| ---------------------- | -------------------------- |
| Amazon EC2             | Virtual servers            |
| Amazon EBS             | Block storage for EC2      |
| Amazon VPC             | Private networking         |
| Elastic Load Balancing | Distribute network traffic |
| Amazon EFS             | Shared file storage        |

EC2 is one of the most important AWS examples of IaaS.

## 2.5 Practical example — Deploy Spring Boot on EC2

Suppose you have a Spring Boot application.

You want to deploy it on AWS using IaaS.

### Architecture

```
              Developer
                  |
                  v
             GitHub Repo
                  |
                  v
             Build JAR
                  |
                  v
             AWS EC2
                  |
          +-------+-------+
          |               |
          v               v
       Linux OS         Java JDK
          |               |
          +-------+-------+
                  |
                  v
          Spring Boot App
                  |
                  v
             PostgreSQL
```

### Implementation steps

Step 1 — Create an EC2 instance

- Open AWS Management Console.
- Navigate to EC2.
- Select Launch Instance.
- Choose an Amazon Machine Image.
- Select an instance type.
- Configure a security group.
- Launch the instance.

Step 2 — Connect to EC2

For a Linux instance:

```
ssh -i my-key.pem ec2-user@YOUR_PUBLIC_IP
```

Step 3 — Install Java

For an Amazon Linux environment:

```
sudo dnf update -y

sudo dnf install java-21-amazon-corretto -y

java -version
```

The exact installation commands depend on the selected operating system.

Step 4 — Upload your JAR file

```
scp -i my-key.pem \
target/myapp.jar \
ec2-user@YOUR_PUBLIC_IP:/home/ec2-user/
```

Step 5 — Run Spring Boot

```
java -jar myapp.jar
```

Your application is now running on EC2.

You are responsible for managing the operating system, Java runtime, application deployment, application security and updates.

## 2.6 Advantages of IaaS

| Advantage              | Explanation                                                     |
| ---------------------- | --------------------------------------------------------------- |
| Infrastructure control | Control the operating system and environment                    |
| Flexibility            | Install your own software                                       |
| Scalability            | Increase or decrease resources                                  |
| Cost flexibility       | Avoid purchasing physical servers                               |
| Customization          | Configure networking and storage                                |
| Migration              | Useful for moving existing applications to cloud infrastructure |

## 2.7 Disadvantages of IaaS

- Requires infrastructure knowledge.
- Customer manages operating system updates.
- Customer manages runtime installation.
- Customer handles application deployment.
- Security configuration requires attention.
- Operational maintenance can be significant.

## 2.8 When should you use IaaS?

Use IaaS when:

- You need control over the operating system.
- You have legacy applications.
- You need custom software configurations.
- You want to migrate traditional servers to cloud infrastructure.
- You need specialized server configurations.

# 3. Platform as a Service (PaaS)

## 3.1 What is PaaS?

PaaS (Platform as a Service) is a cloud service model that provides a managed platform for developing, deploying and running applications.

The cloud provider manages much of the underlying infrastructure and platform.

The customer focuses primarily on:

- Application code.
- Application configuration.
- Application data.
- Deployment settings.

### Simple definition

PaaS means using a ready-made application platform to develop and deploy software without managing the underlying servers and operating systems yourself.

## 3.2 PaaS Architecture

```
             CUSTOMER
                 |
                 v
       +-------------------+
       |    Application    |
       +-------------------+
       | Application Data |
       +-------------------+
                 |
                 v
          CLOUD PROVIDER
       +-------------------+
       |     Runtime       |
       +-------------------+
       |    Middleware    |
       +-------------------+
       |  Operating System |
       +-------------------+
       |   Virtualization  |
       +-------------------+
       | Physical Hardware |
       +-------------------+
```

The customer focuses on the application, while the platform provider manages the underlying platform.

## 3.3 What does the customer manage?

| Component            | Responsible party |
| -------------------- | ----------------- |
| Physical data center | Provider          |
| Physical servers     | Provider          |
| Virtualization       | Provider          |
| Operating system     | Provider          |
| Middleware           | Provider          |
| Runtime              | Provider          |
| Application          | Customer          |
| Application data     | Customer          |

This is a simplified model. The exact responsibility depends on the particular PaaS service.

## 3.4 AWS services related to PaaS

AWS provides several managed application platforms and services.

| AWS Service           | Purpose                                    |
| --------------------- | ------------------------------------------ |
| AWS Elastic Beanstalk | Deploy and manage applications             |
| AWS App Runner        | Build and deploy web applications and APIs |
| AWS Lambda            | Run code without managing servers          |
| Amazon RDS            | Managed relational database                |

Important distinction:

AWS does not classify every managed service as a strict PaaS product in every context. For example, RDS is a managed database service, while Lambda is a serverless compute service.

## 3.5 AWS Elastic Beanstalk

Elastic Beanstalk is a managed application deployment service.

It helps developers deploy applications without manually managing all the infrastructure components.

For example, you can deploy a Java Spring Boot JAR file.

### Architecture

```
             Developer
                 |
                 v
            Spring Boot
              JAR File
                 |
                 v
         Elastic Beanstalk
                 |
        +--------+--------+
        |        |        |
        v        v        v
       EC2       ALB    Auto Scaling
        |
        v
   Java Runtime
        |
        v
   Spring Boot App
        |
        v
       RDS
```

Elastic Beanstalk handles much of the environment provisioning and deployment orchestration.

The underlying AWS resources may include EC2 instances, load balancers, Auto Scaling groups and other components.

You still remain responsible for your application code, application configuration and data.

## 3.6 Practical example — Deploy Spring Boot using Elastic Beanstalk

Suppose you have a Spring Boot project.

Step 1 — Build your project

```
mvn clean package
```

This generates:

```
target/myapp.jar
```

Step 2 — Create an Elastic Beanstalk application

- Open AWS Management Console.
- Search for Elastic Beanstalk.
- Create Application.
- Select a Java platform.
- Create an environment.

Step 3 — Upload your application

Upload the JAR file or a properly structured deployment package for the selected platform.

Step 4 — Deploy

Elastic Beanstalk provisions the environment and deploys your application.

Step 5 — Access the application

Use the environment URL provided by Elastic Beanstalk.

You don't need to manually create and configure every underlying EC2 instance.

## 3.7 Advantages of PaaS

| Advantage                      | Explanation                                                      |
| ------------------------------ | ---------------------------------------------------------------- |
| Faster development             | Focus on application code                                        |
| Less infrastructure management | Provider manages much of the platform                            |
| Easier deployment              | Managed deployment workflow                                      |
| Scalability                    | Platform can support scaling                                     |
| Productivity                   | Less time spent on server administration                         |
| Integration                    | Often integrates with databases, monitoring and deployment tools |

## 3.8 Disadvantages of PaaS

- Less control over the underlying environment.
- Platform restrictions may exist.
- Provider-specific configurations can create vendor dependency.
- Some applications require custom operating system configurations.
- Costs can increase with usage.
- Migration between platforms may require changes.

## 3.9 When should you use PaaS?

Use PaaS when:

- You want to focus on developing applications.
- You don't want to manage operating systems.
- You need faster deployment.
- Your application fits the supported platform.
- You want managed infrastructure and deployment workflows.

# 4. Software as a Service (SaaS)

## 4.1 What is SaaS?

SaaS (Software as a Service) is a cloud service model that delivers ready-to-use software applications over the Internet.

Users access the application through a web browser, mobile application or API.

The provider manages the application infrastructure and software operations.

### Simple definition

SaaS means using software over the Internet without installing and managing the entire application infrastructure yourself.

## 4.2 Examples of SaaS

| Software         | Purpose                        |
| ---------------- | ------------------------------ |
| Gmail            | Email                          |
| Google Workspace | Productivity and collaboration |
| Microsoft 365    | Office applications            |
| Salesforce       | CRM                            |
| Dropbox          | File storage                   |
| Slack            | Team communication             |

For example, when you use Gmail, you don't need to:

- Install an email server.
- Configure an email database.
- Maintain physical servers.
- Update the email platform.
- Configure the provider's network infrastructure.

Google manages those underlying components.

## 4.3 SaaS Architecture

```
              END USER
                  |
                  v
              Web Browser
                  |
                  v
             SaaS Software
                  |
          +-------+-------+
          |       |       |
          v       v       v
       Backend  Database Storage
          |       |       |
          +-------+-------+
                  |
                  v
            CLOUD PROVIDER
```

The provider manages the complete software platform and underlying infrastructure.

## 4.4 What does the customer manage?

| Component               | Responsible party                                |
| ----------------------- | ------------------------------------------------ |
| Physical data center    | Provider                                         |
| Physical servers        | Provider                                         |
| Networking              | Provider                                         |
| Operating system        | Provider                                         |
| Middleware              | Provider                                         |
| Runtime                 | Provider                                         |
| Application             | Provider                                         |
| Application updates     | Provider                                         |
| User configuration      | Customer                                         |
| Access permissions      | Customer                                         |
| Customer data and usage | Customer, according to the service and agreement |

Although the SaaS provider manages the software, customers still need to manage their users, access permissions, data handling and security settings.

## 4.5 Real-world example — Gmail

Imagine a company wants to provide email accounts to 500 employees.

Traditional approach:

The company may need to:

- Install email server software.
- Configure mail protocols.
- Maintain storage.
- Configure spam filtering.
- Maintain security.
- Manage backups.
- Monitor infrastructure.

SaaS approach:

The company subscribes to Google Workspace.

Architecture:

```
          COMPANY EMPLOYEES
                  |
                  v
             Web Browser
                  |
                  v
           Google Workspace
                  |
          +-------+-------+
          |               |
          v               v
         Gmail          Drive
          |               |
          v               v
        Email          Documents
```

Google manages the underlying infrastructure and software.

The company manages employee accounts, permissions and its use of the service.

## 4.6 Advantages of SaaS

| Advantage            | Explanation                                     |
| -------------------- | ----------------------------------------------- |
| Ready to use         | No need to develop the software                 |
| Easy access          | Use through browser or application              |
| Less maintenance     | Provider manages software operations            |
| Automatic updates    | Provider manages application updates            |
| Subscription pricing | Often available through recurring subscriptions |
| Collaboration        | Users can work together online                  |

## 4.7 Disadvantages of SaaS

- Limited control over application infrastructure.
- Limited customization compared with building your own system.
- Dependence on the service provider.
- Internet access may be necessary.
- Data migration may be difficult.
- Subscription costs can grow as users increase.

## 4.8 When should you use SaaS?

Use SaaS when:

- You need ready-made software.
- You don't want to develop an application.
- You want to reduce maintenance.
- You need collaboration tools.
- You need software that is available through the Internet.

# 5. Compare IaaS vs PaaS vs SaaS

This is one of the most important sections of Day 3.

## 5.1 Main comparison

| Criteria               | IaaS                             | PaaS                                     | SaaS                  |
| ---------------------- | -------------------------------- | ---------------------------------------- | --------------------- |
| Full name              | Infrastructure as a Service      | Platform as a Service                    | Software as a Service |
| Provides               | Infrastructure                   | Application platform                     | Ready-to-use software |
| Server management      | Customer manages OS and software | Provider manages platform infrastructure | Provider manages      |
| OS management          | Customer                         | Provider                                 | Provider              |
| Runtime management     | Customer                         | Provider                                 | Provider              |
| Application management | Customer                         | Customer                                 | Provider              |
| Customization          | High                             | Medium                                   | Usually limited       |
| Infrastructure control | High                             | Medium                                   | Low                   |
| Ease of use            | Requires technical skills        | Easier                                   | Easiest               |
| Example                | EC2                              | Elastic Beanstalk                        | Gmail                 |

## 5.2 Responsibility comparison

The following table shows the traditional conceptual responsibility model.

| Component        | On-Premises | IaaS     | PaaS     | SaaS                    |
| ---------------- | ----------- | -------- | -------- | ----------------------- |
| Applications     | Customer    | Customer | Customer | Provider                |
| Data             | Customer    | Customer | Customer | Shared responsibilities |
| Runtime          | Customer    | Customer | Provider | Provider                |
| Middleware       | Customer    | Customer | Provider | Provider                |
| Operating System | Customer    | Customer | Provider | Provider                |
| Virtualization   | Customer    | Provider | Provider | Provider                |
| Servers          | Customer    | Provider | Provider | Provider                |
| Storage          | Customer    | Provider | Provider | Provider                |
| Networking       | Customer    | Provider | Provider | Provider                |
| Data Center      | Customer    | Provider | Provider | Provider                |

Note: This table is a learning model, not a substitute for the responsibility documentation of a particular cloud service. Customers retain security and governance responsibilities even when using SaaS.

## 5.3 The kitchen analogy

Imagine you want to eat a meal.

This analogy helps you remember the differences.

On-Premises — Cook everything yourself

You purchase ingredients, equipment, kitchen tools and prepare everything.

You manage almost everything.

IaaS — Rent a kitchen

You rent the kitchen and equipment, but you prepare and cook the food yourself.

You manage the OS, software and application.

PaaS — Use a prepared kitchen service

The kitchen, equipment and cooking environment are ready. You focus on preparing your specific meal.

You focus on application development.

SaaS — Eat at a restaurant

You order a finished meal and enjoy it.

You use ready-made software.

## 5.4 How much control do you have?

```
       MORE CONTROL
            |
            v
       On-Premises
            |
            v
           IaaS
            |
            v
           PaaS
            |
            v
           SaaS
            |
            v
       LESS CONTROL
```

As you move from IaaS to PaaS to SaaS:

- Infrastructure management decreases.
- Operational responsibility generally decreases.
- Provider management increases.
- Direct customization and control generally decrease.

Let's connect this knowledge directly to AWS.

| AWS Service           | Category         | Explanation                            |
| --------------------- | ---------------- | -------------------------------------- |
| Amazon EC2            | IaaS             | Rent virtual servers                   |
| Amazon EBS            | IaaS-related     | Block storage                          |
| Amazon VPC            | IaaS-related     | Virtual networking                     |
| AWS Elastic Beanstalk | PaaS-like        | Managed application deployment         |
| AWS App Runner        | PaaS-like        | Managed web application deployment     |
| AWS Lambda            | Serverless       | Run functions without managing servers |
| Amazon RDS            | Managed Database | Managed relational database            |
| Amazon S3             | Managed Storage  | Object storage service                 |

Important certification distinction:

AWS Lambda is generally described as Function as a Service (FaaS), a serverless computing model. It is not simply traditional PaaS.

Amazon RDS and Amazon S3 are managed cloud services, but they do not fit neatly into the traditional IaaS/PaaS/SaaS categories.

# 8. Shared Responsibility Model

This concept is closely related to IaaS, PaaS and SaaS.

## 8.1 What is the Shared Responsibility Model?

The Shared Responsibility Model describes how security responsibilities are divided between AWS and the customer.

AWS is responsible for security of the cloud.

Customers are responsible for security in the cloud.

## 8.2 Security of the Cloud

AWS is responsible for the security of its underlying infrastructure.

Examples:

- Physical data center security.
- Physical server hardware.
- Physical networking.
- Infrastructure facilities.
- Underlying virtualization infrastructure.

## 8.3 Security in the Cloud

Customers are responsible for securing their cloud resources.

Examples:

- IAM permissions.
- Application security.
- Data encryption configuration.
- Network access rules.
- Operating system updates where applicable.
- User credentials.
- Application vulnerabilities.

## 8.4 Shared Responsibility Architecture

```
                AWS CLOUD
                    |
          +---------+---------+
          |                   |
          v                   v
     AWS SECURITY       CUSTOMER SECURITY
          |                   |
          v                   v
     Physical Data       IAM Permissions
     Center Security     Application Security
          |                   |
          v                   v
     Hardware Security   Data Protection
          |                   |
          v                   v
     Network Hardware    Security Groups
```

## 8.5 Responsibility changes by service model

| Responsibility          | EC2      | RDS      | Lambda   | SaaS                                         |
| ----------------------- | -------- | -------- | -------- | -------------------------------------------- |
| Physical infrastructure | AWS      | AWS      | AWS      | Provider                                     |
| Operating system        | Customer | AWS      | AWS      | Provider                                     |
| Runtime                 | Customer | AWS      | AWS      | Provider                                     |
| Application code        | Customer | Customer | Customer | Provider                                     |
| Application data        | Customer | Customer | Customer | Shared responsibilities                      |
| Access permissions      | Customer | Customer | Customer | Customer configuration and provider controls |

For example:

When you use EC2, you manage the guest operating system.

When you use RDS, AWS manages the underlying database infrastructure and operating system, but you remain responsible for important database configuration, access control and data security.

When you use Lambda, AWS manages the execution infrastructure, while you manage your function code, permissions and data access.

## 10.2 Technical conversation — B1

Question 1: What is IaaS?

Answer:

IaaS stands for Infrastructure as a Service. It provides virtual infrastructure such as servers, storage, and networking. Customers can install their own operating systems and applications.

Question 2: What is PaaS?

Answer:

PaaS stands for Platform as a Service. It provides a managed platform for developing and deploying applications. Developers can focus on writing code instead of managing infrastructure.

Question 3: What is SaaS?

Answer:

SaaS stands for Software as a Service. It provides ready-to-use software through the Internet. Users can access applications without managing the underlying infrastructure.

Question 4: What is the difference between IaaS and PaaS?

Answer:

IaaS provides virtual infrastructure, while PaaS provides a managed application platform. With IaaS, customers manage the operating system. With PaaS, the provider manages much of the underlying platform.

Sample answer:

"Today, I want to explain the three main Cloud Service Models.

First, IaaS stands for Infrastructure as a Service. It provides virtual servers, storage and networking. For example, Amazon EC2 allows developers to create virtual machines and install their own software.

Second, PaaS stands for Platform as a Service. It provides a managed platform for application development and deployment. For example, AWS Elastic Beanstalk helps developers deploy applications without managing every infrastructure component.

Finally, SaaS stands for Software as a Service. It provides ready-to-use software through the Internet. Gmail and Microsoft 365 are examples of SaaS.

The main difference is the level of management and responsibility. IaaS gives customers more control, while SaaS requires less infrastructure management.

Companies choose different service models depending on their technical requirements, budget and business goals."
