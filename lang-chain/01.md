# Explain `fetch_text_from_url` in LangChain

This code creates a LangChain tool that downloads text content from a URL and returns it to an AI agent.

For example, an agent could use this tool to fetch a web page, read its content, and then summarize or analyze it.

One important detail: this code fetches the raw response body. It does not automatically extract readable text from HTML or convert a PDF into text.

## 1. Understand the workflow

1\. AI agent

Requests a document from a URL

2\. LangChain tool

`fetch_text_from_url(url)`

3\. HTTP request

Downloads the URL's response using Python

4\. Decode response

Converts response bytes into a Python string

5\. Return content to the agent

The model can analyze the returned content

## 2. Explain the code line by line

### Part 1 — Import Python libraries

```
import urllib.errorimport urllib.request
```

These are built-in Python modules, so you don't need to install them separately.

| Module           | Purpose                                         |
| ---------------- | ----------------------------------------------- |
| `urllib.request` | Creates and sends HTTP requests to URLs.        |
| `urllib.error`   | Provides exceptions for URL and network errors. |

For example, Python can use `urllib.request` to request:

```
https://example.com/article
```

The server responds with data, which your function can read.

### Part 2 — Import LangChain's `tool` decorator

```
from langchain.tools import tool
```

The `tool` decorator converts a Python function into a tool that LangChain agents can discover and call.

Without the decorator, this is just a normal Python function:

```
def fetch_text_from_url(url: str) -> str:    ...
```

With `@tool`, LangChain can expose information about the function, including its name, description, and input schema.

### Part 3 — Define the tool

```
@tooldef fetch_text_from_url(url: str) -> str:    """Fetch the document from a URL.    """
```

Let's break this down.

- `@tool`: Registers the function as a LangChain tool.
- `fetch_text_from_url`: The tool's name.
- `url: str`: The tool accepts a URL as a string.
- `-> str`: The function is expected to return a string.
- The docstring describes what the tool does and helps the model decide when to use it.

An agent might select this tool when the user asks, "Read this article and summarize it."

### Part 4 — Create the HTTP request

```
req = urllib.request.Request(    url,    headers={        "User-Agent": "Mozilla/5.0 (compatible; quickstart-research/1.0)"    },)
```

This creates a request object but does not download the document yet.

The `url` specifies the destination. The `headers` provide additional information to the server.

The `User-Agent` identifies the HTTP client. Some websites reject requests that have no User-Agent or apply different rules based on it.

However, this particular value does not make your program a real browser or guarantee that the server will accept the request.

### Part 5 — Send the request and read the response

```
try:    with urllib.request.urlopen(req, timeout=120) as resp:        raw = resp.read()
```

There are three important operations here.

| Code                        | Explanation                                                                  |
| --------------------------- | ---------------------------------------------------------------------------- |
| `urlopen(req, timeout=120)` | Opens the URL and waits for the response, with a 120-second timeout setting. |
| `with ... as resp`          | Manages the response resource and closes it automatically afterward.         |
| `resp.read()`               | Reads the response body as bytes and stores it in `raw`.                     |

For example, the server might return HTML like this:

```
<html>
  <body>
    <h1>LangChain Tutorial</h1>
    <p>Learn how to build AI agents.</p>
  </body>
</html>
```

The variable `raw` contains the downloaded bytes, not yet a Python string.

Note that the timeout is not necessarily a strict 120-second total limit for the entire download; it primarily governs socket operations.

### Part 6 — Handle URL errors

```
except urllib.error.URLError as e:    return f"Fetch failed: {e}"
```

If a URL-related error occurs, the function returns an error message instead of allowing that exception to propagate normally.

Possible causes include:

- DNS resolution failure.
- Connection problems.
- A server that cannot be reached.
- A timeout.

For example, the function might return:

```
Fetch failed: <url error details>
```

The exact message depends on the error.

This does not handle every possible failure. For example, HTTP error responses such as 404 or 500 can raise `urllib.error.HTTPError`, a subclass of `URLError`, so they are caught here. Other exceptions, such as certain decoding or unexpected programming errors, may still propagate.

### Part 7 — Convert bytes into text

```
text = raw.decode("utf-8", errors="replace")return text
```

The `read()` method returns bytes. The `decode()` method converts those bytes into a Python string.

- `"utf-8"`: The character encoding used to interpret the bytes.
- `errors="replace"`: Replaces invalid byte sequences instead of raising a decoding exception.
- `return text`: Returns the resulting string to the caller or agent.

For example:

```
raw = b"Hello LangChain"text = raw.decode("utf-8", errors="replace")print(text)
```

Output:

```
Hello LangChain
```

## 3. How to test the tool

You can call the tool directly without creating an agent:

```
result = fetch_text_from_url.invoke({    "url": "https://example.com"})print(result)
```

Because the function is decorated with `@tool`, calling `.invoke()` with a dictionary is a convenient way to supply its arguments.

For `https://example.com`, the returned content will typically be HTML containing an example-domain page. The exact response depends on the server.

## 4. Use it with a LangChain agent

You can register this tool with an agent, just as in your previous example.

```
from langchain.agents import create_agentagent = create_agent(    model="openai:gpt-5.5",    tools=[fetch_text_from_url],    system_prompt=(        "You are a research assistant. "        "Use the URL-fetching tool when the user asks "        "you to read a web page."    ),)result = agent.invoke({    "messages": [        {            "role": "user",            "content": (                "Fetch https://example.com "                "and explain what the page contains."            ),        }    ]})print(result["messages"][-1].text)
```

The agent can decide to call the tool, receive the fetched content, and generate an explanation.

## 5. Important limitation for RAG

If your goal is to build a Retrieval-Augmented Generation (RAG) system, fetching a URL is only the first step.

| Stage       | What happens                                           | Relevant component               |
| ----------- | ------------------------------------------------------ | -------------------------------- |
| 1. Fetch    | Download a document                                    | Your `fetch_text_from_url` tool  |
| 2. Extract  | Convert HTML, PDF, or other formats into readable text | HTML parser or document loader   |
| 3. Split    | Divide long documents into smaller chunks              | `RecursiveCharacterTextSplitter` |
| 4. Embed    | Convert chunks into vectors                            | An embedding model               |
| 5. Store    | Save vectors for similarity search                     | A vector database                |
| 6. Retrieve | Find relevant chunks for a question                    | Retriever                        |
| 7. Generate | Answer using the retrieved context                     | LLM                              |

One additional caution: because the tool accepts arbitrary URLs, production applications should validate URLs and restrict internal or private network destinations to prevent server-side request forgery (SSRF). They should also limit response size and consider content type, redirects, and encoding.

The main takeaway is that `fetch_text_from_url` is a document-fetching tool, not a complete web scraper or RAG pipeline.
