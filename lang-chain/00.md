# Explain the LangChain Agent Code

This code creates an AI agent that can use a Python function as a tool to answer questions about the weather.

The key idea is that the LLM (Large Language Model) decides when to call a tool, the tool executes Python code, and the agent uses the tool's result to respond to the user.

## 1. Understand the overall workflow

1\. User asks a question

"What's the weather in San Francisco?"

2\. LLM decides to call a tool

The model selects `get_weather` and supplies the city.

3\. Python tool executes

Returns: `It's always sunny in San Francisco!`

4\. Agent returns the final answer

The final response is stored in the agent's message history.

Important: this example does not retrieve real weather data. The Python function always returns a sunny forecast, regardless of the city.

## 2. Explain the code line by line

### Part 1 — Import `create_agent`

```
from langchain.agents import create_agent
```

This imports the function used to create a LangChain agent.

An agent is an application that combines a language model, tools, and instructions. It can decide whether to answer directly or call a tool to complete a task.

For example:

- Question: "What is 2 + 3?" — the model may answer directly.
- Question: "What's the weather in San Francisco?" — the model may call `get_weather`.
- Question: "What's the weather in Tokyo?" — the model may call the same tool with a different city.

The model makes the tool-selection decision based on the question and the tools available.

### Part 2 — Define a tool

```
def get_weather(city: str) -> str:    """Get weather for a given city."""    return f"It's always sunny in {city}!"
```

This defines a normal Python function that LangChain can expose to the model as a tool.

| Code                                  | Meaning                                                                                                        |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `def get_weather`                     | Defines a function named `get_weather`.                                                                        |
| `city: str`                           | The input parameter `city` should be a string.                                                                 |
| `-> str`                              | Indicates that the function is expected to return a string.                                                    |
| `"""Get weather for a given city."""` | Describes the tool's purpose. LangChain can use this description to help the model understand when to call it. |
| `f"...{city}..."`                     | Inserts the value of `city` into the returned string.                                                          |

For example, calling the function directly:

```
print(get_weather("San Francisco"))
```

Output:

```
It's always sunny in San Francisco!
```

No AI is needed to execute this function. It is ordinary Python code.

### Part 3 — Create the agent

```
agent = create_agent(    model="openai:gpt-5.5",    tools=[get_weather],    system_prompt="You are a helpful assistant",)
```

This is the most important part of the code.

| Parameter                                     | Explanation                                                                                                                               |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `model="openai:gpt-5.5"`                      | Specifies the language model provider and model name. This requires a compatible LangChain integration and an available model/API access. |
| `tools=[get_weather]`                         | Registers `get_weather` as a tool the agent can use.                                                                                      |
| `system_prompt="You are a helpful assistant"` | Gives the agent its general behavior instructions.                                                                                        |
| `agent = ...`                                 | Stores the configured agent so you can invoke it later.                                                                                   |

Notice that you pass the function itself:

```
tools=[get_weather]
```

You do not call the function when registering it:

```
# Correcttools=[get_weather]# Incorrect for tool registrationtools=[get_weather("San Francisco")]
```

The first version lets the agent choose the arguments when a user asks a question. The second version executes the function immediately and passes its return value instead of registering the function as a tool.

### Part 4 — Invoke the agent

```
result = agent.invoke(    {        "messages": [            {                "role": "user",                "content": "What's the weather in San Francisco?"            }        ]    })
```

The `invoke()` method runs the agent with the supplied input.

Let's break down the input structure:

```
{    "messages": [        {            "role": "user",            "content": "What's the weather in San Francisco?"        }    ]}
```

- `messages`: A list representing the conversation history.
- `role: "user"`: Identifies the message as coming from the user.
- `content`: Contains the user's actual question.

During execution, the agent typically follows this sequence:

1. Sends the conversation and available tool definitions to the model.
2. The model requests a tool call for `get_weather`, with `city="San Francisco"`.
3. LangChain executes the Python function.
4. The tool result is added to the conversation.
5. The model produces a final response, which is returned in `result`.

The agent can perform multiple tool calls if needed. It is not limited to exactly one call.

### Part 5 — Print the result

```
print(result["messages"][-1].content_blocks)
```

The returned `result` is a dictionary containing the agent's message history.

| Expression           | Explanation                                                              |
| -------------------- | ------------------------------------------------------------------------ |
| `result["messages"]` | Retrieves the list of messages generated or maintained during execution. |
| `[-1]`               | Selects the last message in the list.                                    |
| `.content_blocks`    | Retrieves the last message's content as structured content blocks.       |
| `print(...)`         | Displays that content in the console.                                    |

The last message is normally the assistant's final response after the tool has been used.

For example, the content might be displayed as a text block containing:

```
It's always sunny in San Francisco!
```

The exact representation of `content_blocks` can vary with the LangChain and model integration versions.

If you want to print just the final answer as a plain string, you can use:

```
print(result["messages"][-1].text)
```

For a simpler text-only display, this is often easier to read.

## 3. What happens internally? (Tool calling)

The model does not directly execute your Python function. Instead, it requests a tool call, and LangChain executes the function.

LLM — Decision making

Selects `get_weather` and generates its arguments.

```
{"city": "San Francisco"}
```

LangChain — Tool execution

Calls the Python function with the selected argument.

```
get_weather("San Francisco")
```

LLM — Final response

Uses the tool output to formulate the answer.

```
It's always sunny in San Francisco!
```

This is called tool calling or function calling. The model chooses the tool and proposes its arguments; LangChain handles execution and passes the result back to the model.

## 4. Complete example with clearer output

Here is your code with a few extra print statements to make the workflow easier to understand.

```
from langchain.agents import create_agentdef get_weather(city: str) -> str:    """Get weather for a given city."""    return f"It's always sunny in {city}!"agent = create_agent(    model="openai:gpt-5.5",    tools=[get_weather],    system_prompt="You are a helpful assistant",)result = agent.invoke({    "messages": [        {            "role": "user",            "content": "What's the weather in San Francisco?"        }    ]})# Print the complete conversationfor message in result["messages"]:    print(f"Role: {message.type}")    print(f"Content: {message.content}")    print("-" * 40)# Print the final answerprint("Final answer:")print(result["messages"][-1].text)
```

## 5. Key concepts to remember

| Concept         | Responsibility                                                      |
| --------------- | ------------------------------------------------------------------- |
| LLM             | Understands the request and decides which tool to use.              |
| Tool            | Executes a specific operation, such as retrieving weather data.     |
| Agent           | Coordinates the model, tools, and conversation.                     |
| `invoke()`      | Starts an agent execution.                                          |
| `result`        | Contains the returned conversation messages and other agent output. |
| `system_prompt` | Provides instructions for the agent's behavior.                     |

The most important distinction: a normal LLM generates text, while an agent can also use external functions to perform tasks and incorporate their results into its response.
