### Part 1 — Understanding Chat Models

### 3\. What is a Chat Model?

A Chat Model is an LLM interface designed to process conversational messages and generate responses.

Unlike a basic text completion interface, a chat model works with structured messages.

Example:

```text
System: You are a helpful Python teacher.

Human: What is Python?

AI: Python is a high-level programming language.
```

The chat model receives a list of messages and returns an AI message.

The important point is that a chat model does not automatically remember every previous conversation. Your application must provide conversation history or use a memory/persistence mechanism.

### 4\. Chat Model vs Completion Model

These are two different ways of interacting with language models.

### Completion Model

A completion-style interface accepts a text prompt.

```python
prompt = """
You are a Python teacher.

Question: What is Python?

Answer:
"""
```

The model continues generating text based on that prompt.

### Chat Model

A chat-style interface accepts structured messages.

```python
messages = [
    ("system", "You are a Python teacher."),
    ("human", "What is Python?")
]
```

The model generates an assistant response.

### Comparison

| Feature                 | Completion Model                  | Chat Model                                  |
| ----------------------- | --------------------------------- | ------------------------------------------- |
| Input                   | Text prompt                       | Structured messages                         |
| Conversation roles      | Usually encoded in text           | Explicit roles                              |
| System instructions     | Usually prompt-based              | System message                              |
| Conversation history    | Manually included                 | Message list                                |
| Tool calling            | Interface-dependent               | Commonly supported                          |
| Current LangChain usage | Legacy and specialized interfaces | Recommended for conversational applications |

Important: Modern chat models are also generative language models. The difference is primarily their interaction interface, not necessarily their underlying neural network architecture.

### Part 2 — Message Architecture

### 5\. Understanding message types

LangChain provides several message types.

The most important ones are:

| Message        | Purpose                         |
| -------------- | ------------------------------- |
| SystemMessage  | Instructions for model behavior |
| HumanMessage   | User input                      |
| AIMessage      | Model response                  |
| ToolMessage    | Tool execution result           |
| AIMessageChunk | Partial streaming response      |

### 5.1 SystemMessage

A SystemMessage defines the model's behavior.

Example:

```python
from langchain_core.messages import SystemMessage

message = SystemMessage(
    content="You are a professional Python teacher."
)
```

You can specify:

* Role

* Communication style

* Response language

* Output format

* Restrictions

* Domain expertise

Example:

```text
You are a senior software engineer.

Your responsibilities:
1. Explain programming concepts.
2. Provide Python examples.
3. Explain errors.
4. Suggest best practices.
5. Keep answers structured.
```

### 5.2 HumanMessage

A HumanMessage represents the user's input.

```python
from langchain_core.messages import HumanMessage

message = HumanMessage(
    content="Explain Python decorators."
)
```

### 5.3 AIMessage

An AIMessage represents the model's response.

```python
from langchain_core.messages import AIMessage

message = AIMessage(
    content="A decorator is a function that modifies another function."
)
```

### 5.4 ToolMessage

A ToolMessage contains the output returned by a tool.

Example:

```python
from langchain_core.messages import ToolMessage

message = ToolMessage(
    content="The result is 100.",
    tool_call_id="call_123"
)
```

ToolMessage is particularly important when studying AI agents and tool calling.

### Part 3 — Model Configuration

### 7\. Understanding model parameters

When initializing a model, you can configure its behavior.

Common parameters:

| Parameter   | Purpose                               |
| ----------- | ------------------------------------- |
| temperature | Controls randomness                   |
| max_tokens  | Limits generated output tokens        |
| timeout     | Maximum request waiting time          |
| max_retries | Number of retry attempts              |
| top_p       | Controls probability-based sampling   |
| streaming   | Enables incremental response delivery |

Note: Exact parameter support and naming can differ between model providers.

### 8\. Temperature

Temperature controls the randomness of token selection.

For example:

```python
model = init_chat_model(
    "openai:gpt-5.5",
    temperature=0
)
```

A simplified conceptual comparison:

Temperature = 0

More predictable

Useful for structured answers, factual tasks and repeatable outputs.

Example: "What is 10 + 20?" → "30"

Temperature = 0.7

More varied

Useful for conversational answers and creative generation.

Example: "Give me a creative story about a robot."

Temperature = 1.0

Higher variation

Can produce more diverse outputs, depending on the model.

Important: Temperature does not directly control intelligence or guarantee factual accuracy. Some reasoning models do not support user-configurable temperature.

### 9\. Maximum output tokens

The token limit controls how much output the model can generate.

For example:

```python
model = init_chat_model(
    "openai:gpt-5.5",
    max_tokens=300
)
```

A lower limit can reduce response length and sometimes API cost.

The exact meaning and accepted parameter may depend on the model and provider.

### 10\. Timeout and retry

Production applications should handle network failures.

Example:

```python
model = init_chat_model(
    "openai:gpt-5.5",
    timeout=30,
    max_retries=2
)
```

Explanation:

* `timeout=30`: Allow up to 30 seconds for a request.

* `max_retries=2`: Retry certain failed requests up to two times.

Retries do not fix invalid credentials, unavailable models or all types of errors.

### Part 4 — Model Invocation

### 11\. Understanding `invoke()`

In LangChain, `invoke()` is the standard method for sending an input to a model and receiving a complete response.

Example:

```python
response = model.invoke(
    "Explain object-oriented programming."
)

print(response.content)
```

The execution process:

* Python sends a request.

* LangChain prepares the messages.

* The provider receives the request.

* The model generates a response.

* LangChain returns an AIMessage.

### 11.1 Different invocation methods

LangChain supports several ways to interact with models.

| Method    | Purpose                                |
| --------- | -------------------------------------- |
| invoke()  | Execute one request                    |
| ainvoke() | Execute one asynchronous request       |
| stream()  | Receive incremental response chunks    |
| astream() | Receive asynchronous response chunks   |
| batch()   | Process multiple inputs                |
| abatch()  | Process multiple inputs asynchronously |

Example of batch processing:

```python
questions = [
    "What is Python?",
    "What is Java?",
    "What is JavaScript?"
]

responses = model.batch(questions)

for question, response in zip(questions, responses):
    print("Question:", question)
    print("Answer:", response.content)
    print("-" * 40)
```

This is useful when processing multiple independent requests.

### 12\. Understanding response metadata

A model response contains more than just text.

Example:

```python
response = model.invoke(
    "Explain LangChain."
)

print(response.content)

print(response.id)

print(response.usage_metadata)

print(response.response_metadata)
```

Important response fields:

| Field             | Description                                     |
| ----------------- | ----------------------------------------------- |
| content           | Generated text                                  |
| id                | Response identifier, when provided              |
| usage_metadata    | Token usage information, when provided          |
| response_metadata | Provider-specific response details              |
| tool_calls        | Tool calls requested by the model, when present |

Example of token usage:

```python
{
    "input_tokens": 20,
    "output_tokens": 100,
    "total_tokens": 120
}
```

The actual fields and values depend on the provider.

### Part 5 — Streaming Responses

### 13\. What is streaming?

Normally, when you call `invoke()`, you wait until the entire response is generated.

Streaming allows you to receive the response incrementally.

Compare:

Normal invocation

Wait for completion

The user sees the answer after the model finishes generating it.

Streaming invocation

Receive chunks immediately

The user sees the answer progressively while the model generates it.

Example:

```text
User:
Explain LangGraph.

AI:
LangGraph
LangGraph is
LangGraph is a framework
LangGraph is a framework for
LangGraph is a framework for building
...
```

### 14\. Implement streaming with LangChain

Create `streaming_demo.py`:

```python
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model

load_dotenv()

model = init_chat_model(
    "openai:gpt-5.5",
    temperature=0
)

print("AI: ", end="", flush=True)

for chunk in model.stream(
    "Explain LangChain in 100 words."
):
    if isinstance(chunk.content, str):
        print(chunk.content, end="", flush=True)

print()
```

Explanation:

* `model.stream()` starts streaming.

* Each `chunk` contains part of the response.

* `chunk.content` extracts the text.

* `flush=True` displays output immediately.

Note: Some providers return multimodal content blocks rather than plain strings. This simple example handles text-only output.

### 14.1 When should you use streaming?

| Use case                   | Streaming                 |
| -------------------------- | ------------------------- |
| Chatbot                    | Recommended               |
| AI writing assistant       | Recommended               |
| Long text generation       | Recommended               |
| Background processing      | Optional                  |
| Structured JSON extraction | Often simpler with invoke |

### Part 6 — Asynchronous Model Invocation

### 15\. What is asynchronous programming?

Python supports synchronous and asynchronous execution.

Synchronous execution:

The program waits for one operation to finish before continuing.

```python
response = model.invoke("What is Python?")
print(response.content)
```

Asynchronous execution:

The program can perform other work while waiting for an operation to complete.

```python
response = await model.ainvoke("What is Python?")
```

This is especially useful for backend applications that handle multiple requests.

### 15.1 Synchronous vs asynchronous

Synchronous

Task 1

0–3 seconds

Task 2

3–6 seconds

Tasks execute sequentially in this simplified example.

Asynchronous

Task 1

0–3 seconds

Task 2

0–3 seconds

Independent requests can overlap while waiting for network responses.

The actual execution time depends on provider latency, rate limits and concurrency.

### 16\. Implement asynchronous invocation

Create `async_demo.py`:

```python
import asyncio

from dotenv import load_dotenv
from langchain.chat_models import init_chat_model

load_dotenv()

model = init_chat_model(
    "openai:gpt-5.5",
    temperature=0
)

async def ask_ai(question: str):
    response = await model.ainvoke(question)

    return response.content

async def main():

    questions = [
        "What is Python?",
        "What is LangChain?",
        "What is LangGraph?"
    ]

    tasks = [
        ask_ai(question)
        for question in questions
    ]

    responses = await asyncio.gather(*tasks)

    for question, answer in zip(questions, responses):

        print("\nQuestion:", question)
        print("Answer:", answer)

if __name__ == "__main__":
    asyncio.run(main())
```

Important concepts:

* `async def`: Defines an asynchronous function.

* `await`: Waits for an asynchronous operation.

* `asyncio.gather()`: Runs multiple awaitable tasks concurrently.

* `asyncio.run()`: Starts the asynchronous event loop.

For production applications, add concurrency limits and handle provider rate limits.

### 19\. Build a chatbot with conversation history

Now let's build a practical application.

Create `chatbot.py`:

```python

import os

from dotenv import load_dotenv
from langchain.chat_models import init_chat_model

from langchain_core.messages import (
    SystemMessage,
    HumanMessage,
    AIMessage
)

load_dotenv()

# Select provider and model
provider = os.getenv("PROVIDER", "openai")

if provider == "openai":
    model = init_chat_model(
        "openai:gpt-5.5",
        temperature=0
    )

elif provider == "huggingface":
    from langchain_openai import ChatOpenAI

    model = ChatOpenAI(
        model="openai/gpt-oss-120b:fastest",
        base_url="https://router.huggingface.co/v1",
        api_key=os.getenv("HF_TOKEN"),
        temperature=0
    )

else:
    raise ValueError("Unsupported provider")

# Initialize conversation history
messages = [
    SystemMessage(
        content="""
        You are a helpful AI assistant.

        Your responsibilities:
        1. Answer questions clearly.
        2. Remember information in the conversation.
        3. Explain technical concepts.
        4. Provide Python examples when appropriate.
        """
    )
]

def chat(user_input: str):

    # Add user message
    messages.append(
        HumanMessage(content=user_input)
    )

    # Send conversation history to LLM
    response = model.invoke(messages)

    # Save AI response
    messages.append(
        AIMessage(content=response.content)
    )

    return response.content

def main():

    print("AI Chatbot Started")
    print("Type 'exit' to quit.")
    print("Type 'history' to view messages.")

    while True:

        user_input = input("\nYou: ").strip()

        if user_input.lower() == "exit":
            print("Goodbye!")
            break

        if user_input.lower() == "history":

            for message in messages:
                print(
                    type(message).__name__,
                    ":",
                    message.content
                )

            continue

        if not user_input:
            continue

        try:

            response = chat(user_input)

            print("\nAI:", response)

        except Exception as error:

            print("Error:", error)

if __name__ == "__main__":
    main()
```

### Step 3 — Chatbot Service

`app/chatbot.py`

```python
from langchain_core.messages import (
    SystemMessage,
    HumanMessage,
    AIMessage
)

class ChatBot:

    def __init__(self, model):

        self.model = model

        self.messages = [
            SystemMessage(
                content="You are a helpful AI assistant."
            )
        ]

    def chat(self, user_input):

        self.messages.append(
            HumanMessage(content=user_input)
        )

        response = self.model.invoke(
            self.messages
        )

        self.messages.append(
            response
        )

        return response.content

    def stream(self, user_input):

        self.messages.append(
            HumanMessage(content=user_input)
        )

        full_response = ""

        for chunk in self.model.stream(
            self.messages
        ):

            if isinstance(chunk.content, str):

                full_response += chunk.content

                yield chunk.content

        self.messages.append(
            AIMessage(content=full_response)
        )

    def clear_history(self):

        system_message = self.messages[0]

        self.messages = [system_message]
```

### Step 4 — Application Entry Point

`main.py`

```python
import os

from dotenv import load_dotenv

from app.model import create_model
from app.chatbot import ChatBot

def main():

    load_dotenv()

    model = create_model()

    chatbot = ChatBot(model)

    print("Multi-Provider AI Chatbot")
    print("Commands: exit, clear")

    while True:

        user_input = input("\nYou: ").strip()

        if user_input.lower() == "exit":
            break

        if user_input.lower() == "clear":

            chatbot.clear_history()

            print("Conversation cleared.")

            continue

        if not user_input:
            continue

        try:

            print("\nAI: ", end="", flush=True)

            for chunk in chatbot.stream(user_input):

                print(chunk, end="", flush=True)

            print()

        except Exception as error:

            print("\nError:", error)

if __name__ == "__main__":
    main()
```

