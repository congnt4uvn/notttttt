### Part 1 — Understanding Output Parsers

### 3\. What is an Output Parser?

An Output Parser is a component that transforms a model's output into a format that your application can use.

For example, an LLM might return:

```text
The customer is Alex.

He is 28 years old.

His occupation is Software Developer.
```

This is readable by humans, but it is inconvenient for a Python application that needs to access customer fields.

You would prefer:

```json
{
    "name": "Alex",
    "age": 28,
    "occupation": "Software Developer"
}
```

Now Python can access individual fields.

```python
customer["name"]
customer["age"]
customer["occupation"]
```

### 3.1 Output Parser architecture

User Input

Natural language

Prompt Template

Instructions and output requirements

LLM

Generate response

Output Parser

Transform and validate output

Structured Python Data

String, dictionary or Pydantic object

### 4\. Why do we need Output Parsers?

Consider this LLM response:

```text
The product costs $100.
```

A human can understand the price.

But your application might need to:

* Store the price in a database.

* Calculate tax.

* Compare prices.

* Generate invoices.

* Return data through an API.

Structured data makes these operations easier.

| Raw LLM response              | Structured response       |
| ----------------------------- | ------------------------- |
| Natural language              | JSON / Python object      |
| Difficult to process reliably | Easier to process         |
| Format may vary               | Defined schema            |
| Requires extraction logic     | Direct field access       |
| Validation is harder          | Validation can be applied |

Important: An Output Parser does not make an LLM infallible. Parsing and schema validation help detect invalid responses, but semantic correctness still needs checking.

### 5\. Types of Output Parsers

Some important LangChain parsers:

| Parser                         | Purpose                             |
| ------------------------------ | ----------------------------------- |
| StrOutputParser                | Extract text from model responses   |
| JsonOutputParser               | Parse JSON output                   |
| PydanticOutputParser           | Parse and validate Pydantic objects |
| CommaSeparatedListOutputParser | Parse comma-separated lists         |
| XMLOutputParser                | Parse XML output                    |

We will study the most important ones today.

### Part 2 — StrOutputParser

### 6\. Understanding StrOutputParser

You encountered this parser on Day 3.

It converts an AI message into plain text.

Example without parser:

```python
response = model.invoke(
    "Explain LangChain."
)

print(type(response))
print(response.content)
```

The result is an `AIMessage` object.

Example with parser:

```python
from langchain_core.output_parsers import StrOutputParser

```

Expected output:

```text
<class 'str'>

LangChain is a framework for building
```


When to use it: When you want ordinary text rather than a full AIMessage object.

### Part 3 — JSON and JSON Parsing

### 7\. What is JSON?

JSON stands for JavaScript Object Notation.

It is a lightweight data-interchange format commonly used by APIs and applications.

Example:

```json
{
    "name": "Alex",
    "age": 28,
    "is_developer": true,
    "skills": [
        "Python",
        "Java",
        "LangChain"
    ]
}
```

### 7.1 JSON data types

| JSON type | Example            |
| --------- | ------------------ |
| String    | "Alex"             |
| Number    | 28                 |
| Boolean   | true               |
| Array     | ["Python", "Java"] |
| Object    | {"name": "Alex"}   |
| Null      | null               |

JSON is important because most AI applications need to exchange data with:

* REST APIs

* Databases

* Frontend applications

* Other backend services

* External tools

### 8\. Parsing JSON in Python

Python has a built-in `json` module.

Example:

```python
import json

json_text = """
{
    "name": "Alex",
    "age": 28,
    "occupation": "Software Developer"
}
"""

data = json.loads(json_text)

print(data["name"])
print(data["age"])
print(data["occupation"])
```

Output:

```text
Alex
28
Software Developer
```

### 8.1 JSON serialization

You can also convert Python dictionaries into JSON.

```python
import json

customer = {
    "name": "Alex",
    "age": 28,
    "occupation": "Software Developer"
}

json_text = json.dumps(
    customer,
    indent=4
)

print(json_text)
```

Remember:

* `json.loads()` converts JSON text into Python data.

* `json.dumps()` converts Python data into JSON text.

### Part 4 — Pydantic and Data Validation

### 10\. What is Pydantic?

Pydantic is a Python library used to validate data and define structured data models.

It is especially useful when developing AI applications because LLM responses can contain:

* Missing fields

* Incorrect data types

* Unexpected values

* Invalid formats

* Inconsistent structures

Instead of manually checking every field, you can define a Pydantic model.

### 10.1 Install Pydantic

```bash
pip install -U pydantic
```

### 10.2 Create your first Pydantic model

```python
from pydantic import BaseModel

class Customer(BaseModel):

    name: str

    age: int

    occupation: str

customer = Customer(
    name="Alex",
    age=28,
    occupation="Software Developer"
)

print(customer)
print(customer.name)
print(customer.age)
```

Output:

```text
name='Alex' age=28 occupation='Software Developer'

Alex
28
```

Let's understand the code.

`BaseModel` is the parent class provided by Pydantic.

```python
class Customer(BaseModel):
```

This declares a structured data model.

```python
name: str
age: int
occupation: str
```

These are field definitions with their expected types.

Pydantic validates the data when you create the object.

### 11\. Pydantic data validation

Consider this:

```python
from pydantic import BaseModel, ValidationError

class Customer(BaseModel):

    name: str

    age: int

    occupation: str

try:

    customer = Customer(
        name="Alex",
        age="twenty-eight",
        occupation="Developer"
    )

except ValidationError as error:

    print(error)
```

Expected behavior:

```text
ValidationError:
age
Input should be a valid integer
```

Pydantic catches the invalid data rather than allowing an incorrect Customer object to be created.

### 11.1 Optional fields

Sometimes information is not available.

You can define optional fields:

```python
from pydantic import BaseModel

class Customer(BaseModel):

    name: str

    age: int | None = None

    occupation: str | None = None
```

Now:

```python
customer = Customer(
    name="Alex"
)

print(customer.model_dump())
```

Output:

```python
{
    "name": "Alex",
    "age": None,
    "occupation": None
}
```

### 11.2 Field descriptions and constraints

You can provide additional validation rules using `Field`.

```python
from pydantic import BaseModel, Field

class Customer(BaseModel):

    name: str = Field(
        description="Customer full name",
        min_length=2
    )

    age: int = Field(
        ge=0,
        le=120,
        description="Customer age"
    )

    email: str = Field(
        description="Customer email address"
    )
```

Important validation options:

| Option      | Meaning               |
| ----------- | --------------------- |
| ge          | Greater than or equal |
| gt          | Greater than          |
| le          | Less than or equal    |
| lt          | Less than             |
| min_length  | Minimum string length |
| max_length  | Maximum string length |
| description | Field documentation   |

You can also use `EmailStr` from Pydantic's email validation support if you install its email extra.

### 12\. Exporting Pydantic data

Convert a Pydantic object into a dictionary:

```python
customer = Customer(
    name="Alex",
    age=28,
    email="alex@example.com"
)

data = customer.model_dump()

print(data)
```

Convert it into JSON:

```python
json_text = customer.model_dump_json(
    indent=4
)

print(json_text)
```

Generate a JSON Schema:

```python
schema = Customer.model_json_schema()

print(schema)
```

This schema can describe your expected data structure to an LLM or an external service.

### Part 5 — PydanticOutputParser

### 13\. What is PydanticOutputParser?

`PydanticOutputParser` connects LangChain with Pydantic models.

It helps convert the LLM response into a validated Pydantic object.

Architecture:

User Text

My name is Alex. I am 28.

Chat Model

Extract information

PydanticOutputParser

Parse and validate

Customer Object

Validated Python object

### 14\. Implement PydanticOutputParser

Create `pydantic_parser.py`:

```python
from pydantic import BaseModel, Field

from langchain_core.output_parsers import (
    PydanticOutputParser
)

from langchain_core.prompts import PromptTemplate

# 1. Define the data model
class Customer(BaseModel):

    name: str = Field(
        description="Customer full name"
    )

    age: int = Field(
        description="Customer age"
    )

    occupation: str = Field(
        description="Customer occupation"
    )

# 2. Create parser
parser = PydanticOutputParser(
    pydantic_object=Customer
)

# 3. Create prompt
prompt = PromptTemplate(
    template="""
    Extract customer information
    from the following text.

    Text:
    {text}

    {format_instructions}
    """,

    input_variables=["text"],

    partial_variables={
        "format_instructions":
            parser.get_format_instructions()
    }
)

# 4. Create chain
chain = prompt | model | parser

# 5. Execute
result = chain.invoke({

    "text": """
    My name is Alex.
    I am 28 years old.
    I work as a software developer.
    """

})

# 6. Display result
print(result)

print("Name:", result.name)
print("Age:", result.age)
print("Occupation:", result.occupation)
```

Expected output:

```text
name='Alex' age=28 occupation='software developer'

Name: Alex
Age: 28
Occupation: software developer
```

### 14.1 Understanding `get_format_instructions()`

This is an important method.

```python
parser.get_format_instructions()
```

It generates instructions describing the required output format based on your Pydantic model.

For example, the generated instructions communicate that the output must contain:

```json
{
    "name": "string",
    "age": 0,
    "occupation": "string"
}
```

The actual instructions also include schema details and formatting requirements.

### 14.2 Why use PydanticOutputParser?

Without Pydantic:

```python
result = {
    "name": "Alex",
    "age": "28"
}

print(result["age"] + 1)
```

This produces a type error because `"28"` is a string.

With Pydantic, the application validates and, where permitted by its configuration, coerces input into the expected types.

```python
customer = Customer(
    name="Alex",
    age=28,
    occupation="Developer"
)

print(customer.age + 1)
```

Output:

```text
29
```

Important: Pydantic validation does not prove that the extracted information is factually true. It verifies that the data conforms to your schema.

### Part 6 — Native Structured Output

### 15\. What is `with_structured_output()`?

LangChain supports a simpler approach for obtaining structured data directly from a chat model.

Instead of manually asking the model to format JSON and parsing the response, you can provide a schema to the model integration.

Example:

```python
structured_model = model.with_structured_output(Customer)

result = structured_model.invoke(
    """
    My name is Alex.
    I am 28 years old.
    I work as a software developer.
    """
)

print(result)
print(result.name)
```

The result is a Pydantic object when using the Pydantic schema.

### 15.2 Complete example with OpenAI

```python
from pydantic import BaseModel, Field
from langchain.chat_models import init_chat_model

class Product(BaseModel):

    name: str = Field(
        description="Product name"
    )

    price: float = Field(
        gt=0,
        description="Product price"
    )

    category: str = Field(
        description="Product category"
    )

    in_stock: bool = Field(
        description="Whether the product is available"
    )

model = init_chat_model(
    "openai:YOUR_AVAILABLE_MODEL",
    temperature=0
)

structured_model = model.with_structured_output(
    Product
)

result = structured_model.invoke(
    """
    The iPhone costs 999 dollars.
    It belongs to the smartphone category.
    It is currently available.
    """
)

print(result)

print("Product:", result.name)
print("Price:", result.price)
print("Category:", result.category)
print("Available:", result.in_stock)
```

Expected output (illustrative):

```text
name='iPhone'
price=999.0
category='smartphone'
in_stock=True
```

Provider support varies. The model integration must support the requested structured-output method or tool/function calling mechanism.

### 15.3 Structured output with Hugging Face

For Hugging Face, support depends on the selected inference provider, model and endpoint.

One practical alternative is to use the `JsonOutputParser` chain from Part 3:

```python
import os

from langchain_openai import ChatOpenAI

from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import JsonOutputParser

from pydantic import BaseModel, Field

class Product(BaseModel):

    name: str

    price: float = Field(gt=0)

    category: str

    in_stock: bool

hf_model = ChatOpenAI(
    model=os.environ["HF_MODEL"],
    base_url="https://router.huggingface.co/v1",
    api_key=os.environ["HF_TOKEN"],
    temperature=0
)

parser = JsonOutputParser(
    pydantic_object=Product
)

prompt = ChatPromptTemplate.from_messages([
    (
        "system",
        """
        Extract product information.

        Return JSON matching this format:

        {format_instructions}
        """
    ),
    ("human", "{text}")
])

chain = (
    prompt
    | hf_model
    | parser
)

result = chain.invoke({
    "format_instructions": parser.get_format_instructions(),
    "text": """
    The iPhone costs 999 dollars.
    It is a smartphone and is available.
    """
})

product = Product.model_validate(result)

print(product)
```

Here, Pydantic performs the final validation explicitly.

The key distinction:

| Method                   | How it works                                          |
| ------------------------ | ----------------------------------------------------- |
| PydanticOutputParser     | Parses formatted model text and validates it          |
| JsonOutputParser         | Parses JSON into Python data                          |
| with_structured_output() | Uses model integration's structured-output capability |

My recommendation: use native structured output when your chosen provider supports it reliably. Use explicit JSON parsing and validation when you need a more portable approach.

### Part 7 — Handling Invalid LLM Responses

### 16\. Why can parsing fail?

LLMs do not always return the expected format.

Suppose your application expects:

```json
{
    "name": "Alex",
    "age": 28
}
```

But the model returns:

```text
Here is the extracted information:

{
    "name": "Alex",
    "age": "twenty-eight"
}
```

There are two potential problems:

* The response contains extra text.

* The age has an incorrect data type.

Your application needs to handle these situations.

### 17\. JSON parsing errors

Example:

```python
import json

invalid_json = """
{
    "name": "Alex",
    "age": 28,
}
"""

try:

    result = json.loads(invalid_json)

except json.JSONDecodeError as error:

    print("Invalid JSON:", error)
```

The trailing comma makes this invalid JSON.

### 18\. Pydantic validation errors

Example:

```python
from pydantic import BaseModel, Field, ValidationError

class Employee(BaseModel):

    name: str

    age: int = Field(
        ge=18,
        le=100
    )

try:

    employee = Employee(
        name="Alex",
        age=15
    )

except ValidationError as error:

    print(error)
```

The age is below the required minimum.

Pydantic raises a `ValidationError`.

### 19\. Retry and correction strategies

You can use LangChain's `RetryOutputParser` to attempt to repair an incorrectly formatted response.

Conceptually, it works like this:

```text
Original LLM response
        |
        v
   Output Parser
        |
        v
    Parse error
        |
        v
  Retry / Correction
        |
        v
   Parse again
        |
        v
  Structured result
```

Example:

```python
from langchain.output_parsers import RetryOutputParser
from langchain_core.output_parsers import PydanticOutputParser

from pydantic import BaseModel

class Employee(BaseModel):

    name: str
    age: int

parser = PydanticOutputParser(
    pydantic_object=Employee
)

retry_parser = RetryOutputParser.from_llm(
    parser=parser,
    llm=model
)
```

The retry parser needs the original prompt and completion when parsing:

```python
from langchain_core.outputs import Generation

original_prompt = """
Extract employee information.

Required JSON:
{"name": "string", "age": 0}

Text:
Alex is 28 years old.
"""

bad_output = """
The employee is Alex.
"""

try:

    result = retry_parser.parse_with_prompt(
        bad_output,
        original_prompt
    )

    print(result)

except Exception as error:

    print("Could not parse:", error)
```

For newer applications, you can also implement explicit validation and correction loops using model retries or LangGraph.

The key principle is:

Never assume that an LLM response is valid simply because it looks like JSON.

### 25\. Create the model factory

Create `app/model_factory.py`:

```python
import os

from langchain.chat_models import init_chat_model
from langchain_openai import ChatOpenAI

def create_model():

    provider = os.getenv("PROVIDER", "openai")

    if provider == "openai":

        return init_chat_model(
```

### 26\. Create the extraction service

Create `app/extractor.py`:

```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import JsonOutputParser

from app.schemas import ExtractionResult

class InformationExtractor:

    def __init__(self, model):

        self.model = model

        self.parser = JsonOutputParser(
            pydantic_object=ExtractionResult
        )

        self.prompt = ChatPromptTemplate.from_messages([

            (
                "system",
                """
                You are an information extraction system.

                Extract customer and product information
                from the supplied text.

                Rules:

                1. Follow the provided JSON format.
                2. Do not invent missing information.
                3. Use null for unavailable optional fields.
                4. Preserve the original meaning.

                {format_instructions}
                """
            ),

            (
                "human",
                """
                Extract information from this text:

                {text}
                """
            )

        ])

        self.chain = (
            self.prompt
            | self.model
            | self.parser
        )

    def extract(self, text):

        raw_result = self.chain.invoke({

            "text": text,

            "format_instructions":
                self.parser.get_format_instructions()

        })

        # Explicit Pydantic validation
        validated_result = ExtractionResult.model_validate(
            raw_result
        )

        return validated_result
```

```python
    """

    try:

        result = extractor.extract(text)

        print("\nExtracted Information:\n")

        print(
            json.dumps(
                result.model_dump(),
                indent=4,
                ensure_ascii=False
            )
        )

        print("\nCustomer:", result.customer.name)

        print("Product:", result.product.name)

        print("Price:", result.product.price)

    except Exception as error:

        print("Extraction failed:", error)

if __name__ == "__main__":
    main()
```

```json
    },
```

Production note: For financial, legal or other high-impact data, add source verification, confidence handling, missing-field policies and human review. A valid schema is not proof that the extracted values are correct.

### Exercise 4: Advanced coding challenge

Build an AI job information extractor.

Input:

```text
John is a senior Java developer.

He has 8 years of experience.

He works with Spring Boot, Kafka and AWS.

His expected salary is 3000 USD per month.
```

Expected JSON:

```json
{
    "name": "John",
    "position": "Senior Java Developer",
    "experience_years": 8,
    "skills": [
        "Java",
        "Spring Boot",
        "Kafka",
        "AWS"
    ],
    "expected_salary": 3000,
    "currency": "USD"
}
```

Solution:

```python
from pydantic import BaseModel, Field

from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import JsonOutputParser

class JobCandidate(BaseModel):

    name: str

    position: str

    experience_years: int = Field(ge=0)

    skills: list[str]

    expected_salary: float = Field(gt=0)

    currency: str

parser = JsonOutputParser(
    pydantic_object=JobCandidate
)

prompt = ChatPromptTemplate.from_messages([

    (
        "system",
        """
        Extract job candidate information.

        Do not invent missing information.

        Return data matching this schema:

        {format_instructions}
        """
    ),

    (
        "human",
        "{text}"
    )

])

chain = prompt | model | parser

result = chain.invoke({

    "text": """
    John is a senior Java developer.

    He has 8 years of experience.

    He works with Spring Boot, Kafka and AWS.

    His expected salary is 3000 USD per month.
    """,

    "format_instructions":
        parser.get_format_instructions()

})

candidate = JobCandidate.model_validate(result)

print(candidate.model_dump_json(indent=4))
```
